# GRIMODEX // TERMINAL REVISION v2.0.9

## OPERATOR NOTICE

This is the revision record for v2.0.9 of the GRIMODEX LLM-integrated narrative authoring terminal.

This revision protects document saves, Inline AI, and Beat operations when multiple panes or external updates overlap. It also improves AI connectivity, Chronicle, Glass, the Web Editor, and Vivliostyle export. The Japanese and English desktop builds add an experimental feature that reranks related-scene candidates locally.

## ⚠️ Please read before installing

### Platform release classification

- **Windows and Linux**: Continue the Stable release classification used for v2.0.8.
- **macOS**: Continues the v2.0.8 Open Beta classification for Apple Silicon. Unconfirmed defects may remain in macOS-specific behavior or its distribution path. Before using this build with an important manuscript, create a backup and verify its behavior with copied data or test writing.

### Updating from v2.0.8 and migrating from v0.10.4

- After this Release is published, supported v2.0.8 packages can use the in-app updater. If no update is offered, obtain the package for your environment manually from the v2.0.9 Assets.
- Arch Linux does not use the in-app updater. After the AUR `grimodex-bin` package reaches v2.0.9, update through pacman or an AUR helper.
- v0.10.4 does not provide automatic updates. After this Release is published, obtain the package for your environment manually from the v2.0.9 Assets. This Release workflow verifies the Windows installer with a migration E2E using the actual public v0.10.4 installer. If the previous registration cannot be validated, the process terminates without changing the previous installation or user data.
- Workspaces and settings continue to use the existing local data location. On first launch, Grimodex attempts to migrate API keys from the OS credential store into Electron's encrypted storage. If secure OS storage is unavailable or migration fails, Grimodex displays a warning; re-enter the API keys in Settings. Previous credentials are not deleted.
- Make your own backup of important manuscripts before updating.

### Code signing and security notices

- **Windows**: The v2.0.9 installer is not Authenticode-signed. Windows may display a security warning. Download the installer only from the official release page and verify its source.
- **macOS**: The package is for Apple Silicon. This Release workflow verifies the Developer ID signature and Apple notarization before providing the v2.0.9 app and DMG.
- **Linux**: v2.0.9 provides AppImage, deb, rpm, and Arch packages for x86_64.

### Data storage and AI use

- Manuscripts and project data are stored in a local SQLite database. A Grimodex account is not required.
- AI chat can use API keys for OpenRouter, OpenAI, or Anthropic; a local Ollama model; or an agentic CLI such as Claude Code, Codex CLI, or OpenCode. Install and complete any required setup, authentication, and startup for Ollama or those CLIs separately. The editor remains usable without AI configuration.
- If an embedding model is not already present in the desktop app, opening a project can start automatic indexing and use a network connection to download a language-specific model of approximately 34–37 MB. Full-text search remains available while the model is downloading or unavailable.
- Experimental Semantic reranking itself runs with local models bundled in the desktop app. Excerpts from the selected related scenes may still be included in the context sent to the configured AI provider, as with normal AI chat.

## NEW CAPABILITIES

- Added experimental Semantic reranking to the desktop app for Japanese and English projects. It runs only when explicitly enabled in Project Settings and requires automatic related-scene injection. It is unavailable in the Web Editor and for other project languages. If processing is slow, the inference lane is busy, or reranking fails, Grimodex preserves the original search order.

## IMPROVEMENTS

- Unified how content and save generations are managed across document saves, external updates, workspace switches, and multiple panes. Save failures and conflicts now propagate through switching, and peer panes no longer replace unsaved local edits.
- Restored AI provider and model discovery, including Ollama and OpenAI-compatible local endpoints. For Ollama, Grimodex now distinguishes the model's maximum context from the active runner's effective context and includes Agent tools and output reserves in the usage display and final preflight.
- Hardened Chronicle bulk date and lane operations, Undo and Redo, the target Project during Workspace switches, and time display. The side dock now safely restores its previous slots and visibility after a region is hidden and shown again.
- Moved post-AutoSave lint, revision, derived-data, and semantic-index work onto background paths to stabilize editing responsiveness and long-document performance measurements.
- Vivliostyle export now opens the save dialog automatically after generation and keeps the work title horizontal in the running header for bunko and shinsho formats.
- Refined dimensions and icons across Web Editor stripes, docks, chat, and the selection toolbar, and made the trial notice dismissible. Settings navigation and update progress now stay within the available space.
- Glass and live backgrounds now preserve blur while menus open or panels change, with improved refraction and antialiasing around rounded edges.

## RESOLVED ANOMALIES

- Fixed Inline AI preview and cancellation, A/B candidate adoption, and Beat drag-and-drop being able to apply after the editor session, document, displayed view, or Beat array had changed since the operation began.
- Fixed peer-saved content and its save generation becoming separated, which could cause unnecessary conflicts or retain stale state on a later save. Legacy Beat preview backfill now participates in the same save-generation stream.
- Fixed AutoSave failures, external imports, and retired editor sessions being able to publish stale document revisions or associated Beat data as current.
- Fixed the Scene tree becoming empty after layout-preset or split-layout changes, and stopped Codex display filters from leaking into body highlighting or candidate searches.
