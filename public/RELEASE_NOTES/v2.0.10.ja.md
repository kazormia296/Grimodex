# 端末更新通達 // GRIMODEX REVISION v2.0.10

## 運用者《オペレーター》各位

大規模言語モデル統合型物語編纂端末《GRIMODEX》、Revision v2.0.10の更新記録です。

本改訂では、Settings から Mozkey IbG の公式配布物を取得する導線と、Codex の主読みを詳細画面から直接編集する機能を追加しました。日本語 IME での読み登録を安定させ、Arch Linux で Grimodex の辞書が Mozkey IbG に認識されない問題も修正しています。

## 配備要領

本 Release の公開後、下記 Assets から対象環境に対応する手動導入用インストーラーまたはパッケージを選定し、取得してください。

| 対象環境            | 公開区分         | 手動導入用の配布形式        |
| ------------------- | ---------------- | --------------------------- |
| Windows x64         | 正式版（Stable） | `.exe`                      |
| macOS Apple Silicon | オープンベータ   | `.dmg`                      |
| Linux x86_64        | 正式版（Stable） | `.AppImage`、`.deb`、`.rpm` |
| Arch Linux x86_64   | 正式版（Stable） | `.pkg.tar.zst`              |

- [Grimodex v2.0.10 公式配布ページ（Release 公開後に利用可能）](https://github.com/kazormia296/Grimodex/releases/tag/v2.0.10)
- [AUR / grimodex-bin](https://aur.archlinux.org/packages/grimodex-bin)

Linux 向けパッケージは glibc 2.39 以上を必要とします。deb 版は、これに加えて libstdc++6 12 以上を必要とします。AUR 版は本 Release の公開後に別 workflow で更新されるため、`grimodex-bin` が v2.0.10 へ更新されたことを確認してから導入してください。

## ⚠️ インストール前に必ずお読みください

### プラットフォーム別配備区分

- **Windows / Linux**: v2.0.9 と同じく、正式版（Stable）の配備区分を継続します。
- **macOS**: v2.0.9 と同じく、Apple Silicon 向けのオープンベータを継続します。macOS 固有の動作および配布経路には、未確認の不具合が残存する可能性があります。重要な原稿で使用する前にバックアップを作成し、複製したデータまたは試し書きで動作を確認してください。
- **Arch Linux**: Fcitx 5 が Grimodex をアプリ単位で識別できるよう、v2.0.10 の Arch package は XWayland 経路で起動します。XWayland を利用できる環境で使用してください。

### v2.0.9 からの更新と v0.10.4 からの移行

- 本 Release の公開後、v2.0.9 の対応パッケージではアプリ内更新を利用できます。更新が提示されない場合は、v2.0.10 の Assets から対象環境の配布物を手動で取得してください。
- Arch Linux はアプリ内更新を使用しません。AUR の `grimodex-bin` が v2.0.10 へ更新された後、pacman または AUR helper で更新してください。
- v0.10.4 は自動更新機能を備えていません。本 Release の公開後、v2.0.10 の Assets から対象環境の配布物を手動で取得してください。本 Release の workflow では、Windows 版インストーラーを公開済み v0.10.4 の実インストーラーから移行する E2E で検証します。旧版の登録状態を検証できない場合は、旧版およびユーザーデータを変更せずに処理を停止します。
- ワークスペースおよび設定には既存のローカルデータ領域を引き続き使用します。初回起動時に、API キーを OS の資格情報ストアから Electron の暗号化ストレージへ移行する処理を試みます。安全な OS ストレージを利用できない場合、または移行に失敗した場合は警告を表示するため、設定画面で API キーを再入力してください。旧資格情報は削除しません。
- 大切な原稿は、更新前にご自身でもバックアップしてください。

### コード署名およびセキュリティ警告

- **Windows**: v2.0.10 のインストーラーは Authenticode 未署名です。Windows がセキュリティ警告を表示することがあります。インストーラーは必ず公式配布ページから取得し、出所を確認してください。
- **macOS**: Apple Silicon 向けです。本 Release の workflow で Developer ID 署名と Apple 公証を検証した v2.0.10 のアプリおよび DMG を提供します。
- **Linux**: v2.0.10 では AppImage、deb、rpm、Arch package を x86_64 向けに用意します。

### データ保管および AI 利用

- 原稿とプロジェクトデータは、端末内の SQLite データベースへ保存されます。Grimodex の利用にアカウントは必須ではありません。
- AIチャットは、OpenRouter / OpenAI / Anthropic の API キー、Ollama のローカルモデル、または Claude Code / Codex CLI / OpenCode などのエージェント型 CLI で利用できます。Ollama と各 CLI は別途導入し、必要な設定、認証、起動を完了してください。AI を設定しなくてもエディタは使用できます。
- デスクトップ版に埋め込みモデルがない場合、プロジェクトを開いたときの自動索引作成で、言語に応じた約 34〜37 MB のモデルを取得するためネットワーク接続が発生することがあります。モデルの取得中または利用できない場合も、全文検索は利用できます。
- 実験的な Semantic reranking の再順位付け自体は、デスクトップ版に同梱したローカルモデルで実行します。選択された関連シーンの抜粋は、通常のAIチャットと同じく、設定したAI providerへ送信する文脈に含まれる場合があります。
- Settings から Mozkey IbG の取得を開始すると、公式 GitHub Releases へ接続し、対象 OS／CPU 用 package と `SHA256SUMS` をダウンロードします。SHA-256 とファイルサイズを検証して OS のインストーラーを開いた後は、OS の案内に従ってインストールを完了してください。

## 機能系統増設

- デスクトップ版の Settings から、Mozkey IbG の公開済み Release を取得できるようにしました。Windows x64／Arm64、macOS Apple Silicon、Debian／Ubuntu 系 x64、Fedora／RHEL／SUSE 系 x64では、対象 package を自動選択して検証後に OS のインストーラーを開きます。Arch Linux では AUR の `mozkey-ibg-bin` を使用してください。
- Codex 詳細画面の名前の上で主読みを直接編集できるようにしました。Enter またはフォーカス移動で保存し、Escape で取り消します。代替読みは維持され、管理画面への導線も引き続き利用できます。

## システム改修

- 名前や別名の保存時に読みを自動で AI 推定せず、運用者が「AIで推定」を実行した場合だけ推定するようにしました。既存の読みは、推定の失敗時も保持されます。
- Codex CLI／Codex App Server では実行できない単発 AI 機能を IPC 送信前に検出し、対象ロールへ OpenRouter などの HTTP provider を割り当てる手順を表示するようにしました。通常の CLI チャットと、機能別の HTTP provider は併用できます。
- Linux の IME 辞書書き出し先を毎回検査し、directory を `0700`、snapshot を `0600` へ修復するようにしました。Mozkey IbG の secure reader が権限の広い書き出し先を拒否して、辞書を読み込めなくなる状態を防ぎます。

## 解消済み異常

- 読みまたは別名の入力中に、日本語 IME の変換確定 Enter が登録操作として扱われる問題を修正しました。
- Arch Linux package で Electron の汎用識別子または native Wayland 経路が使われ、Mozkey IbG へ `program:grimodex` が届かず、Grimodex の project dictionary が注入されない問題を修正しました。
- HTTP provider 専用の Codex 読み推定、候補判定、Map／Tree の単発 AI 処理が、CLI provider の空 endpoint を HTTP 経路へ渡して失敗する問題を修正しました。
