# GRIMODEX // TERMINAL REVISION v2.0.10

## OPERATOR NOTICE

This is the revision record for v2.0.10 of the GRIMODEX LLM-integrated narrative authoring terminal.

This revision adds a Settings path for obtaining official Mozkey IbG packages and direct editing of the primary Codex reading. It also makes reading registration reliable with Japanese IMEs and fixes Grimodex dictionaries not being recognized by Mozkey IbG on Arch Linux.

## DEPLOYMENT PROCEDURE

After this Release is published, select and obtain the manually installable package for your environment from the Assets below.

| Target environment  | Release channel | Manual installation formats |
| ------------------- | --------------- | --------------------------- |
| Windows x64         | Stable          | `.exe`                      |
| macOS Apple Silicon | Open Beta       | `.dmg`                      |
| Linux x86_64        | Stable          | `.AppImage`, `.deb`, `.rpm` |
| Arch Linux x86_64   | Stable          | `.pkg.tar.zst`              |

- [Official Grimodex v2.0.10 release page (available after publication)](https://github.com/kazormia296/Grimodex/releases/tag/v2.0.10)
- [AUR / grimodex-bin](https://aur.archlinux.org/packages/grimodex-bin)
- [Browser Editor](https://grimodex-try.pages.dev/)

The macOS `.zip` and `.app.tar.gz` files, metadata, blockmaps, and signature files are Assets used for automatic updates or distribution verification. For manual installation, select a format from the table above.

Linux packages require glibc 2.39 or later. The deb package additionally requires libstdc++6 12 or later. The AUR package is updated by a separate workflow after this Release is published; confirm that `grimodex-bin` has reached v2.0.10 before installing it.

## ⚠️ Please read before installing

### Platform release classification

- **Windows and Linux**: Continue the Stable release classification used for v2.0.9.
- **macOS**: Continues the v2.0.9 Open Beta classification for Apple Silicon. Unconfirmed defects may remain in macOS-specific behavior or its distribution path. Before using this build with an important manuscript, create a backup and verify its behavior with copied data or test writing.
- **Arch Linux**: The v2.0.10 Arch package starts through XWayland so that Fcitx 5 can identify Grimodex at application scope. Use it in an environment where XWayland is available.

### Updating from v2.0.9 and migrating from v0.10.4

- After this Release is published, supported v2.0.9 packages can use the in-app updater. If no update is offered, obtain the package for your environment manually from the v2.0.10 Assets.
- Arch Linux does not use the in-app updater. After the AUR `grimodex-bin` package reaches v2.0.10, update through pacman or an AUR helper.
- v0.10.4 does not provide automatic updates. After this Release is published, obtain the package for your environment manually from the v2.0.10 Assets. This Release workflow verifies the Windows installer with a migration E2E using the actual public v0.10.4 installer. If the previous registration cannot be validated, the process terminates without changing the previous installation or user data.
- Workspaces and settings continue to use the existing local data location. On first launch, Grimodex attempts to migrate API keys from the OS credential store into Electron's encrypted storage. If secure OS storage is unavailable or migration fails, Grimodex displays a warning; re-enter the API keys in Settings. Previous credentials are not deleted.
- Make your own backup of important manuscripts before updating.

### Code signing and security notices

- **Windows**: The v2.0.10 installer is not Authenticode-signed. Windows may display a security warning. Download the installer only from the official release page and verify its source.
- **macOS**: The package is for Apple Silicon. This Release workflow verifies the Developer ID signature and Apple notarization before providing the v2.0.10 app and DMG.
- **Linux**: v2.0.10 provides AppImage, deb, rpm, and Arch packages for x86_64.

### Data storage and AI use

- Manuscripts and project data are stored in a local SQLite database. A Grimodex account is not required.
- AI chat can use API keys for OpenRouter, OpenAI, or Anthropic; a local Ollama model; or an agentic CLI such as Claude Code, Codex CLI, or OpenCode. Install and complete any required setup, authentication, and startup for Ollama or those CLIs separately. The editor remains usable without AI configuration.
- If an embedding model is not already present in the desktop app, opening a project can start automatic indexing and use a network connection to download a language-specific model of approximately 34–37 MB. Full-text search remains available while the model is downloading or unavailable.
- Experimental Semantic reranking itself runs with local models bundled in the desktop app. Excerpts from the selected related scenes may still be included in the context sent to the configured AI provider, as with normal AI chat.
- When you start Mozkey IbG retrieval from Settings, Grimodex connects to the official GitHub Releases, downloads the package and `SHA256SUMS` for the target OS and CPU, and verifies the SHA-256 digest and file size. After Grimodex opens the operating system installer, follow the operating system prompts to complete installation.

## NEW CAPABILITIES

- Added a desktop Settings path for obtaining a published Mozkey IbG Release. On Windows x64 or Arm64, macOS Apple Silicon, Debian- or Ubuntu-family x64, and Fedora-, RHEL-, or SUSE-family x64, Grimodex selects the target package and opens the operating system installer after verification. On Arch Linux, use the AUR `mozkey-ibg-bin` package.
- The primary reading can now be edited directly above the name in Codex details. Enter or moving focus saves it, while Escape cancels. Alternate readings are preserved, and the full management path remains available.

## SYSTEM MODIFICATIONS

- Saving a name or alias no longer starts AI reading estimation automatically. Estimation runs only when an operator selects “Estimate with AI,” and existing readings remain intact if estimation fails.
- One-shot AI features that cannot run through Codex CLI or Codex App Server are now detected before IPC. Grimodex explains how to assign an HTTP provider such as OpenRouter to the relevant role. Normal CLI chat and a per-feature HTTP provider can be used together.
- Linux IME dictionary export locations are inspected on every write, repairing directories to `0700` and snapshots to `0600`. This prevents the Mozkey IbG secure reader from rejecting a dictionary because its export location has broader permissions.

## RESOLVED ANOMALIES

- Fixed the Enter key used to confirm Japanese IME conversion being treated as a registration action in reading or alias fields.
- Fixed the Arch Linux package using Electron's generic identity or the native Wayland path, which prevented `program:grimodex` from reaching Mozkey IbG and blocked injection of the Grimodex project dictionary.
- Fixed HTTP-provider-only Codex reading estimation, candidate judgment, and one-shot Map or Tree AI processing passing an empty CLI provider endpoint into the HTTP transport and failing.
