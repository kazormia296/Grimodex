# Grimodex モーション美学

SKILL.md の 4 スローガンの根拠と具体例。

Grimodex の文脈前提:
- 長時間の執筆セッションで使われる（数時間連続が普通）
- AI チャット・Codex 抽出・多パネル構成
- コア体験は「読む／書く」。UI はそれを邪魔しない黒子

---

## 1. Chrome は動く、Content は動かない

**原則**: テキストが置かれている領域は動いてはいけない。動いていいのは周辺の枠（Chrome）だけ。

### Do
- サイドパネル開閉時、エディタ側はリフローするだけで `scale` / `translate` しない
- ChatPanel の開閉はパネル自体だけが動く。中のメッセージは動かない
- TreeNode の expand/collapse で兄弟ノードはスライドでも OK、自分の中身はフェードのみ

### Don't
- TipTap 編集中の背景・周辺 UI に自動アニメを走らせる（フォーカスが切れた後なら OK）
- 本文スクロール連動で装飾アニメを入れる
- AI メッセージストリーミングを「文字が跳ねるタイプライター」にする → **カーソル blink + フェード挿入**に留める

### なぜ
執筆者の視線はテキストに張り付いている。その周囲で派手に動くものがあると、認知リソースを奪う。執筆ツールが「楽しい」より「疲れない」を優先すべき理由。

## 2. 減速 `*.out` を既定、跳ねる系は賞味期限付き

**原則**: 動く物体は目的地で止まるのが自然。UI の 9 割は減速系で足りる。

### イージング選択表

| イージング | 用途 | 頻度 |
|---|---|---|
| `power2.out` / `[0.16,1,0.3,1]` | 汎用（開く、入る、ホバー） | 無制限 |
| `sine.inOut` | yoyo・脈動（tour ハイライト） | 注意喚起の瞬間のみ |
| `power2.in` | 退場（次動作に譲る時） | 控えめに |
| `back.out(1.7)` / `elastic.out` | 「成功」の瞬間 | **セッションで数回まで** |
| `ease-in` 単体 | — | **ほぼ禁止** |

### `ease-in` 単体が禁止な理由

始まりがモッタリ → 到着がスッ、になり違和感。物理的に不自然（静止→加速しきって壁に突っ込む挙動）。入退場のペアで使うときのみ、退場側に限定。

### 跳ねる系の賞味期限

`back.out` や `elastic.out` は「成功感」を生むが、**productivity tool で連発すると疲れる**。Grimodex では以下の瞬間のみ許可:

- オンボーディング完了
- Codex 抽出の確定
- 達成系の通知

既存の `celebrationBurst` が `back.out(1.7) → power2.out` で締めているのは正しい設計。

### 連続発火の抑止

連続して codex を抽出した時、`celebrationBurst` が重なると鬱陶しい。**直前の発火から N ms 以内は skip** するデバウンスを呼び出し側に入れる。

## 3. モーションの発生源をトリガーに揃える

**原則**: ポップアップ系は「どこから出てきたか」を視覚的に示す。

### transform-origin 設計

- **ドロップダウン**: `transform-origin: top` + `y: -4 → 0`
  - 既存 `VARIANTS.dropdown` のとおり。崩さない
- **ポップオーバー**: トリガー位置に応じて切り替える
  - 右寄せ配置 → `top right`
  - 下寄せ配置 → `top left`
  - 中央スケールは違和感
- **InlineAIPalette**（カーソル位置に出る系）: `transform-origin` をキャレット基準に
- **トースト・通知バッジ**: 画面端から生える
  - 現在地ではなく**所属スロット**から出す
  - 例: 右下に出るトーストは `x: 20 → 0` で右端から

### なぜ
「同じ UI に何度遭遇しても毎回同じ場所から出る」と、ユーザーの注意フォーカスが安定する。発生源がブレる UI は、毎回どこを見ればいいか探す認知コストがかかる。

---

## 4. 退場は入場より速く、中断は巻き戻しではなくキャンセル

**原則**: ユーザーが「消す」を決めた後の演出は時間泥棒。

### Duration 非対称

- 入場: `DURATIONS.normal` (0.2s)
- 退場: `DURATIONS.fast` (0.15s) 目安

ユーザーは既に次の操作を決めている。長い退場アニメは「待たされている」感を生む。

### 中断時の挙動

**ダメな例**:
- 開き 0.2s 途中の 0.1s で閉じる → いったん 0.2s 開ききってから閉じる（カクつく）

**良い例**:
- 現在の進行位置からそのまま逆再生
- Framer Motion: `AnimatePresence` + `key` + `initial={false}` でほぼ自動
- GSAP: `.reverse()` か `gsap.to(el, { ...original, duration: 残り })`

### なぜ Grimodex で効くか
**パネル開閉を連打する**ユーザー挙動が想定される。ChatPanel・CodexManagementPanel などの切替が滑らかかどうかは実使用で効く。

---

## 付録: エディタ本文に絶対入れないもの

- 自動スクロールアニメ（ユーザーのスクロール以外）
- カーソル位置の自動ハイライト（ユーザーが選択していない場所）
- 文字単位の入場アニメ（読み始めに動くテキストは読みにくい）
- 背景のパララックス・装飾パーティクル

執筆は紙の上で起きる出来事の拡張であって、ゲームではない。
