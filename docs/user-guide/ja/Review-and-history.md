# 校閲と履歴

> 対象バージョン: Grimodex 2.0.10
>
> 対象: Electron版 / Web Editor
>
> 最終動作確認: 2026-08-02

校閲は本文を変更する前に問題候補を見つける作業です。履歴とスナップショットは、変更後に戻すための仕組みです。目的と保護範囲が異なるため、同じものとして扱わないでください。

## 校閲に使う機能

| 目的 | 機能 |
| --- | --- |
| 日本語の表記・文体の候補を確認する | Linter |
| 作品内の用語や表記を揃える | 用語辞書 |
| 他シーンとのつながりを確認する | 関連シーン |
| Codexとの食い違いを確認する | 設定・整合性の校閲 |
| 伏線や作中時間を確認する | Foreshadow、Timeline |
| AIに複数の観点でレビューさせる | Review / 校閲AI |

指摘は候補です。作品固有の表現、意図的な破格、語り手の癖まで機械的に修正しないでください。

## リビジョン履歴

リビジョン履歴は、現在のシーンやドキュメントの編集履歴を確認するための機能です。

1. 対象シーンを開きます。
2. ProjectメニューまたはショートカットのCtrl+Shift+Hから履歴を開きます。
3. 変更時刻と内容を選び、プレビューまたは差分を確認します。
4. 戻す場合は対象を確認して復元します。

復元は現在の内容を失う可能性があります。復元前の状態が必要なら、先にプロジェクトスナップショットを作成するか、ワークスペースをバックアップしてください。

## プロジェクトスナップショット

プロジェクトスナップショットは、本文・章立て、Codex、Snippet、Map、Foreshadow、Labels、校閲設定など、プロジェクト単位の状態を大きく戻したいときに使います。

1. Projectメニューからプロジェクトスナップショットを開きます。
2. 名前と説明を付けて作成します。
3. 大きな変更後に戻す場合は、対象スナップショットと復元範囲を選びます。
4. 復元前の現在状態も保存されることを確認してから実行します。

スナップショットは同じSQLiteデータベース内に保存されます。データベースが壊れた場合の災害復旧には使えないため、ワークスペースバックアップも別に用意してください。

## 三つの復旧機能の違い

| 機能 | 守る対象 | 主な用途 |
| --- | --- | --- |
| リビジョン履歴 | 個別のシーン・ドキュメント | 直前の編集や一つの変更を戻す |
| プロジェクトスナップショット | プロジェクトの内容・設定 | 大きな構成変更を戻す |
| ワークスペースバックアップ | SQLiteデータベース全体 | DB破損、全損、移行失敗から復旧する |

## 保存されるデータ

リビジョンとスナップショットはデスクトップ版のSQLiteに保存されます。ワークスペースバックアップはデータベースの外にあるbackupsフォルダーへ保存されます。

## 外部へ送信されるデータ

Linter、履歴閲覧、手動のスナップショット操作はローカルで処理されます。AI校閲や整合性分析を実行した場合は、選択した本文・Codex・設定などがAI接続先へ送信される場合があります。

## よくある問題

### 履歴に戻す前の状態を残したい

復元前にプロジェクトスナップショットを作成し、必要ならワークスペース全体をバックアップします。復元操作は現在の編集内容を置き換えるため、対象範囲を確認してください。

### スナップショットを作ったのにワークスペースが開けない

スナップショットはSQLite内にあるため、DB自体の破損や紛失からは守れません。backupsフォルダーの自動バックアップからの復元を使います。
