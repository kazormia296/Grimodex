# ワークスペースと作品構造

> 対象バージョン: Grimodex 2.0.10
>
> 対象: Electron版 / Web Editor
>
> 最終動作確認: 2026-08-02

## 用語

| 用語 | 意味 |
| --- | --- |
| ワークスペース | 作品とデータベースをまとめる保存先フォルダー |
| プロジェクト | ワークスペース内の一つの作品 |
| フォルダー / 章 | プロジェクト内の整理単位 |
| シーン | 本文を執筆するドキュメント |
| Note | 本文とは分けて保存するメモや補助ドキュメント |
| Codex | キャラクター、場所、用語、設定などの構造化された知識 |
| Snippet | チャットなどから保存する再利用可能な文章・断片 |

一つのワークスペースに複数のプロジェクトを置けます。作品を分けたいときも、まず保存単位であるワークスペースと、作品単位であるプロジェクトを区別してください。

## デスクトップ版のフォルダー構造

ワークスペースのルートは、おおむね次の構成です。

    <workspace>/
      grimodex.db
      .grimodex/
        workspace.json
      backups/

- grimodex.dbが本文、Codex、Snippet、チャット履歴、作品設定などを保持するSQLiteデータベースです。
- .grimodex/workspace.jsonはワークスペースの識別情報です。隠しフォルダーをコピーから外さないでください。
- backups/には自動バックアップが保存されます。ファイル形式は.dbまたは.db.gzです。
- 外部Markdownをマウントしたシーンを使う場合、本文の一部は指定した外部ファイルにも保存されます。

データベースを直接編集したり、grimodex.dbだけを移動してワークスペースとして開いたりしないでください。移動・複製にはワークスペースフォルダー全体を使います。

## ワークスペースを開く

1. 起動時のランチャーで最近使ったワークスペースを選ぶか、フォルダーを開きます。
2. 別の保存先に移る場合は、ワークスペースメニューから別フォルダーを開きます。
3. 新しく始める場合は、新しいワークスペースを作成し、専用フォルダーを選びます。

信頼できないフォルダーや、出所の分からない外部ファイルを開かないでください。

## プロジェクトを整理する

作品メニューから新しいプロジェクトを作成します。プロジェクト内では、フォルダー、章、シーン、Noteを用途に合わせて組み合わせます。

- 章やシーンは執筆順に並べます。
- 本文に直接入れない調査メモや作業メモはNoteまたはCodexへ分けます。
- 作品固有のAI指示や想定読者などは、作品設定で管理します。
- シーンごとにChatの会話履歴が分かれるため、相談対象を切り替えるときは現在のシーンを確認します。

## 別PCへ移動する

1. Grimodexでワークスペースを閉じるか、アプリを終了します。
2. ワークスペースのルートフォルダー全体をコピーします。
3. コピー先で、grimodex.dbと.grimodex/workspace.jsonが揃っていることを確認します。
4. 新しいPCの同じ世代のGrimodexで、コピー先フォルダーを開きます。
5. 作品、本文、Codex、履歴を確認してから元データの利用を再開します。

バックアップフォルダーを含めると、アプリ内復元用の世代も移動できます。異なるバージョン間の移動では、先に[インストールと更新](Install-and-update.md)と[保存・バックアップ・入出力](Data-backup-and-transfer.md)を確認してください。

## Web Editorからデスクトップへ移す

Web EditorのワークスペースはブラウザのIndexedDBに保存されます。デスクトップ版のgrimodex.dbとは別物です。

Web Editorからハンドオフ用のエクスポートを作成し、デスクトップ版の「Grimodexで続きを書く」または同等のインポート操作で読み込みます。自動同期やクラウド上の共通データベースはありません。

## 外部Markdownシーン

外部Markdownを実体とするシーンは、ファイルとデータベースを連携させる上級機能です。通常のシーンとは保存場所と対応書式が異なります。

- エディタの保存でMarkdownファイルへ書き戻されます。
- 外部でファイルが変更され、未保存の編集もある場合は、ローカルを保持するか再読み込みするかを選びます。
- Markdown向けの制限付き書式を使うため、通常のシーンのルビや出所Markなどがそのまま使えない場合があります。

競合が起きたときに迷う場合は、まずファイルとワークスペースを別々にコピーしてから判断してください。

## 保存されるデータ

通常のシーン、Note、Codex、Snippet、チャット履歴、プロジェクト設定はSQLiteに保存されます。外部Markdownシーンだけは、指定したファイルが本文の実体になります。

## 外部へ送信されるデータ

ワークスペースを開く操作だけで原稿本文を開発者へ送ることはありません。AIを実行した場合は、選択した本文やコンテキストが設定したプロバイダーへ送られる場合があります。

## よくある問題

### ワークスペースが開けない

選択したフォルダーがワークスペースのルートか確認します。別の階層を選んでいないか、grimodex.dbが存在するか、ファイル権限があるかを確認してください。新規ワークスペースは空の専用フォルダーから作成します。

### 作品が見えない

別のワークスペースを開いていないか確認します。設定のDataに表示される保存先と、ファイルマネージャーで確認したフォルダーを照合してください。
