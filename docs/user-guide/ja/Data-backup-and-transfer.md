# 保存・バックアップ・入出力

> 対象バージョン: Grimodex 2.0.10
>
> 対象: Electron版 / Web Editor
>
> 最終動作確認: 2026-08-02

## まず保存場所を理解する

デスクトップ版の通常のワークスペースは、選択したフォルダーの中に保存されます。

    <workspace>/
      grimodex.db
      .grimodex/workspace.json
      backups/

grimodex.dbが本文・Codex・Snippet・Chat履歴・作品設定などの正本です。日常の本文をMarkdownファイルとして別に保持する方式ではありません。Markdownはインポート・エクスポート用で、外部Markdownシーンを使う場合だけ例外的にファイルが本文の実体になります。

アプリをアンインストールしてもワークスペースが自動でクラウドへ退避されるわけではありません。重要な作品は、アプリの更新やOS変更の前にワークスペース全体を別の場所へコピーしてください。

## 自動バックアップ

自動バックアップは設定で有効・無効を切り替えられます。既定では有効で、ワークスペースを開いたときや切り替えたときに、前回から設定した間隔が経過していれば作成されます。バックグラウンドで常時タイマーが動く仕組みではありません。

設定のDataで、次を調整できます。

- 自動バックアップのON/OFF
- 作成間隔（UIの範囲は15〜360分、既定60分）
- 保持世代数（UIの範囲は1〜50、既定10）

保存先はワークスペースのbackupsフォルダーです。ファイル名はgrimodex-日時.dbまたはgrimodex-日時.db.gzです。バックアップはワークスペース全体のSQLiteを対象にします。

自動バックアップは同じディスク上の復旧用コピーです。ディスク故障、誤削除、ランサムウェア、同期ツールの破損から守るものではないため、定期的に外部ストレージへワークスペースまたはバックアップをコピーしてください。

## アプリ内でバックアップから復元する

復元はワークスペース全体を置き換える破壊的操作です。

1. 設定のDataを開きます。
2. Backupセクションのバックアップ一覧を更新します。
3. 日時とサイズを確認して復元対象を選びます。
4. 確認操作を二度行います。
5. 復元前の現在状態が安全用に退避されることを確認して実行します。
6. 復元後にアプリが再読み込みされるまで待ちます。

復元前に、未保存の本文、インラインAIの未確定編集、外部Markdownの変更を確定または退避してください。対象のバックアップに含まれない最新変更は復元されません。

## リビジョン・スナップショットとの違い

- リビジョン履歴は一つのシーンやドキュメントを戻すためのものです。
- プロジェクトスナップショットは、一つの作品の構成や知識を戻すためのものです。
- ワークスペースバックアップは、複数作品を含むSQLite全体をDB外から戻すためのものです。

同じSQLite内にあるスナップショットは、DB破損からの復旧には使えません。大きな変更の前には、スナップショットとワークスペースバックアップを目的に応じて使い分けます。

## エクスポートとインポート

作品メニューのExport、または設定のDataから利用します。

| 目的 | 使う形式・操作 |
| --- | --- |
| 本文を他のエディタへ渡す | Markdown、テキスト、HTMLなど、表示された形式から選ぶ |
| 投稿・書籍向けに整形する | Exportのサイトプリセット、ルビ、傍点、縦書きなどの設定を確認する |
| 作品をまとめて移動する | プロジェクトZIP |
| AI Novelistへ渡す | Novel形式の専用エクスポート |
| Codexだけを再利用する | Codex JSON |
| Web Editorとデスクトップを行き来する | ハンドオフ用エクスポートとインポート |

エクスポートには、形式に応じてシーン本文、メタデータ、チャット履歴、Snippet、Map、出所情報などを含めるオプションがあります。ダイアログの対象範囲を確認してください。

エクスポートは移行・共有用であり、SQLiteの全テーブル、履歴、設定、復元可能な状態を必ず含む完全バックアップではありません。

## Web Editorの保存と持ち出し

Web Editorのデータは現在のブラウザプロファイルのIndexedDBに保存されます。サーバー側のクラウドバックアップや別端末との自動同期ではありません。

ブラウザのサイトデータを消す前、別ブラウザへ移る前、作品を長期保存する前に、エクスポートまたはハンドオフファイルを作成してください。デスクトップ版へ移した後も、内容と文字化けを確認します。

## 保存されるデータ

デスクトップ版はワークスペースのSQLite、backupsフォルダー、必要に応じて外部Markdownファイルへ保存します。Web EditorはIndexedDBと、ユーザーが明示的に作成したエクスポートファイルへ保存します。

## 外部へ送信されるデータ

保存、バックアップ、ローカルの復元は、原稿本文をAIへ送信しません。Exportやハンドオフをユーザーが行った場合、生成ファイルが保存先や共有先へ渡ります。AI付きエクスポートやAI分析を実行した場合は、AI設定に従って送信されます。

## よくある問題

### バックアップ一覧が空

ワークスペースが開いているか、自動バックアップが有効か、設定間隔がまだ経過しているかを確認します。自動バックアップはワークスペースを開いたタイミングで作られるため、常時監視ではありません。

### 復元後に新しい編集が消えた

バックアップ作成時点より後の変更は、復元対象には含まれません。復元前に現在状態を別のバックアップまたはエクスポートへ退避してください。

### ZIPをバックアップとして使ってよいか

ZIPは移動・共有に便利ですが、DB全体の復元を保証するものではありません。災害復旧にはワークスペースコピーまたはbackups内のDBバックアップを使います。
