The ContextBar exact-preview sub-flow uses the same authority boundary as
Chat send. Each request is generation-owned and bound to an immutable
Workspace, Project, session, scope, focus, and prompt-input key. Closing,
reopening, unmounting, or changing that authority invalidates the old request;
neither a stale result nor its `finally` callback may publish prompt data or
clear the current loading state.

## Generic renderer SQL migration stage

This branch establishes a source-level migration ceiling, not a runtime
security boundary or an endorsement of the existing generic routes.
`policies/architecture/generic-renderer-sql-writes.json` now records 223
existing route signatures representing 306 callsites. Moving Plot and
Foreshadow create flows to typed commands lowered the migration ceiling by four
callsites, and moving Plot history restores to one atomic typed command lowered
it by three more. The architecture scanner counts:

- `db.insert`, `db.update`, and `db.delete` calls against their schema target;
- raw `INSERT`, `REPLACE`, `UPDATE`, and `DELETE` SQL literals against their
  table target;
- direct renderer calls to `db_execute` and `db_execute_batch`.

Removing or migrating a callsite requires lowering the manifest in the same
change; stale manifest headroom fails the gate. Adding a new generic callsite
also exceeds the recorded ceiling and fails `validate:architecture`; new work
should use a typed persistence command instead. If a temporary generic route
is unavoidable, changing the manifest is an explicit architecture-debt review
point.

Remaining debt is deliberately not hidden: the 306 existing callsites still
need bounded-context migration to typed commands, after which the manifest
counts should be reduced. A native SQLite Authorizer/table policy remains a
separate hardening stage and is not claimed as completed here.

Codex Match, Lint, AutoSave, and scene semantic indexing now reserve their
debounced work through one Editor Analysis Scheduler instead of owning four
independent wake timers. The scheduler latest-coalesces per producer key,
starts simultaneously due work on separate ticks in
save → Codex Match → Lint → Semantic order, and terminally handles rejected
background tasks. Explicit AutoSave flush still cancels the reservation and
enters the existing document single-flight drain directly.

The runtime gate rejects metrics unless editor input and autosave both name the
canonical seeded Scene. The later small-Scene smoke remains a separate
functional check and cannot accidentally satisfy the performance budget.
The 5k/50k/200k Editor, 0/20/200 Beat, 500/2k/10k Tree/Grid,
100/500/2k Linear, 100/1k/5k Chat, 1k-scene/100-thread/5k-marker-link
Timeline, 1k/5k Chronicle, and 500/2k Map profiles remain independently
selectable focused fixtures; the per-PR Electron run deliberately uses the
combined canonical profile above instead of running the entire matrix as one
unstable Cartesian benchmark.

Chronicle keeps the complete lane pack, world coordinates, selection, drag
targets, and causal graph in memory, but projects only the vertically visible
marker and edge spans plus one viewport of overscan into the DOM. Scroll and
resize update that projection independently of horizontal pan; the runtime
fixture proves both the full state cardinality and a strictly smaller rendered
marker count before opening the unchanged frame-rate gate.

For example, `pnpm electron:perf --review-fixture chat-100` runs the focused
Chat profile, while `pnpm electron:perf --review-fixture editor-200k` runs the
largest editor payload. Omitting `--review-fixture` keeps the stable canonical
per-PR profile.
