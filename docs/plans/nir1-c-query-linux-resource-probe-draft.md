## Why a probe, not another SQL change

On the current candidate, private Q513/R3/D0 finishes all A3 SQL at 4.988316 ms but returns Unavailable before A3 evaluation with no deadline observation. The first revision alone yields A2 171 rows/254,195 bytes and at least A3 85 rows/21,397 bytes; the existing `8 × bytes + 4 KiB × rows` reservation therefore exceeds 2 MiB even *without* nonnegative A3 global rows (lower bound 3,253,312 bytes). That is a conservative reservation, **not** measured simultaneous memory or a hard upper bound. The current small public-reader release test failed the 8 ms positive path 7/7 times (8.021991–8.038124 ms); generous-deadline retries were Available. No fixed threshold or qualification check may be removed to turn these failures into PASS.

## GDX-PRECHECK-001 — actors, residuals, finite owner

Untrusted: malformed synthetic/persisted shapes and candidate code; a same-UID malicious process, host admin/kernel compromise, arbitrary child escape from a cgroup and unforced outbound traffic are **not** defeated by this diagnostic. Run only on an acceptable trusted Linux host; otherwise stop. Protect assets: source database, other workspaces, host responsiveness, partial Graph disclosure, stale results and truthful receipts. The supervisor may start and terminate only its exact benign owner subprocess; it cannot kill this Pi session, product processes or unrelated units.
