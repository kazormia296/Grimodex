# M4 変更レビューの画面の案（起案、2026-11-25）

状態：**§6 の 4 点は利用者が確認済み（2026-11-25）。§7 の形で実装した（案 A）。** §1・§2 は実装の前の調査の記録。
事実は 2026-11-25 の枝（`#1129` の head）を静的に読んだもので、実行していない。大半は read-only の別の agent の調査で、起案者が確かめたのは §1 の 1・3・4・5。
前提：[変更レビューの設計](m4-change-review-design-draft.md)、DR-M4PF-11・12。

## 1. 確かめた事実

1. **作者は比較する版を今も作れる。** Codex の詳細の「関係」タブにある「Entity / Relationレビュー」「Entity / Relationレビューを準備」から、
   場面と項目を選んで版を作り、承認できる（`features/codex/components/CodexTypedRelationsSection.tsx`）。旗は無く、製品の build の既定で開く。
   既定の runtime mode（review-only）でも作成と承認はできる（閉じるのは disabled か hard-disable の時だけ）。
2. 変更レビューの読み取り（`nir1_change_review_read`）に、renderer の呼び手は無い。
3. **応答は「変化の種類」と引用の変化だけで、前後の値（名前・種類）を返さない**（`Nir1ChangeReviewRead`）。
4. **「内容が変わった」は、元の項目の source token（更新時刻を含む）の比較**。中身が同じで保存し直しただけでも出る。
5. `restricted` の profile に作者の操作で入る入口は、製品の build に無い（`PROFILE_ACTIVATION_UI_ENABLED = false`）。
   起動時に状態の記録から `restricted` になった場合、版の作成・承認・読み出しは通るが、変更レビューは `unclassified` なので拒まれる。`unavailable` では project 自体が開けない。
6. Work Layer の変更レビュー（`features/work-layer/ChangeReview.tsx`）は開発の見本でだけ開く。見本は出来事の例（タイトル・手段・時期の表）で、実データの形（人物・関係）と合わない。

## 3. 画面（案 A の見え方）

```
Entity / Relationレビュー
  （今の欄：この版の人物・関係・引用、承認・却下）

  前に承認した版との違い
   アリス（人物）          元の項目が更新されています
      「彼女は鍵を拾った」   引用の位置が変わりました
      「剣を抜いた」         引用がなくなりました
   ボブ（人物）            変化はありません
   アリス → ボブ（関係）    今回はじめて入りました
   ※「更新されています」は、保存し直しただけでも表示します。
```

名前は renderer が持つ Codex の項目から引く（応答は id だけ）。関係は引用の本文を持たないので、引用の比較は出さない。

## 4. 文言の案

| 場合                          | 文言                                                   |
| ----------------------------- | ------------------------------------------------------ |
| 欄の見出し                    | 前に承認した版との違い                                 |
| added                         | 今回はじめて入りました                                 |
| content-changed               | 元の項目が更新されています                             |
| unchanged                     | 変化はありません                                       |
| unresolved                    | 前の版を確かめられません                               |
| 引用 unchanged                | 引用は同じです                                         |
| 引用 relocated                | 引用の位置が変わりました                               |
| 引用 lost                     | 引用がなくなりました                                   |
| 引用 gained                   | 新しい引用です                                         |
| 注意書き                      | 「更新されています」は、保存し直しただけでも表示します |
| 比べる版が無い                | 比べる承認済みの版がありません                         |
| 読めない（unavailable、拒否） | 違いを表示できません                                   |

今の画面の文言は日本語の直書きで、locales を通していない。案は同じ流儀（英語の UI でも日本語で出る）。

## 5. 最初の版で入れないもの

- 前後の値（名前・種類）の表示。出すなら読み取りの拡張が要る（過去の承認済み版の値を返す範囲が広がる）。今の版の名前と種類は、同じ画面の上の欄に出ている。
- 項目ごとの適用・却下（追記 9：入れない）。承認・却下は今の版全体の操作のまま。
- 下流の影響の一覧（IPC が無い）、Freshness／Build Action の表示。
- `restricted` で読めるようにする区分の変更（DR-M4PF-12 の 3 のまま。§1 の 5 のとおり、製品の操作では入らない）。

## 6. 利用者の確認（2026-11-25、AskUserQuestion。いずれも推奨の選択肢。contracts の M4 の記録 追記 10）

1. 問「変更レビュー（今の版と、前に承認した版の違いを見せる欄）を、どこに出しますか？」→「レビュー画面の中（推奨）」（§2 の案 A）。
2. 問「欄の文言は、案のままでよいですか？」（保存し直しただけでも「更新されています」が出る注意つき）→「案のまま（推奨）」（§4）。
3. 問「前の版の名前や種類（何から何に変わったか）も、最初の版で出しますか？」→「出さない（推奨）」。
4. 問「「外部送信を制限中」の状態では、この欄は「違いを表示できません」になります。このままでよいですか？」→「このままでよい（推奨）」。区分は変えない（DR-M4PF-12 の 3 のまま）。
