# CB-2 の委任判断の記録（mutation の前に記録。継続計画 §3.2 の形式）

出所の確認済み draft は K2/4（`docs/plans/nir1-c-body-disclosure-proposal-4-draft.md`。`graph-target-scene-body-disclosure` と `scope-storage-authority`。2026-10-17 の Session B2 で確認済み。K2-3 は取消の入口に grant を要さない）。この文書は S1（grimodex-db の writer 群）の mutation の前に書く。S2（grimodex-node の grant と gate と入口）と S3（Main の横取りと CI seam）の判断は、実装の前に同じ形で追記する。DR-CB2-8〜11 は S2／S3 の設計の記録で、S1 の commit の時点では実装がない。名前と形は S1 の API（DR-CB2-1、-2、-12）と矛盾しないように固定し、S2／S3 で変える場合は追記で理由を書く（後から本文を直さない）。

U3 の委任（継続計画 §3.1）の外に当たる要素は、この lane の範囲に無い。新しい受信先、保存範囲の拡大（schema、table、列）、確認済みの閾値の緩和、製品入口の公開、認可の削除、新しい authority のどれも置かない。固定されていて変えないもの：宣言、取消、クリアの書込みは行の宣言の2列だけ（`version`、`source_token`、`updated_at`、A1 の意味の列、incarnation、principal、`tree_nodes`、registry、ほかの Scene の行は書かない）。feed の kind は `scene-body-declaration`（CB-1）。A1 の保存の payload に宣言の欄を足さない。`narrative_scene_scope_update` と取消の入口は `GRANT_REQUIRED_COMMANDS` に載せない。v1 で宣言できる値は G-01 subset だけ。

## owner/lifecycle matrix（GDX-PRECHECK-001。mutation の前に記録。有限）

DSN §7.4（grant の lifecycle）と DSN §1.10／DT-2 の matrix を、この lane の型にした。「所有者」は値を作り放す側、「終了の証拠」は後始末が済んだことを示す値である。

| 区分 | 宣言の writer と取消の writer（S1。grimodex-db） | grant（MG-1。S2／S3） | gate と seam（S2／S3） |
|---|---|---|---|
| entry | Native の typed な入口2つだけが呼ぶ。宣言は Main の横取りで grant が付き、writer は grant の consume が作る `ConsumedBodyDeclarationBinding` なしには呼べない。db crate では `native-current-human-capture` の feature gate の中にだけ置き、MCP は有効にしない。restore のクリア（CB-1）は入口ではなく、gate によらない | Main の `GRANT_REQUIRED_COMMANDS` の invoke だけ。Native の `main_grant_*` は Main 専用で `NAPI_COMMANDS` に載せない | gate を開ける N-API は Main 専用。呼べるのは起動時の seam 判定の後だけ |
| start | `ActiveWorkspaceSnapshot`（participant を持つ）を呼出し側が取得して渡す。writer はまず process-local の quarantine を DB を触らずに確かめ、次に transaction を開く。DB を読む前に拒否できるもの（gate、caller、workspace、quarantine）は先に拒否する | sender が destroyed でない、window が一致、gate が開いている、workspace が Ready、D2a の activation の途中でない | seam の条件（packaged でない、`CI=true`、owner token、nonce）を Main が起動時に1回だけ判定する |
| retry | 暗黙の再試行なし（transaction を開く回数は1回）。同じ request ID の再送は idempotency の記録を返す。quarantine 中は何度呼んでも `restart-required` | 期限切れや revoke の後は新しい preview から。同じ previewId の issue のやり直しと消費済みの grant の再利用は拒否 | 再判定しない（process の間は固定） |
| reentrant | 同じ Scene への2件目は OCC が拒否する。DB の書込みは `BEGIN IMMEDIATE` で直列。writer の中から別の participant SQL scope を開かない（`ensure_no_nested_sql_owner`） | process 全体で1件。2件目は `MAIN_GRANT_BUSY`（Main の in-flight 記録と Native の slot の両方）。待たせない | — |
| admission closure | transaction の中で lifecycle の binding を `check_current_binding` で照合し、COMMIT の直前にもう一度照合する（stop を観測したら rollback）。fence は `Admission`（呼出し側の probe を含む）。Open／Restore／Recover／Shutdown の transition は participant の drain を待つので、COMMIT より前に restore のクリアが走って ABA になることはない | TransitionAdmitted、Unavailable、ShutdownRequested で revoke。preview は Ready でないと拒否 | gate は process の間は開いたまま。workspace が Ready でない間は writer が拒否する |
| pending-start work | transaction を開く前は何も書かない。grant の consume は transaction の前（消費は戻さない）。pending marker や意図の記録は作らない | `Previewed` は期限か revoke で消える | — |
| active handle | participant は `ActiveWorkspaceSnapshot` の借用として COMMIT の終端の証拠が作られるまで保持する。接続は有限の待機（mutex、busy、操作）。証拠を作る前に放さない | slot と Main の in-flight 記録（WebContents に束縛） | — |
| cancellation | COMMIT の前の stop は rollback（`RolledBack` の証拠）。COMMIT の途中・直後の stop は COMMIT を止めず、`Committed` か `QuarantinedUnknown` の証拠を作ってから放す。取消の入口の要求は writer のキャンセルではなく宣言を消す操作 | ダイアログの取消、sender の破棄と遷移、window の close | — |
| bounded wait | K1b の上限（DB mutex 100 ms、busy 100 ms、操作 250 ms。DR-CB2-7）。期限なしの `db.with_conn` は使わない。超えたら typed に失敗し grant は戻さない。COMMIT の結果の読み直しにも同じ上限を使う | preview から 60 秒 | — |
| 終了の証拠 | `DeclarationTerminalEvidence`（`Committed`／`RolledBack`／`QuarantinedUnknown`）。commit の経路（`commit_outcome.rs`）の外では作れない型で、writer は証拠を持つ結果でしか返らない | slot が `Consumed`／`Revoked`／`Expired` になり、Main の in-flight 記録が消える | — |
| error／timeout／onClosed | COMMIT の結果が不明なときは draft の手順 1〜4（rollback の確認、清潔な接続での読み直し、3つの識別子の照合、成功／失敗／不明）。panic も不明として扱い読み直す。接続の quarantine の既存の規則は変えない | issue／consume の失敗は writer を実行しない。revoke の失敗は握りつぶさず次の preview を拒否する | seam の不一致は gate を開けない |
| restart | 永続状態は宣言の2列と feed と idempotency のみ。marker なし。再起動の後は DB の状態だけで判定し、process-local の quarantine は解ける | 永続化しない。再起動で grant はすべて無効 | gate は再起動で閉じる |

COMMIT と lifecycle の edge の順序（DR-CB2-3 で確定）：(i) writer は participant を COMMIT の終端の証拠が作られるまで保持する（`ActiveWorkspaceSnapshot` を関数の最後まで借用する）。(ii) COMMIT の前に stop／edge を観測したら rollback し、`RolledBack` の証拠で放す。(iii) COMMIT の最中・直後の edge は COMMIT を取り消さない。(iv) restore のクリアは participant の drain の後に走るので、COMMIT した宣言を確実にクリアする（ABA なし）。(v) COMMIT は Core の lock の外で行う（lifecycle の lock は pre-commit の照合で短く取って放す）。(vi) 通常の participant（本文の保存、読取）は止めない（writer は有限の待機で自分が失敗する）。COMMIT が戻らない間は終端を待つ。終端が来ない場合の最後は Main の観測予算の後の `exit(1)`（DSN §1.6 の 4。ここでは待つことと証拠を偽造しないことだけを固定する）。
