### 残余と観測

1. BeforeClaim（claim の直前）の index generation の変更は、Revision の変更と同じく claim が読まないので request が送られる（DI-1c から続く残余。DR-DI1A-16、22、25）。claim の transaction に seal の再読取を足す案は DI-1c の claim の契約を変えるので採らなかった。
2. D-final の `begin` が `warming`／`stale`／`busy` を受けると owner は unserved を記録し、READY の公開で graph-ready の通知が出うる（D-final が自分で待った後でも出る）。製品入口が閉じている間は起きない。CP-2b／CP-3a が graph-ready を契機に query を出す設計なら、余分な query が出うる（DR-DI1A-21 (4)）。
3. query が成功すると worker は退役して slot が Empty に戻り、同じ process の次の Graph の要求は直前の prepare の開始から 1 s（`rebuild_min_interval`）まで `warming` を待つ（CP-2a の性質。W = 4 s が覆う）。
4. `busy` の原因の区別（slot の使用中か stamp の読取の失敗か）は owner の counter からの推定で、owner は stamp の失敗を `busy` にしない（DR-DI1A-8、21）。実測では stamp の失敗が0件だった。
5. 履歴：Graph 由来の attempt の生成出力は `PendingAuthority` で除外されたまま、Human は採用されうる（DR-DI1A-19）。Pending を外す新しい draftRef で、Index の ref の形（`nir1-graph-index-ref@1`）を採用するか版を上げて置き換える（DR-DI1A-3）。
6. 実 worker の A-11 は取っていない（cache と再資格化は worker の種類に依らないため fake worker で覆った。DR-DI1A-30）。DD-1 の最終候補で A-11 が通ることが DP-1 の条件。
7. 製品入口は閉じたまま：`PRODUCT_GRAPH_PUBLISHED = false`、IPC、preload、N-API、schema、`Cargo.toml` の依存の変更なし。
8. 評価 feature の baseline arm（P-12）は Graph の kept item を拒否したまま（`NIR1_EVAL_BASELINE_GRAPH_ITEM_UNSUPPORTED`）。(c-1) の Graph の candidate ref は DR-DI1A-32 で持たせたが、baseline の Graph 対応は DD-1 の担当（Graph の variant は HOLD）。

### 申し送り

- DD-1：(c-1) の candidate ref は Graph の group を持つ（DR-DI1A-32）。baseline arm（P-12）は Graph の kept item を `NIR1_EVAL_BASELINE_GRAPH_ITEM_UNSUPPORTED` で拒否したままなので、Graph の variant の baseline を走らせるには DD-1 が record に Graph の outcome を持たせて対応する（残余 8）。`busy_cause`（`StampUnreadable` は counter からの推定）を到達の理由の証拠にせず、owner の `diagnostics()` を直接読む（DR-DI1A-21）。結果の種別 `DFinalGraphOutcome`（`NativeSelectedPreparedRequest::graph_outcome()`）は (c-2) の位置で参照できる（`Used`／`Empty`／`NotRequested`／`Unavailable`〔busy の推定の原因つき〕／`WaitExpired`〔warming、stale、query〕／`Invalidated`〔seed、binding、seal〕／`NotUsed`／`Excluded`）。cold process の trial の骨組み（`nir1_graph_reach_tests.rs`）と、A-11 を最終候補で通すこと。Graph の variant の evidence は HOLD。
- DI-1b：Graph の group は同じ（Revision, edge）の accepted IR の group を置き換え、512 items と 2 MiB と attempt の参照数の上限（`NATIVE_ATTEMPT_MAX_REFERENCES`）を共有する。history を最終予算に入れるときも Graph の入力数と参照数を含める。
- CP-3b：seed の規則（`created_at`、`entry_id` の昇順の先頭の pin）を renderer の seed の選択と揃える。
- CP-2b／CP-3a：unserved と graph-ready の通知（残余 2）。
- CP-4／PUB-G：送信の遅れ（最大 W = 4 s）の開示。製品入口を開くときの `PRODUCT_GRAPH_PUBLISHED` の変更は DI-1a の外。
- Session C-2：D-final で Graph が使われない場合（`busy`、`limit`、`timeout`、`worker-unavailable`、W の満了、取消）は Graph なしで続くこと、送信の遅れ、到達の実測（上の表）を開示する。
