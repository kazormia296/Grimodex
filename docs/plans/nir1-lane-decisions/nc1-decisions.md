## threat model（確認済みの actor・防御・受信先・受入れの範囲内。新しいものを足さない）

- 信頼する: Main と Native、Chromium の network stack（版の範囲で。Electron 43.5.0／Chromium 150）、利用者。信頼しない: 乗っ取られた renderer（WebRTC の接続・名前解決・dns-prefetch で、攻撃者が選んだ宛先〔host 名、IP literal、loopback の任意 port、LAN〕へ接続・解決しようとする）。
- 範囲に入れない: 同じ OS ユーザーの別プロセス（listener の port を後から取りうる残余は FC-1 で開示済み）、QUIC・mDNS・TURN の relay candidate など行列の外（draft の「未確認と未検証」）、Windows／macOS（G-pub の範囲）。
- 必須の防御: 3 機構が独立に要る（proxy、`<-loopback>`、policy、rules。外した構成を対照で検出）、許可先 0（AL-0）と RS-1 の閉じた集合、LS-1 の上界と bytes の破棄、default session の最初の接触、fail-closed の起動失敗と固定コード、製品に無効化の入口を置かない、閉じた集合の静的な固定。
- LS-1 の listener 自体の脅威: renderer（Chromium 経由）が接続の洪水・RST・half-open・巨大な書込みで Main を落とす、または資源を使い切る。防御は、socket の `error` の握りつぶし、同時 256 以下、保持 5 秒以下、超過は受けた直後に切断、受けた bytes は `resume()` で読み捨てて検査・保存・log・書込みに渡さない、返事をしない。
- 受入れ: TASK の 5 の表（K3/3 の Positive (9)、Negative (23)(29)〜(33)）。
