この lane は、NIR-1 の残レーンの委任の外である。規則、脅威モデル、残る制限は、ユーザーが個別に確認した。下の判断は、確認された本文の範囲内の技術判断である。

## PR の分け方

1 つの PR にする。画面側の検査（`projectSnapshotAdapter`）、抽出の画面、試験、実機（Electron）の検査 1 本を含む。Native は変えない。

## 判断

| ID | 判断 | 理由 |
| -- | ---- | ---- |
| DR-SSE-1 | 検査の形は、本文を封印する要求（`buildProjectNarrativeSnapshot` の request）に足す任意の引数で選ぶ。指定が無ければ、今の「完全に一致」である。この引数は、抽出の対象の記録（`scope_json`）にも、抽出の仕様の digest にも入れない | S1、S3。対象の記録は 2 つのキーに固定で、Native は未知のキーを拒む。指定が途中で落ちても、今の厳しい検査に戻る（止まる側） |
| DR-SSE-2 | 「要求した場面だけ」の形の不変条件は、3 か所の検査で同じ関数を使う：要求した場面が、保存済みの木で、そのフォルダの直接の子の場面であること。フォルダから根までの祖先がすべてフォルダであること。行が読めること。エラーコードは、今の 3 か所のものをそのまま使う | S2。場面 1 つなので、順の検査は要らない。関数は、場面が複数でも成り立つ形（直接の子、木の順と同じ相対順）で書くが、製品から呼ぶのは場面 1 つだけである |
| DR-SSE-3 | その形では、行の読み込みと、外部ファイルの変更の待ち・照合（開始のときと、封印の後）は、要求した場面のファイルだけを対象にする。フォルダと、外部ファイルの取り込みの根は、対象に入れない。木の操作が落ち着くのを待つ処理は残す | S4。フォルダを対象に入れると、そのディレクトリの下の全ファイルが読み込んだ行に入っていることを求められ、兄弟の場面がある限り失敗する |
| DR-SSE-4 | 今ある試験「フォルダの一部の場面だけを要求すると拒む」は、既定の形の試験としてそのまま残す。新しい形の試験を足す。人物・設定の抽出の呼び出しは変えない | S3。既定の挙動が変わらないことの固定 |
| DR-SSE-5 | 抽出の画面は、今ある対象の選択（select）に「今の場面：〈題〉」の項目を 1 つ足す。選択の部品と「解析」のボタンは増やさない | S5。実機の検査 3 本と画面の試験が、選択の部品とボタンを 1 つと仮定している |
| DR-SSE-6 | 「今の場面」は、画面を開いた時点ではなく、項目を描くたびに今の値から導く。条件は、対象が場面であること、親がフォルダであること。満たさないときは、項目を選べない状態にして理由を出す | S6。開いている対象は、ノートや空のことがある |
| DR-SSE-7 | 本文の長さは、保存の後に、封印と同じ読み込みと正規化（外部ファイルの場面の切り替えを含む）で数える。0 字なら始めない。6,000 字を超えるときは、知らせを出して、もう一度の操作で始める | S7。画面がいま持つ本文は、空白の畳み方が違う |
| DR-SSE-8 | 前の組の知らせ（S8）は、画面に開いている組に未取り込みの提案が残っているときに出す。同じ場面の知らせ（S8b）は、その場面を根拠に持つ、承認済みで取り込んでいない提案があるときに出す。どちらも、知らせを出して、もう一度の操作で始める。判定は、今ある読み取りの範囲で行い、新しい IPC は足さない。足りない場合は、S8b の判定の範囲を記録して報告する | S8、S8b。新しい IPC は確認の範囲に無い |
| DR-SSE-9 | 再開の候補は、場面が 1 つの抽出のとき、木から題を引いて出す。破棄の後の選択は、その場面が今も選べるなら「今の場面」に、選べないなら未選択に戻す | S9 |
| DR-SSE-10 | 実機の検査は、新しい journey を 1 本足す（総数 35 → 36）。フォルダに場面が 2 つ以上ある形で、「今の場面」を選んで抽出し、承認、取り込み、再起動まで通す。承認した提案が IR の資格の判定を通ることを、Native の読み取りで確かめる。Full の資源の見積もりは、今ある年表の抽出の journey と同じ値を新しい id で足す | S10。フォルダにほかの場面がある形は、評価の記録では確かめていない |
| DR-SSE-11 | 範囲外：Native、抽出の形式、IR の資格の判定、材料の再生の条件、フォルダを選んで場面ごとに順に抽出する操作、組を選ぶ操作、フォルダに入っていない場面、抽出し直しのときの自動の取り下げ、「まとめて承認」 | 候補を小さく保つ |

## 信頼境界と影響

| 面 | 影響 |
| -- | ---- |
| 画面側の検査 | 年表の場面 1 つの抽出だけ、確かめる範囲が狭まる（フォルダのほかの場面、兄弟の側の木の整合、外部ファイルを取り込んだフォルダの未取り込みのファイル）。ほかの抽出は変わらない |
| 封印する本文 | 今と同じ経路で、要求した場面のものだけ |
| Native | 変わらない。Native は今も、フォルダと場面の関係を照合していない |
| 関連場面（IR） | 判定は変わらない。届く条件を満たす抽出（区切りが 1〜2）が、場面 1 つの抽出で作れるようになる |
| 人物・設定の抽出 | 変わらない |
| 評価の harness | 変わらない |

外部への送信、subprocess、背景の処理、非同期の lifecycle、保存先、IPC は変えない。

## 実装後の追記（2026-11-12）

上の判断と影響の表は、mutation の前の記録としてそのまま残す。確認済みの設計（改訂 3）の文面は変えない。実装と、実装と独立の受入れレビュー（候補に触らない read-only）で分かったことを、ここに足す。受入れレビューに P0 は無かった。P1 の 3 件は、下のとおり対応した。

| ID | 追記 |
| -- | ---- |
| 設計 §1 の訂正 | 前の組の review が画面から外れるのは、「新しい抽出を始めたとき」ではなく、「対象の選択を変えたとき」である（`handleSelectTarget` が `clearProjection()` を呼ぶ）。前の組の提案が残ること、後で画面に戻ることは、設計のとおりである。S8 の知らせに使う件数は、選択を変える直前に控える |
| DR-SSE-2 | 実装のとおり。要求した場面のうち条件を満たすものを木の順で返し、3 か所の今ある比較（欠落、順序、置き換え）が止める。新しいエラーコードは足していない。兄弟の並び順の重複は、既定の形では拒み、新しい形では通ることを、対の試験で固定した |
| DR-SSE-3 | 外部ファイルを取り込んだフォルダの中の場面 1 つを、兄弟のファイルがある状態で通す試験を足した。照合は本物を通し、ディスクの走査だけを偽にしている。フォルダと取り込みの根を対象に入れると失敗することも、比較として固定した。フォルダのディレクトリだけに起きた変更は待たない。その場合も、要求した場面のファイルの実在と内容の照合で止まる |
| DR-SSE-8 | 訂正：前の組の提案が残っているときの知らせ（S8）は、抽出を止めずに出す（始めるときに toast で出す）。mutation の前の記録の「知らせを出して、もう一度の操作で始める」は、S8 には当てはめない。理由：この知らせはフォルダの抽出でも出る。フォルダを続けて抽出する評価の準備の script（`setup-nir1-retrieval.mjs`、`setup-nir1-recovery.mjs`）が、2 件目で止まる。設計の「抽出は止めない」は、S8 では、確認の操作も挟まない意味に取る（S8b の「止めない」は、拒まない意味で、確認の操作は挟む）。長い場面の知らせ（S7）と、同じ場面の知らせ（S8b）は、場面の抽出でだけ出るので、知らせを出して、もう一度の操作で始める。フォルダの抽出は、どの場合も 1 回の操作で始まる（試験で固定） |
| DR-SSE-8 | S8 の文は、「承認済みで秘密の印を外した提案は、取り込まなくても関連場面に使われることがある」とした（使われるのは、場面の scope が設定されていて、問い合わせる場面が後ろにあるときである）。設計の S8 の「承認済みの提案は取り込まなくても関連場面に使われる」は言い過ぎである（提案は秘密の印つきで出て、印が付いている間は使われない） |
| DR-SSE-8 | S8b の判定の範囲：未取り込みの提案が残る抽出を、新しい順に 50 件まで見る。その場面を対象に含む抽出に、承認済みで取り込んでいない提案があれば知らせる。提案の根拠ではなく、抽出の対象の場面で判定するので、広めに知らせる側である。読み取りに失敗したときは、知らせを出さずに始める（知らせは補助で、安全の境界ではない）。新しい IPC は足していない。「解析」を押すたびに、対象の抽出ごとの読み取りが走る（場面の抽出のときだけ） |
| DR-SSE-9 | 対象の記録に抽出の種類は無いので、場面 1 つの抽出かどうかは、場面の列が 1 つであることで判定する。そのフォルダの下の場面が今もその 1 つだけなら、フォルダの抽出と区別できず、結果も同じなので、フォルダとして扱う（再開の候補の表示と、破棄の後の選択の両方） |
| DR-SSE-10 | 実機の検査は、3 番目の shard に入れた（2 → 3 件）。5 番目は 1 つ前の追加で 6 件になっている。準備で、project の scope の既定を、作成ダイアログの「本筋」と同じ値に、設定の画面と同じ更新の経路で設定する。検査用の project には既定が無く、そのままだと場面の scope が未設定で作られ、関連場面の判定が全部 `ScopeUnsupported` で止まるためである |
| DR-SSE-10 | 「承認した提案が IR の資格の判定を通る」は、判定（`read_revision_retrieval_eligibility`）が IPC に出ていないので、実機の検査の中では直接読めない。実機の検査は、判定が見る条件の一部（承認の記録、開示の scope、材料の再生の条件）を読んで確かめる。判定そのものは、実機の検査の後の DB に、診断の example（`nir1_retrieval_cold_oracle`）を当てて確かめた（手元で 1 回。CI には入らない）。結果：後ろの場面からの問い合わせで、secret を外して承認した版は Eligible、secret のままの版は `Secret`。抽出した場面自身からの問い合わせでは、secret を外した版は `SourceNotBeforeQuery` |
| DR-SSE-10 | 実機の検査は、抽出する場面をフォルダの先頭に置いた。開いている場面の前に兄弟があると、再起動で画面が落ちる不具合に当たるためである。原因はこの変更ではない（master で再現する。開いているタブがプレビューだけで、先頭以外の場面のときに起きる）。修正は別の作業で扱う。「前に兄弟がある場面」の再起動は、この検査では通していない |

**残したもの（この PR では変えない）。**

- 関連場面に届くのは、作者が開示の項目を編集して承認した版（secret を外した版）だけである。AI が出したままの版は、secret の印で止まる。場面の scope が未設定の project（取り込みで作った project、最初からある project）では、関連場面の判定は全部止まり、画面は scope の設定を案内する（今ある挙動）。
- 外部ファイルの変更の通知が残っている間の待ちは、試験で固定していない。外部ファイルを取り込んだフォルダの場面は、実機では通していない（単体の試験だけ）。
- S8b の読み取りは、抽出ごとに封印した本文を含む束を読む。大きい抽出が多いと重くなる。
- 評価の準備の script は、scope を設定しない。この PR では変えていない。
