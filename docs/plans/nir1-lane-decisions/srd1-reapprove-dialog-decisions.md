# 判断の記録：SRD/1 の RA7 のうち、年表の「AI 抽出」の画面の分（設計 §5 の 4 (b′)）

確認済みの行は、台帳 `docs/plans/nir1-l6-l9-execution-plan.md` の `nir1-chronicle-scene-review-apply-delta/1#chronicle-applied-proposal-redecide`（RA1〜RA7、確認 139）。表示とボタンを置くことは確認 79、この画面の「まとめて承認し直す」は確認 84 (a)、確認の文を挟まないことは確認 133 (5) でユーザーが選んだ。下の項目は、設計が「画面の PR で決める」とした起案者の読み（技術判断）。

## この PR の範囲

年表の「AI 抽出」の画面（既存のダイアログ）のカード・詳細欄・「まとめて承認し直す」と、開いたときと押した後の読み直し。場面の節の分（場面の節の画面は SRA/1 の画面の PR で作る）、作品全体の「全部」（置き場を決めてから）、復元の確認の件数（RD6）は、後の PR。

## DR-SRD-RA7-1　カードの出し方

- Native が `rejectedBy: "event-removed"` を返したカードは、「取り込み済み（再適用しません）」の代わりに「却下（出来事を消したため） — 〈外れた操作〉で外れました（〈時刻〉）」を出し、印は ☒ にする。
- その下に「承認し直す」を 1 つ出す。Native が押せないと言うときは、押せなくし、理由（RA2 の符号を作者の言葉にしたもの）を並べて出す。
- 読み直しが失敗して確かめられないカードは、「取り込み済み」とも「却下」とも言わず、「取り込んだ出来事の状態を確かめられませんでした」と出し、印は ? にする。ボタンは出さない。
- 承認・拒否・保留と、重複の選択肢は、今までどおり取り込み済みには出さない。
- 詳細欄の文も、同じ 3 つの状態で言い分ける。

## DR-SRD-RA7-2　「まとめて承認し直す」

- 置き場は、既にある「まとめて承認」のボタンの下の行（同じ見た目）。ラベルに押せる件数を付ける。確認の文は挟まない。
- 出来事を消して外れた提案が 1 件も無い画面では、ボタン自体を出さない（ほとんどの review に関係の無いボタンが並ばないように）。外れた提案はあるが押せる提案が 0 件なら、押せなくする。
- 対象は、その画面に出ていて、Native が押せると言う提案だけ。4,096 件を超えるときは分けて呼ぶ。「既に承認されている」は承認として数える。結果は、承認し直した件数と、飛ばした件数・主な理由を、まとめて承認と同じ形の注記で出す。

## DR-SRD-RA7-3　読み直し

- ダイアログを開いたとき、投影が残っていて scope が合う場合も、review bundle を 1 回読み直す（閉じている間に出来事が消えた・承認し直された分を拾う）。投影が無い場合は、今までどおり復元が bundle を読む。
- 承認し直した後は、押した場所に関わらず、この画面の review を読み直す。場面の節と作品全体の一覧は、この PR ではまだ画面が無いので、読み直す相手が無い。
- 読み直しの関数は、ダイアログが遅延で読む窓口（`extractEventsApi.ts`）に、既存の関数と同じ形で置いた。ダイアログから `chronicleExtractionApi` を直接、開いた時点で動的に読み込むと、試験の mock の差し替えより先に実物の module が読まれ、同じ場面の知らせの試験が崩れた（試験で確かめた）。

## DR-SRD-RA7-4　文言の置き場

日本語の文言は、コードの既定の文（`t(key, 既定の文)`）だけに置き、`ja.json` には足さない。`ja.json` は起動時に読まれ、足すと起動時の JS が約 1.9KB 増えて上限まで 379 byte になった（ローカルの値）。英語は `en.json`（遅延で読まれる）に足した。日本語の表示は、`ja.json` に足した場合と同じ。

## 残る制限

- ほかの窓で承認し直したり出来事を消したりした後は、この画面は、開き直すか承認し直すまで古いまま（設計 §3）。
- 場面の節・作品全体の「全部」・復元の確認の件数は、まだ無い。
