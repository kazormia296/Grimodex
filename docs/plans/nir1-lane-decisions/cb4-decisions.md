# CB-4 の委任判断の記録（mutation の前に記録。継続計画 §3.2 の形式）

出所の確認済み draft は K2/4（`docs/plans/nir1-c-body-disclosure-proposal-4-draft.md`。`graph-target-scene-body-disclosure` と `scope-storage-authority`。2026-10-17 の Session B2 で確認済み。K2-3 は取消の入口に grant を要さない）。この文書は S1（候補の走査と、本文を読まない判定。draft「利用時の判定」の手順 3）の mutation の前に書く。S2（本文の読取、`Eligible`、click 時の再検証）、S3（失効の全経路と出口の試験）、S4（統合）の判断は、実装の前に同じ形で追記する。DR-CB4-4（後半）、-5、-9（S2 の値）、-10〜-12 の S2 以降に当たる部分は設計の記録で、S1 の commit の時点では実装がない。S2 で変える場合は追記で理由を書く（後から本文を直さない）。

U3 の委任（継続計画 §3.1）の外に当たる要素は、この lane の範囲に無い。新しい受信先、保存範囲の拡大（schema、table、列）、確認済みの閾値の緩和、製品入口の公開、認可の削除、新しい authority のどれも置かない。固定されていて変えないもの：reader は read-only（宣言の 2 列、v1 の列、feed、idempotency、`tree_nodes` を書かない）。宣言の状態は行から読む（feed や cache から推定しない）。新しい IPC、preload、N-API、Main の route 台帳、gate、grant を足さない。入口は `native-current-human-capture` の feature の内側にだけ置き、MCP は有効にしない。宣言を非 NULL にする production の経路を足さない（試験は `#[cfg(test)]` の setter か CB-2 の writer を使う）。`scene_body_declaration_veto` の署名（DR-CB2-12）を変えない。

## owner/lifecycle matrix（GDX-PRECHECK-001）

不要。CB-4 は egress、subprocess、background、async lifecycle を変えない。reader は、既存の participant の read transaction の中で呼ばれる同期の関数で、thread、timer、cache、永続の記録、process-local の状態（診断 counter の件数を除く）を作らない。接続と participant の保持・放出は呼び出し側（CP-3a）が持つ既存の作法のままで、reader は `&Connection` を借りるだけである。取消と期限は呼び出し側の checkpoint を処理の境界で呼んで観測し、`Err` で伝える。診断 counter は理由の種別ごとの件数だけの process-local な `AtomicU64` で、target を識別する値を持たず、再起動で消える。

## threat model（GDX-PRECHECK-001 の security-sensitive。mutation の前に記録）

- 守るもの：Graph-only target の本文・title・excerpt（作者が宣言した Scene のものだけが、Related Scenes の共通追加 1 枠に出る）。
- 攻撃者と経路（draft の In-scope attacks の reader 側）：renderer の申告（rank、frame の token）／stale な frame／pin の移動・削除・再挿入／宣言の後の編集／restore・複製・ID の再利用／workspace の複写・移動／veto の後掛け／返却と click の間の TOCTOU／unavailable の理由・診断・cache を通じた漏えい／巨大な本文・title・宣言。
- S1 が受け持つ行（本文を読まない判定）：renderer の申告→reading rank と query の authority の revision は同じ live Scope authority の読取から導く（DR-CB4-7）。stale な frame・pin の移動→parent の読取と exact に比べ、`recheck_scene_pin` を通す（DR-CB4-4）。宣言の後の編集・複製・ID の再利用→束縛の不一致（DR-CB1-3 の token と workspace の値）。workspace の複写・移動→平文の workspace ID と canonical locator の digest の両方（DR-CB4-4）。veto の後掛け→毎回の記録の判定（DR-CB4-6）。unavailable の理由の漏えい→公開の型は理由を持たない `NotAppended` だけ（DR-CB4-3）。巨大な入力→allocation の前の検査と上限の超過は追加なし（DR-CB4-9）。quarantine→DB を読む前と候補の確定の前に見る（DR-CB4-4）。
- S1 の担当外：本文の digest・正規化の版・UTF-16 長の照合、`sceneBeat` の POV、excerpt（S2）。click 時の TOCTOU（S2、S3）。失効の全経路の試験と出口の試験（S3）。手順 1、2（B の seal と R+IR の path の再検証）と path の material binding の revalidate の実装（CP-3a。S1 は trait の seam だけ置く）。測定の workspace の照合（CP-4）。
- 経路ごとの試験名の対応表は、S1 の A／B 群の名前を DR-CB4-10 に、S2 以降の名前を各 subtask の追記に書く。
