## restricted の試走で FAIL した journey の原因（コードの読解。`st5/keep/run-restricted-results.tsv`）

- **chat 6 件**（`chat-authority-isolation`、`chat-stream-{folder,snippet,codex,project,workspace}-switch`）：prompt を送り、偽の provider の stream が返す `AUTHORITY-OLD-EARLY` が画面に出るのを待つ（`electron/scripts/product-journeys.mjs:1439`）。restricted では stream が始まらない。止まるのは 2 か所で、会話の無い scope では送信の途中の会話の自動作成（`createSession` の INSERT … RETURNING、D、`chatTurnStoreActions.ts:658` の経路）が汎用 SQL で拒否され、会話がある場合も AI の送信の route（外へ出す経路の台帳の行 1）が Main の gate で拒否される。どちらも D で、ST4-B は開けない（K3/2 のとおり FAIL のまま）。ST4-B の後は、拒否が生の marker でなく一般の失敗の文（`aiFailureToastText` → `aiFailureText`）で出る。
- **`cross-feature-authoring`**：Codex の文脈 pin の check を待つ（`product-journeys.mjs:4056`）。journey の scope に会話が無く、pin は `ensureSession`（`useChatPinsController.ts:267` → `createSession`、D）を要るので拒否され、pin が保存されない。既存の会話への pin は通る（K3/2「chat の書込みの入口」10）。
- **agent 2 件**（`agent-stream-{project,workspace}-switch`）：`ai_audit_events` の `chat_agent_main` の `request.prepared` を待つ（`product-journeys.mjs:880-899`。oracle の読取は O-2 で通る）。agent の送信は会話の作成（D）か agent の route（D、Main の gate）で拒否され、`request.prepared` を書く前に終わる。
- ST4-B で PASS に変わる見込みのものは無い（K3/2 の予想どおり）。ST5 の試走では、これらの journey の画面に生の marker や誤帰属が出ないことを記録する。
