## 未解決事項（PR 本文用の下書き。DI1B-4 で完成させる）

- 長い会話の上限：同じ chat session の attempt が 128 件を超えると、列挙を読み切れないので履歴なしになる（K4/3 §8 の「列挙を読み切れないときは履歴なし」。HC-1 の規則）。**失敗・取消・Review の attempt も数える**ので、会話の turn 数より早く超える。新しい会話で戻る。厳しくする側の値で、緩めるには再確認が要る。DD-1 の開示項目に載せる。
- window の規則（DR-DI1B-2a）：request に入れる history は、新しい turn から、親 attempt の参照行の合計が create の 8,192 行／8 MiB に収まる範囲（最大 16 turn）まで。Revision の多い turn が続く session では window が狭まる（102 Revision の turn が続くと4 turn）。DI1B-3 の packing がこの規則を実装する（`adoptable_turn_count`、`parent_read_cost_in_tx`）。create の ReadBudget と `create_parent_read_budget` の等値の断言は DI1B-4（Native 側）。
- envelope の外（全 turn が 30 Revision など）の長い session は、候補の除外か履歴なしになる（誤りではない）。
- SQL VM steps の余裕（envelope M' で 1.71 倍）は、実測の fixture の project の tree が小さいことへの余裕。期限（10 s）に対し envelope M' は debug・共有機で 5.6 s（1.8 倍）。大きな project の実測は DD-1 以降で取る。release build の実測は無い（debug の値）。
- 適格な Revision が約 34 件を超える project で Native 選択が常に失敗する件（DI-1c の DR-DI1C-1／DR-DI1C-13 の申し送り）は DI-1b では扱わない。
- DI-1 は 3 つの slice の受入れで合格する。DI-1b の merge だけでは合格にしない（DI-1a の受入れが別）。
- 製品入口は閉じたまま。`index.d.ts`、IPC、preload の差分は無い。
