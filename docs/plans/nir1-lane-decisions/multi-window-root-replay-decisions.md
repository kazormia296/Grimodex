この lane は、NIR-1 の残レーンの委任の外である。規則、脅威モデル、残る制限は、ユーザーが個別に確認した。下の判断は、確認された本文の範囲内の技術判断である。

## PR の分け方と止める点

- 1 つの PR にする（Native の再生、試験用のデータと正本、Native と画面側の試験、実機の検査と抽出の画面の直し）。
- **§5 の測定の結果をユーザーに見せるまで、merge しない。** 測定で上限が要ると分かった場合は、上限の数を案として伺ってから決める。
- 実装で、区切り 3 つ以上のデータを実際に通して、欠けている処理が見つかった場合は、実装を止めて報告する（設計の §8）。

## 判断

| ID | 判断 | 理由 |
| -- | ---- | ---- |
| DR-MW-1 | 数を限る検査（`material_roster/replay.rs` の、区切りの数が 1〜2 であること）を、「1 つ以上」に変える。区切りの数と計画の一致の検査は残す | M1 |
| DR-MW-2 | 区切りごとの材料（本文の範囲と文脈）と、観測の要求の照合は、抽出に固有で、提案に依らない。これを、1 回の読み取りの中で、抽出ごとに 1 回だけ作って使い回す。提案ごとに行うのは、必須の区切りの集合の決定、根拠と材料の照合、合成の要求の照合である | M6。区切りの材料と観測の要求の照合は、封印済みの本文、区切りの計画、受領書だけで決まる。将来、提案ごとの記録を絞っても、必須の区切りの集合が部分集合になるだけで、この使い回しは成り立つ |
| DR-MW-3 | 使い回す値は、今ある検証の記憶と同じ方針にする：成功した結果だけを覚える。失敗は覚えず、毎回確かめ直す。鍵に project と抽出を入れる。記憶の寿命は、今と同じく、1 回の読み取りの間だけである | 失敗を覚えると、直った後も通らない。今ある作りに合わせる |
| DR-MW-4 | 根拠の目録の検証と、本文の組み直しは、文書ごとに 1 回にする（今は、区切りと受領書の組ごと、目録の項目ごとにやり直す） | M6。長い 1 場面で、手間が区切りの数の 2 乗より急に増える原因である |
| DR-MW-5 | 「結果を変えない」の結果は、通るか通らないかと、材料の中身を指す。直しの前後で、区切り 1 つと 2 つの今の正本と試験が、同じ値で通ることを確かめる。不整合が 2 つ重なる入力で、先に報告される理由の種類は、変わりうる。変わった場合は、記録する | M6、設計の §9 |
| DR-MW-6 | 再生の形の名前（診断に出る）は、区切りの数を含まない名前を足す。区切り 1 つと 2 つの今の名前は変えない | 今の正本と診断の互換 |
| DR-MW-7 | 試験用のデータは、通常の抽出の経路で作った DB を固定する：1 場面が区切り 3 つ以上の形と、3 場面が区切り 1 つずつの形。区切りをまたいで観測がまとめられた出来事を含める。Native の正本と、画面側の独立の照合の正本を持つ。作り方を記録する | M7。今ある区切り 2 つの試験用のデータと同じ作り方にする |
| DR-MW-8 | 区切り 2 つの確認で必須とした 3 つの確かめ（材料の場面を後ろへ移した後の拒否、出せない材料を混ぜた対照との不変、変更後の候補での正式の検証）を、区切り 3 つ以上のデータで行う。閾値と分母は変えない | M7、設計の §4 |
| DR-MW-9 | 抽出の画面の「長い場面」の知らせ（種類 `long-scene`）を外す。本文の長さの測定と、空の場面で始めない規則は残す。実機の検査の「区切りが 1〜2」の確かめを、「1 つ以上」にする | M8、M7 |
| DR-MW-10 | 測定は、評価のデータの写し（区切り 3 つの抽出がある DB）と、区切りの数を増やした試験用のデータ（1 場面が区切り 3、8、16、32。場面の多いフォルダ）で行う。届く割合と理由の内訳、時間、記憶の最大値を出す。写しに対して行い、製品の DB と凍結した評価の材料は変えない | M6、設計の §5 |
| DR-MW-11 | 範囲外：修復が走った抽出と、同じ観測が重なった抽出の受け付け、提案ごとの記録を絞る変更、IR の資格と開示の判定、保存の形式、区切りの数の上限（測定の後に伺う） | 候補を小さく保つ |

## 信頼境界と影響

| 面 | 影響 |
| -- | ---- |
| 材料の再生 | 受け付ける抽出の形が広がる（区切り 3 つ以上）。検査の中身は同じである。必須の区切りの全部がそろわなければ、通さない |
| 材料 | 今と同じく、model が見た本文の全部。区切りが増えても縮めない |
| 関連場面（IR） | 判定は変わらない。資格を持つ提案が増える（長い場面、3 場面以上のフォルダ。既に保存されている提案を含む） |
| 検索の材料の作り直し | 時間と記憶が増えうる。処理を直したうえで測る |
| 抽出の画面 | 長い場面の知らせが無くなる |
| 評価 | 凍結した定義と Gold は変えない。製品のコードが変わるので、CP-4 の候補が変わる |

外部への送信、subprocess、保存先、IPC は変えない。

## 実装後の追記（2026-11-12）

上の判断と影響の表は、mutation の前の記録としてそのまま残す。確認済みの設計（改訂 3）の文面は変えない。実装、実装と独立のレビュー（候補に触らない read-only）、測定で分かったことを、ここに足す。レビューに P0 は無かった。P1（出せない材料を混ぜた対照の確かめが無い）は、下のとおり対応した。

| ID | 追記 |
| -- | ---- |
| DR-MW-2、DR-MW-3 | 実装のとおり。使い回す値は、1 回の読み取りの中の検証の記憶（`RunProofMemo`）に置いた。非同一の merge を含む抽出は、使い回しを通る経路でも、通らない経路でも、同じ理由で止まる（試験で固定） |
| DR-MW-8 | 3 つの確かめのうち、「材料の場面を後ろへ移した後の拒否」は、元の子・元の承認のままで `SourceNotBeforeQuery` になることを、区切り 3 つ以上のデータで固定した。「出せない材料を混ぜた対照との不変」は、検索の材料の束（候補の id、順、vector、文、根拠の場面と抜粋）が同じであることを固定した。混ぜたのは、元の DB では出る提案を、秘密のまま承認した形と、未承認の形にしたものである |
| DR-MW-8 | 残したもの：順位、点数、枠を出す段（`related_scenes/scoring.rs`）は、この試験では走らせていない。この段を試験から呼ぶには、問い合わせの値の構築子と、試験用のデータの準備を、crate の外へ公開する feature が要る。公開面を増やさないことを選んだ。この段は、材料の束だけから決まる（文書ごとの類似度、id での同点の順、言語ごとの下限と上限、場面の重複の除外）ので、束が同じなら結果も同じである。区切り 2 つの確認のときも、この段まで比べる試験は無かった。「変更後の候補での正式の検証」（製品の問い合わせでの比較）は、台帳のとおり未了のままである |
| DR-MW-10 | 測定の後、検索の材料の作り直しが、全部の提案の材料を同時に持つ作りを直した。同時に持つ理由は、通った提案の場面の鍵を集めて、scope を 1 回で読むことだけだった。提案ごとに、場面の鍵の列だけを残して、材料を放す。作り直しの結果（中身、順、digest）は変わらない |
| DR-MW-10 | 測定の値：1 場面が区切り 32、提案 416 件の形で、保持する量が 1,760MB から 102MB になった（区切り 16 で 440MB から 27MB、区切り 8 で 109MB から 7.9MB）。評価のデータの写し（区切りは 1〜3）では、最大の記憶が 321MB から 290MB、時間は 4.5 秒で同じだった。区切り 8 以上の値は、模した入力での保持量で、実際のデータでの作り直しの全体の値ではない |
| DR-MW-11 | 区切りの数の上限は付けない。ユーザーの判断（2026-11-12、上の測定の値と、区切り 8 以上の実際のデータの測定が無いことを見たうえで） |

**残る制限（設計のとおり。変えていない）。**

- 根拠の引用が 2 つ以上の場面にある提案は、関連場面に出ない（開示の scope が 1 つの場面を指すため）。観測が場面をまたいでも、根拠の引用が 1 つの場面に収まる提案は出る。
- 修復が走った抽出と、同じ観測が重なった抽出は、今と同じく出ない。
- フォルダの抽出の提案は、材料が抽出の全部の場面なので、最後の場面より後ろからしか見えない（DMS/1 で扱う）。
