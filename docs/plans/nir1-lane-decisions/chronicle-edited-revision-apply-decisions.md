## PR の分け方

- **PR-1（この記録の対象）**：Native の取り込みの検証と試験（E1〜E7）。
- **PR-2**：画面の案内の置き換え（E8）と、実機（Electron）の検査 1 本。PR-1 の後に出す。

PR-1 だけでは、製品の画面は編集した提案のある組の取り込みを開かない。PR #857 の案内が、取り込みのボタンを無効にしたままだからである。開くのは PR-2 である。

## 判断

| ID | 判断 | 理由と信頼境界 |
| -- | ---- | -------------- |
| DR-ERA-1 | `ensure_supported_intent` を、`revisionBasis.kind` が `interpretation` か `human-derived` で、`changeIntent.changeKind` が `add` であることの検査に改める（E1、E7）。それ以外は今と同じエラーで拒む | 変更の種類は広げない。版の種類がどちらでもないものは拒む |
| DR-ERA-2 | 取り込みの材料の読み込み（`load_v2_apply_sources_with_control`）を、版の種類で分ける。`human-derived` の版では、次の順に行う。(1) 系譜の検証（DR-ERA-3）。(2) 最初の AI の版の id と Envelope で、受領書の照合（`load_v2_context_artifact`）と、文脈と依存の対応の検査（`validate_coverage`）を行う。渡す材料は、最初の版自身の材料である。(3) 取り込む版自身の材料を、今の値と照合する。返す材料の行は、取り込む版のものである | E2〜E5。(2) は今の AI の版の取り込みと同じ検査で、AI の出力の裏付けを確かめる。(3) は、根拠の本文や scope が変わった後の版を拒む。編集した版の文脈の一覧には、取り込みで別の検査を掛けない。開示の項目を 2 回以上編集した版は、同じ id の文脈を 2 件以上持ち、今の検査をそのまま掛けると必ず拒まれるためである。編集した版の形は (1) が確かめる |
| DR-ERA-3 | 系譜の検証（`material_membership/lineage.rs` の `read`）を、取り込みから呼べる入口にする。最初の版の材料の再生（`read_root_material_with_memo`）は呼ばない | E2。関連場面の資格と同じ系譜の検証を使い、新しい緩い検証を作らない。再生は、区切りが 1〜2 でない抽出では未実装なので、取り込みの可否を再生に結び付けない。この点で、資格の検証と同じ強さではなく、今の AI の版の取り込みと同じ強さである |
| DR-ERA-4 | 系譜の検証が通らないときは、取り込みのエラーコード `NEX_V2_APPLY_LINEAGE_INVALID` で拒む。材料が今の値と合わないときは、今ある `NEX_READ_SET_STALE` のままにする | 系譜の検証のエラーには `NEX_` のコードが無い。画面側が原因を見分けられるようにする（PR-2 の案内に使う） |
| DR-ERA-5 | 承認の束縛、操作の組み立て直しの照合、出来事を secret で作る検査（CAS/1）は変えない | E6。編集した版にも同じに掛かる。組み立て直しは、取り込む版の payload と Envelope の根拠から行う |
| DR-ERA-6 | 試験：PR #858 の `current_limit_human_derived_revision_is_refused_by_chronicle_prepare` を、取り込みが通る試験に書き換える。関連場面の資格の試験を、本物の取り込みに置き換える。足す組は、題だけ直した版、secret を外した版、開示の項目を 2 回編集した版、reveal を別の場面に変えた版、取り消しとやり直し。負例は、系譜を崩した版、親の digest が合わない版、受領書の無い最初の版、根拠の本文が変わった版、場面の並びが変わった後の「secret のまま reveal を変えた版」、変更の種類が add でない版 | 下書きの §4 の受入れ。正例は出来事が secret で、題と reveal が編集後の値であることを見る。負例は取り込み全体が拒まれ、年表に出来事が作られないことを見る |
| DR-ERA-7 | 範囲外：受け付ける編集の項目の拡大、変更の種類の拡大、古い形式の抽出、IR 側の開示の判定、取り込みのときに scope を取り直す扱い、画面の案内と実機の検査（PR-2）、「まとめて承認」、場面 1 つの抽出 | 候補を小さく保つ |

## 影響の表（経路ごと）

| 経路 | 変わるか |
| ---- | -------- |
| AI が出したままの版の取り込み | 変わらない |
| 編集した版を含む組の取り込み（Native） | 変わる。通るようになる |
| 製品の画面からの、編集した版を含む組の取り込み | PR-1 では変わらない（PR #857 の案内が止める）。PR-2 で開く |
| 取り込みの取り消し、やり直し | 実装は変えない。編集した版から取り込んだ出来事で動くことを試験で確かめる |
| 取り込みの記録の依存 | 開示の項目を変えた版から取り込むと、scope の投影が 1 件加わる |
| 関連場面の資格と索引 | 変えない |
| 年表から AI への秘密、Graph の本文の開示の拒否 | 判定は変えない。出来事は secret で入る |
| 人物、伏線、プロットの取り込み | 変わらない |
| 評価の harness | 変わらない（取り込みを呼ばない） |

外部への送信、subprocess、背景の処理、非同期の lifecycle、保存先、IPC は変えない。
