## 2. #41（en の UI でも本文の宣言の確認ダイアログが日本語）
- 回答：選択肢を選ばず、「何ですかそれは？ローカライズのせられないんですか？」。
- 統合者の説明：表示文は Native が固定の allowlist から組み、文言全体の digest が grant の束縛に入る（DR-CB2-5）。allowlist は日本語の 1 組だけで、DR-CB2-5 は「言語の切替は必要になったときに足す」としていた。英語の allowlist を足し、言語を digest と束縛に含め、言語は renderer でなく Main が設定から決める形にすれば、束縛の仕組みを崩さずにローカライズできる。
- 扱い：**ローカライズを PUB-G の前提として実装する方向**で進める（統合者が設計を調べて PR にする。不要ならユーザーが止める）。「固定のまま開示」は採らない。送信先・保存範囲・閾値は変わらない。設計で新しい契約・authority に当たることが分かったら、実装の前に改めて伺う。
