## 2 回目の回答（side agent と advisor の指摘を受けて、範囲を絞って伺い直した）

前提として示したこと：同定の負荷の測定で材料が出るのは ★5 だけ（★4・★8 は参考値、★1・2・3・6・7 は方針の問いで数字では決まらない。事前登録 `preregistration-v1-draft.md` の冒頭の「目的」と §7.3 のとおり）。

| 問い | 回答 |
|---|---|
| 方針の問い（★1・2・3・6・7）をどうするか | **測定と並行で先に伺う**（推奨どおり。古くなった起案〔ADR 番号、schema の版、11-20 の方針転換〕を直してから、作者から見える場面の形で 1 回にまとめて伺う） |
| 測定の範囲（A＝AI なし・費用 0、B＝候補画面の AI 判定・候補の前後 50 字ほどと名簿を Anthropic へ・上限 $15、11-15 に止めたもの） | **A と B の両方**（推奨「A だけ先に」ではない）。B の送信先・保存・費用の上限は 11-14 の確認（事前登録 §15）のまま |
| M3 の持ち主 | **新しいセッション**（推奨どおり）。統合者は点検だけ |
| 委任を AGENTS.md に書くか | **引き継ぎ文書だけ**（推奨「docs の PR で足す」ではない）。AGENTS.md の「この委任は NIR-1 の残レーンの外には適用しない」は変えない。M3 の委任は M3 の引き継ぎ文書に書く |

## 帰結（統合者の読み）
- 11-15 の「測定 B は走らせない」は、2 回目の回答で解けた。
- M3 の PR は凍結の待ちの条件に入れない。PR の枠（全セッションで 2 本）は凍結を待つ lane を優先する。
- 凍結の後に M3 の製品の変更が入ると、評価した候補と公開の head がずれる。#15 の規則（次の S4 の正式 run を正とする）、最終 head の packaged smoke（#21）、C-1 の開示で、その差を扱う（`s4-change-list.md` §11）。
- これはユーザーの方向の決定で、ERM の契約（★1〜★8）・保存範囲・脅威モデルの承認ではない。それらは起案の後に個別に伺う。
