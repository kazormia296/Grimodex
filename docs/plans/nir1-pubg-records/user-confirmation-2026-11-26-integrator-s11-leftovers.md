  - 問 11 の「prompt の本文と tool の結果の本文は残しません」と食い違う。保存の中身（途中の AI の出力と tool の結果の本文、対象、再開のきっかけ、原稿が変わったときの扱い）は、事実を確かめた後に、改めてユーザーに伺う。それまで、問 11 の保存の範囲は広げない。
  - ADR 007 §4・§5 の追補と、脅威モデル（W12 など）の改訂が要る。新しい保存は、AI の出力と tool の結果の本文（作品の本文を含みうる）を会話の外に残すことになり、保存の範囲の拡大に当たる。
  - 担当は、表と型の PR を改訂まで止める。docs の PR も改訂の後に出す。
- 統合者の注：問 12 の上書きは、ユーザーの言葉で決まった方向。ただし、何を残すかの範囲は未確認。問 11 の承認（本文は残さない）を超える保存は、改めて伺うまで実装しない。

## 問 14〜17：A3 の範囲の拡張の保存の中身（11-27、A3 の担当 grimodex-59 のセッションの AskUserQuestion。統合者は直接見ておらず、担当が session の jsonl から jq で機械的に取り出した全文をそのまま写す。統合者が受け取ったのは 19:30）
- 問 14 残す中身（原文）：「途中から再開するために残す中身：事実として、今は turn が終わった後の本文と tool の要約しか残っていません。読み直しなしで続けるには、turn の途中の AI の出力と tool の結果の本文（作品の本文や Codex の抜粋を含む）を残すことになります。問 11 の「本文は残さない」を超えます。会話・作品の削除で消えます。hidden の項目は残しません。」
  - 「途中の会話を残し、指示文は組み直す (推奨)」：AI の途中の出力と tool の結果を残す。最初の指示文（system prompt と Codex の注入）は保存せず、再開のときに今の状態で組み直す。間に hidden にした項目は、送る前に外す。
  - 「指示文も含めて全部残す」：開始時の指示文まで保存し、そのまま送り直す。最も同じ状態に戻るが、Codex の本文を DB に複製する。hidden にした項目を外す処理は別に要る。
  - 「確認待ちの時点だけ残す」：質問や承認で止まった時点だけを保存する。生成の途中で落ちた実行は、今どおり中断のままにする。
  - 回答：「途中の会話を残し、指示文は組み直す (推奨)」
- 問 15 保持（原文）：「対象と保持の期間：事実として、CLI（Claude Code など）は provider 側に続きが無いので、途中からは再開できません。Codex App Server は、確定した turn の後からしか続けられません。再開の対象を API の経路の AI の実行にし、保存した状態はいつ消しますか。」
  - 「終わったら消す・中断は 30 日 (推奨)」：完了と Stop で消す。中断のまま再開されなかった実行は 30 日で消す。CLI と Codex App Server は今どおり中断にする。
  - 「終わったら消す・中断は期限なし」：完了と Stop で消す。中断の実行は、作者が捨てるまで残す。
  - 「終わっても残す」：完了の後も残す。後から読み返せるが、保存量は最も多い。
  - 回答：「終わったら消す・中断は期限なし」（推奨ではない）
- 問 16 きっかけ（原文）：「再開のきっかけ：再起動の後、中断した実行をいつ続けますか。続けると provider への送信と費用が発生します。」
  - 「作者が「続ける」を押したとき (推奨)」：起点の会話に「中断」と「続ける」ボタンを出す。確認待ちだった場合は、答えると続く。
  - 「起動時に自動で続ける」：操作なしで送信が始まる。費用と送信が作者の操作なしに起きる。
  - 回答：「作者が「続ける」を押したとき (推奨)」
- 問 17 原稿の変化（原文）：「中断の間に原稿や Codex が変わったとき：保存した tool の結果は古い内容のままです。どう扱いますか。」
  - 「変わった分だけ外して知らせる (推奨)」：変わった場面や項目の tool の結果だけを外し、AI に「中断の間に変わった」と伝える。AI は必要ならそこだけ読み直す。
  - 「古い結果のまま続ける」：読み直しは無いが、AI は古い内容で書き換えを提案しうる。書き換えの承認の時点で、版の検査（OCC）は今どおり効く。
  - 「変わっていたら続けない」：変化があれば再開せず、中断のままにする。
  - 回答：「変わった分だけ外して知らせる (推奨)」
- 効力：
  - 保存の範囲の拡大：turn の途中の AI の出力と、tool の結果の本文（作品の本文や Codex の抜粋を含みうる）を、会話の外に残すことを承認した。指示文（system prompt と Codex の注入）は残さず、再開のときに組み直す。hidden の項目は残さず、間に hidden にした項目は送る前に外す。会話・作品の削除で消える。問 11 の「本文は残さない」は、この範囲で置き換わる。
  - 対象は API の経路の AI の実行。CLI と Codex App Server は今どおり中断にする。
  - 保持：完了と Stop で消す。中断の実行は、作者が捨てるまで期限なしで残す（推奨の 30 日ではない）。担当は、中断の実行を破棄する操作を画面に用意する。
  - 再開は、作者が「続ける」を押したときだけ。起動時の自動の送信はしない。
  - 中断の間に変わった場面や項目の tool の結果は外し、AI に「中断の間に変わった」と伝える。
- 統合者の注：保持が期限なしなので、作者が中断の実行を消し忘れると、作品の本文の写しが残り続ける。破棄の操作の置き場所と文言は、画面の PR の前にユーザーに見せること。新しい authority（問 13）の advisor と Mastra の担当とのすり合わせは、この範囲を含めて行うこと。

## 問 18〜20：A3 の画面で見える挙動（11-27、A3 の担当 grimodex-59 のセッションの AskUserQuestion。統合者は直接見ておらず、担当が session の jsonl から jq で機械的に取り出した全文をそのまま写す。統合者が受け取ったのは 19:50）
- 問 18 hidden（原文）：「中断の間に hidden にした項目を、その実行が既に読んでいた場合。事実：tool の結果を外しても、その後の AI の文章や thinking に内容が写っていて、送り直すと AI に渡ります。どうしますか。」
  - 「続けられないとする (推奨)」：「非公開にした項目を読んでいたため続けられない」と出す。破棄して送り直す。hidden の内容が AI に渡らないことを確実にする。
  - 「読む前の切れ目まで戻す」：その項目を読む前の状態から続ける。切れ目ごとの履歴を保存するので、保存量が増える。その後の作業はやり直しになる。
  - 回答：「続けられないとする (推奨)」
- 問 19 backup（原文）：「backup と中断した実行。事実：自動の backup は DB 全体を写すので、何もしなければ途中の状態（作品の本文の写しを含む）も入り、作者が「破棄」しても backup には残ります。どうしますか。」
  - 「backup には入れない (推奨)」：写しから途中の状態を消す。backup から戻した中断の実行は「続けられない」になる。
  - 「backup にも入れる」：戻した後も続けられる。破棄しても、backup には本文の写しが残る。
  - 回答：「backup には入れない (推奨)」
- 問 20 新しい送信（原文）：「中断した実行がある会話で、新しく送る・再生成する・message を消すとき。事実：新しい turn の後に古い途中の状態を差し込むと、会話の順序が崩れます。どうしますか。」
  - 「確認してから破棄 (推奨)」：「中断した実行を破棄して進めますか」と確認を出す。進めると破棄し、やめれば何もしない。再表示した質問への入力は、送信でなく回答として扱う。
  - 「先に続けるか破棄を選ばせる」：中断した実行がある間は、送信欄を続けるか破棄の選択に置き換える。
  - 回答：「確認してから破棄 (推奨)」
- 効力（担当の報告で、第 3 版〔claude/a3-durable-agentrun の 338d9a217、受け取った時点で未 push〕の DR-A3-6・DR-A3-7 と同じ）：
  - 中断の間に hidden にした項目を、その実行が読んでいたら、続けられない。破棄して送り直す。
  - 自動の backup には、途中の状態を入れない。backup から戻した中断の実行は、続けられない。
  - 中断した実行がある会話で、新しく送る・再生成する・message を消すときは、確認を出してから破棄する。
- 担当の報告（第 3 版の要点）：Fable と 4 観点のレビューの指摘を入れた。main が provider の応答から tool の呼び出しの台帳を書く形にした（画面から受けた tool_use には権限を出さない）。Gate A の前は、実行中だった変更系の tool を再実行しない。
