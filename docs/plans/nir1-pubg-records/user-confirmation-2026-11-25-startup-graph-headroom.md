# ユーザー確認：起動時の JS の上限に一度だけ余裕を取る（2026-11-25 22:5x、grimodex-b1〔統合者〕のセッションで構造化質問）

## 問い（原文）
「起動時に読み込む JS の上限の扱いを伺います。上限の残りは毎回 10〜50 byte しかなく、10-25 のご指示（まず減らし、足りない分だけ別の commit で最小限に緩める）で、今夜は R1（+約 1.4KB）・R2（+650）と 2 回緩めました。さらに、M4 の PR-C（+30）と出力打ち切りの直し（+113）が、23 の R3（+32）と同じ残りを取り合っています。後から入る PR はそのたびに測り直しと緩和が要り、圧縮後の上限の残りも約 2.2KB です。どうしますか？」

## 選択肢（原文）
- 「今のまま PR ごとに」：10-25 の規則のまま。各 PR がまず減らし、足りない分だけ最小限に緩める。手間と順番待ちは続くが、上限は実際の増分にだけ追従する。
- 「一度だけ余裕を取る」：別の小さい PR で、raw と gzip の上限に一度だけ余裕（例：raw +2KB、gzip +2KB）を取る。以後の小さい増分は緩和なしで入る。増分の監視は今の gate と PR 本文で続ける。
- 「削る作業を先に回す」：起動時に要らない部品を遅延読み込みに移す専用の作業を先に回し、余裕を作ってから PR を入れる。上限は緩めないが、数時間〜1 日、他の PR が待つことがある。

## 回答
「一度だけ余裕を取る」

## 適用（統合者の読み）
- `scripts/check-performance-budgets.mjs` の `INITIAL_JS_GRAPH_BUDGET`：raw の allowance を +2,048、gzip の allowance を +2,048、absoluteMax をそれに合わせて上げる（選択肢の例の額）。独立の小さい PR で入れる。
- 以後も、各 PR は増分を PR 本文に書き、lazy 化できるものは先に lazy にする（10-25 の指示は残る）。余裕を使い切ったら、また伺う。
