**何を決める案か。** 年表の出来事の設定「AI に秘匿（ネタバレ防止）」（内部では events.secret）をやめる。出来事は、AI（アプリ内、外部の提供者、MCP）に全部渡す。守る印は、Codex の「AI から除外（hidden）」だけにする。「開示シーン」は残す。

**形**
1. 出来事を AI から隠す判定を、全部の経路から外す（N1）。
2. 画面から、チェック・「秘匿」のタグ・一覧の鍵を消す。「開示シーン」の欄は、全部の出来事に出す（N2）。
3. 残した「開示シーン」は、作者が選んだ出来事にだけ、CPL/1 の「読者にはまだ明かされていない」の印として AI に伝える。選ばなかった出来事（「自動（初出シーン）」）には、何も付けない（確認 98。N3）。
4. AI・MCP・画面・取り込みのどの入口からも、secret を書かない（N4、N6）。取り込みは、開示シーンも自動では入れない（確認 104。N6）。**提案カードからは、「開示の場面」の欄を外す**（確認 112。作者が、承認の前にカードで、開示の場面を変えられなくなる。N6 (e)）。
5. 列と既存の値は残す。製品の挙動に効く所は、稼働している経路で 2 か所、休眠の近似で 1 か所だけ残る（N5）。
6. MCP にも全部見せ、開示シーンの印も伝える（確認 101。N7）。場面 id を省略できる引数で、アプリ内と同じ判定を返す。
7. Codex で hidden の人物は、年表の返り値と自動のまとめの、全部の欄（参加者・主な人物・場所・人物の状況）から外す。出来事は渡す。**アプリ内の年表の道具では、場面ごとの切り替え（Phase）まで計算して、その場面で hidden の人物だけを外す**（確認 127。Codex の道具と同じ）。hidden の id で人物の年表を求められたら「見つからない」（存在しない id も同じ答えにして、hidden かどうかを見分けられないようにする。N8）。AI・MCP が参加者を置き換えるときは、見えていない hidden の参加者を残す（確認 100。N8）。
8. 実装と merge は進め、公開版に入れる前に測る（確認 99。N11）。

## 3. 残る制限

- **既に「AI に秘匿」を付けた出来事が、切り替えの時点から、知らせずに、AI に渡る（確認 95）。** 作者は、隠れていると思ったまま使い続けうる。知らせるのは、更新の説明（リリースノート）だけである。起動時の案内・件数の表示・記録の保存はしない。
- **「作中ではもう起きているが、読者にはまだ明かしていない」出来事（確認 94 の説明の言い方）を、構造で守る手段が無くなる。出来事ごとに AI から隠す手段が無い。** 開示シーンを選んだ出来事には、CPL/1 の実装で「読者にはまだ明かされていない」の印が付く。選ばなかった出来事には、何も付かない（確認 98）。印と指示は、AI が従うことを保証しない。守りは、AI が指示に従うかどうかと、応答の点検になる。**応答の点検はまだ無い**（別のハーネス。ADR 013 の D4）。**伏線の「AI に見せない」は、出来事の代わりにならない。** CSR/1 では変わらないが、確認 102 により、FSR/1 の実装の後は、未回収の伏線が全部 AI に渡る（例：作者が「先の伏線は『AI に見せない』で守れる」と読んでも、FSR/1 の後は、未回収の伏線の題と意図が AI に渡る）。粗い手段として、設定 → AI の「年表を AI に渡す」（`aiPrompt.chronicle.enabled`。プロジェクトスコープ、既定 ON。`CONTEXT_INJECTION.md` の「Chronicle 注入設定」）が残る。OFF にすると自動のまとめ全体が止まるが、`get_event_detail` などの道具は、全部の出来事を返す。
- **自動のまとめの枠を、これまで隠れていた出来事が取り合う。** 直近の出来事 8 件・背景 3 件・人物 10 人の枠（`chronicleSnapshot.ts:20-24`）は、変えない（変えると別の契約）。人物は直近 8 件から選ぶ（`:259-285`）ので、人物の欄も入れ替わる。因果は縮約の対象外で「常に全件」（`:590-626`）なので、増えると 600 トークンを超え、縮約が最後の段（直近 0 件・人物の詳細なし）まで進む。それでも超える分は、後段の `trimChronicleText` に任せる。例：作者が、現在地の直前に、秘匿の出来事を 8 件持つ。今は、その 8 件が隠れ、通常の出来事が直近 8 件を占める。切り替え後は、直近 8 件が全部元の秘匿の出来事になり、通常の出来事は 1 件も出ない。因果が 20 組あれば、直近の出来事の欄そのものが出なくなる（コードの読み。未実行）。
- **作中の時間の窓が、2 か所で成り立っていない（§1.2）。読む道具には、窓が無い。** 例：(1) 「真犯人の自白」（秘匿だった。結果側）を、「毒を盛る」（現在地以前。原因側）がつなぐ。第 1 章を書く場面で、「毒を盛る」から「いずれ『真犯人の自白』」という因果が、毎回 AI に渡る（今は関係ごと落ちて出ない。表示の形は例）。(2) 第 1 章の場面（現在地 none）で、スタンプの無い「ゾラクの死」（death。物語の最後）が、背景の先頭に出る。永久に隠すつもりで付けた、スタンプの無い出来事が、ここに入る。MCP の状態の道具も同じ。窓を足す変更は、CED/1・CPL/1 の範囲で、この案は足さない。
- **読む道具の返り値が大きくなる。** `list_events` と `get_character_timeline` に、件数の上限もページ送りも無い（core の `chronicleTools.ts:117-155`・`:258-325`。PR-7a の merge の前は `chronicleReadTools.ts`。§1.2）。これまで隠れていた出来事が、全部、一覧に出る。例：取り込みで 300 件の出来事ができた作品で `list_events` を呼ぶと、300 件が 1 回の返り値に出る（今は 0 件）。上限・ページ送りは別の契約なので、この案は足さない（返り値を切り詰める別の層があるかは未確認）。
- MCP の向こうの AI にも見える。書き換え・削除もできる（確認 96。AWA/1 の H2 の範囲）。開示シーンを選んだ出来事には、印が付く（確認 101。N7）。**一覧・詳細・人物の年表は、場面 id（`scene_id`）を省略できる引数で受け、渡されたときは、アプリ内と同じ判定を返す。`get_chronicle_state` も同じ。** 渡されなかったときは、`revealScene` の値と注記だけを返し、「同じ印」より弱くなる。例：外部の AI が、`scene_id` を付けずに `list_events` を呼ぶと、`revealScene` = S5 の出来事が返るが、今書いているのが S3 か S6 かを、道具は知らない。AI が注記を読まず、S3 を書きながら S5 の出来事を使えば、「まだ書いてはいけない」と分からないまま、先の展開を書きうる。`scene_id` を渡すかは、外部の AI と、その指示に任せる（道具の説明に書く）。
- 題・メモの文中の、hidden の人物の名前は、そのまま渡る（確認 97）。検索の索引は、参加者の名前を埋め込むので、名前を当てて検索すると、その出来事が出る（出来事は渡す決定のため、新しい漏れではない）。
