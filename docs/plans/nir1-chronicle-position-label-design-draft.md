## 0. 一枚目

**何を決める案か。** AI に年表の出来事を渡すとき、今書いている場面から見て「これまで」の出来事か、「これから」の出来事かを、区別して渡す。あわせて、今の場面の作中の日時と、視点の人物を、はっきり渡す。

**なぜ要るか。**
- SRA/1 で、承認した出来事を、秘密の印なしで年表に入れることになった。位置で絞ることはしない。絞らない代わりに、前後の区別を渡す。
- 承認して入れた出来事は、作中の日時が無く、年表の並びの末尾に入る。今の作りのままだと、その出来事が結び付いた場面で、「作中の現在地」が年表の末尾に寄る。手書きの先の出来事までが「これまで」として自動で渡り、人物の生死・年齢も「不明」になる。
- 今の製品にも、食い違いがある。年表の画面は出来事を日時で並べるが、AI 向けの前後の判定は、年表の並び（作った順）を使う。後から過去の出来事を足すと、先の出来事が「これまで」に入る。

**形**
1. 日時のある出来事の前後は、作中の日時で比べる。日時が無いときだけ、年表の並びで比べる。
2. 作中の日時が無く、確度が不明の出来事（承認して入れた出来事は、必ずこの形）は、「作中の現在地」を決める材料にしない。前後は、結び付いた場面の読む順で決める。
3. 自動のまとめの「これまで」は、この判定で選ぶ。見出しを「これまでの主な出来事」にする。
4. AI が道具で引く出来事の一覧・詳細・検索は、出来事を除かない。1 件ずつ、「これまで／今の場面／これから／不明」の印を付ける。
5. 今の場面の作中の日時が決まらないときは、「未確定」と書く。
6. 場面に設定した視点の人物を、「この場面の視点」として渡す。
7. 自動のまとめに「これからの出来事」の欄を足すかは、小さな測定の結果を見てから決める。

**変えないこと**
- 作者が付ける印（Codex の hidden、年表の出来事の秘密の印）の判定は変えない。位置の印は、その判定の後に付ける。
- 自動のまとめの「未回収の因果」と「本文未描写の背景」の中身の考え方は変えない。
- 今回は、場面ごとの時制の設定を足さない。現実の今日の日付は、渡さない。
- MCP の出来事の一覧には、位置の印を付けない（公開の後に、別に起案する）。

### 1.1 ユーザーの決定（2026-11-22）

2. 「『これまで』と『これから』を区別し、また今の日時、時制、等を渡す必要が有るかもしれません」（発言の原文）。

## 2. 規則

### 2.1 位置の判定（P1〜P8）

- **P1　出来事を 2 種類に分ける。** 「読む順で決める出来事」は、作中の日時（開始の日時）が無く、確度が「不明」の出来事である。確度の値が欠けているときは、「正確」として扱う。承認して入れた出来事は、必ずこの種類になる。作者が、日時の無い手書きの出来事の確度を「不明」にした場合も、この種類になる。「年表で決める出来事」は、それ以外である。
- **P2　位置は 4 つである。** 「これまで」「今の場面」「これから」「不明」。今の場面に結び付いた出来事は、どちらの種類でも、「今の場面」である。
- **P3　「作中の現在地」の材料。** 読む順で決める出来事は、現在地を決める材料にしない。場面ごとの材料からも、借りる先の候補からも、除く。借りる先は、除いた後に現在地を持つ、手前で最も近い場面である。結び付きの全体は、P6 のために、別に持つ。
- **P4　結び付いた出来事から現在地を決めるとき。** 場面に作中日付が無く、結び付いた「年表で決める出来事」から決める場合は、次の順にする。日時のある出来事があれば、日時が最も後のもの。無ければ、年表の並びが最も後のもの（今と同じ）。
- **P5　年表で決める出来事の位置。** 今の場面に結び付かないものは、次の順で決める。
  1. 現在地が決まらない場面では、「不明」。
  2. 現在地と出来事の両方に、作中の日時があれば、日時で比べる。現在地の日時以前なら「これまで」、後なら「これから」。
  3. それ以外は、年表の並びで比べる（今と同じ）。現在地の並び以前なら「これまで」、後なら「これから」。場面の作中日付が、どの出来事よりも前のときは、全部「これから」である。
- **P6　読む順で決める出来事の位置。** 今の場面に結び付かないものは、結び付いた場面のうち、読む順に在るものだけを見て、次の順で決める。
  1. 今の場面が無いか、読む順に無ければ、「不明」。
  2. 読む順に在る結び付きが 1 つも無ければ、「不明」。
  3. 全部が今の場面より前なら、「これまで」。
  4. 1 つでも今の場面より後なら、「これから」。手前の場面にも結び付きがあるときは、そのことを根拠に添える。
- **P7　根拠を添える。** 位置には、何で決めたかを添える。「作中の日時」「年表の並び」「読む順」のどれかである。読む順は、描かれた順であって、作中の順ではない。回想の場面では、食い違うことがある。
- **P8　判定の置き場。** 判定は、1 つの関数に置く。チャットの IR に依存しない、新しい module に置く。自動のまとめの 5 か所（これまでの出来事、人物の所在、未回収の因果、本文未描写の背景、人物の選び方）と、道具が、同じ関数を使う。MCP 側（Rust）は、同じ規則を持つ。秘密の印を持たない入力について、共有の例（fixture）で、画面側と一致することを示す。MCP 側の読む順の作り方を、画面側に合わせる（保管済みの場面を外す。同じ順位は id で決める）。

### 2.2 自動のまとめ（M1〜M8）

- **M1　これまでの主な出来事。** 位置が「これまで」か「今の場面」の出来事を入れる。件数の上限（8 件）は変えない。並べる順は、今の場面に結び付く出来事、年表で決める出来事（現在地に近い順）、読む順で決める出来事（結び付いた場面が今の場面に近い順）である。年表で決める出来事と、読む順で決める出来事に、4 件ずつを確保し、余りは他方へ回す。読む順で決める出来事の行には、読む順で決めたことを短く添える。
- **M2　未回収の因果。** 原因が「これまで」か「今の場面」で、結果が「これから」の組を出す。今と同じ考え方で、判定だけを P5・P6 に通す。結果の側の題は、今までどおり出る。
- **M3　本文未描写の背景。** 場面に結び付かない出来事を、今までどおり入れる。現在地が決まる場面では「これまで」のもの、決まらない場面では前後に関係なく、最大 3 件である。
- **M4　人物の状況。** 生死・年齢は、現在地の日時から導く。所在と、載せる人物の選び方は、位置が「これまで」か「今の場面」の出来事から導く。所在は、年表で決める出来事から取る。年表で決める出来事に所在が無いときだけ、読む順で決める出来事のうち、結び付いた場面が今の場面に最も近いものから取る。
- **M5　見出しと導入の文。** 見出し「直近の出来事」を、「これまでの主な出来事」にする。導入の文に、次の趣旨を足す。「ここに並べた出来事は、件数の上限で選んだ一部である。ここに無い出来事が、起きていないとは限らない。」日本語と英語の両方を直す。
- **M6　作中の日時。** 現在地が決まらない場面では、「作中時刻: 未確定」と書く。書くのは、まとめにほかの行が 1 つでもあるときだけである。ほかに何も無ければ、今までどおり、まとめを出さない。手前の場面から借りたときは、今までどおり、推定であることを書く。
- **M7　縮約。** まとめの大きさの上限は変えない。削る順は、本文未描写の背景、読む順で決める出来事、メモ、相対時間の順にする。
- **M8　「これからの出来事」の欄。** 入れるかどうか、件数、添える指示の文は、測定（§5.2）の結果を見せてから、ユーザーが決める。それまで、master には入れない。測定に使う形は、次のとおりである。位置が「これから」の出来事を、今の場面に近い順に、最大 4 件。秘密の印のある出来事は、開示の後でも入れない。「今の場面では、まだ起きていない（または、まだ描かれていない）。起きたこととして書かない」という指示を添える。縮約では、本文未描写の背景の次に削る。

### 2.3 道具（T1〜T6）

- **T1　範囲。** 出来事の一覧・詳細・検索に、位置の印を付ける（決定 3）。人物の年表と、場面を指定して年表の状況を読む道具にも、同じ判定で付ける（起案者の追加。◆2 で確認する）。
- **T2　印。** 出来事は除かない（SRA/1 の決定 12）。出来事 1 件ずつに、位置（P2）と根拠（P7）を足す。検索の道具の中の、止めてある位置の絞りは、この案では使わない。
- **T3　基準の場面。** 位置の印の基準は、道具を呼んだ時点で開いている場面である。場面を指定して読む道具は、渡された場面を基準にする。場面が開いていなければ、全部「不明」になる（P5・P6）。
- **T4　今の場面の情報。** 一覧・詳細・人物の年表の返り値に、基準の場面の題と id、作中の日時、現在地の出どころ（場面の日付・結び付いた出来事・手前の場面からの推定・未確定）を足す。検索の返り値は並びのままにし、1 件ずつの位置だけを足す。
- **T5　位置の読み方。** 「『これから』の出来事は、今の場面ではまだ起きていないものとして扱う」などの読み方を、道具の説明に書く（`electron/shared/agentReadToolDefinitions.ts`）。自動のまとめが省かれる発言や、調べもの用の補助の AI にも、届くようにするためである。
- **T6　入れる順番。** 道具の作り直しを待たずに、今の道具へ先に入れる（§1.4、§5.1）。

### 2.4 視点・日時・時制（V1〜V4）

- **V1**　チャットの場面の文脈に、場面に設定した視点の人物の名前を、「この場面の視点」として足す。設定が無ければ、何も書かない。
- **V2**　視点の人物の Codex の項目が、今の場面の時点で hidden なら、渡さない。項目が Codex に無いときも、渡さない（ADR 013 の D2）。
- **V3**　場面ごとの時制の設定欄は、今回は足さない。先に、作中の日時（M6・T4）と位置の区別を入れ、場面ごとの時制がなお要るかを見る。要ると分かれば、保存する値が増えるので、別の起案で確認する。作品全体の時制と視点の設定は、今までどおり渡す。
- **V4**　現実の今日の日付は、渡さない。

### 2.5 MCP（X1〜X2）

- **X1**　場面を指定して読む道具（`get_chronicle_state`）は、P1〜P8 と M1〜M4 を、画面側と同じにする。
- **X2**　一覧・詳細・人物の年表への位置の印は、この案に含めない（決定 7）。それまで、MCP の一覧は、区別なしで渡る。

## 3. 残る制限

- 読む順の根拠は、描かれた順である。回想の場面に結び付いた出来事は、作中では過去でも、「これから」と付くことがある。根拠を添えるのは、そのためである。回想の場面を書いているときの現在地は、今と同じく、手前の場面から借りる。回想の時点とは合わないことがある。
- 承認して入れた出来事は、年表の画面では、日付の範囲の後ろに、仮に置かれる。作者が日時を入れると、画面の位置が決まり、AI 向けの判定も、日時で比べる形に移る（P1・P5）。
- 作者が、日時を入れず、確度を「不明」にした手書きの出来事は、承認して入れた出来事と同じ扱いになる。年表の並びだけで運用している作品で、全部の出来事を「不明」にしていると、現在地が決まらなくなり、人物の状況が出なくなる。
- この案は、前後の判定の側を直す。保存してある年表の並びは、書き換えない。そのため、日時の無い出来事どうしの順は、作った順のままである。年表の画面に、並べ替える操作も無い。日時のある出来事と、無い出来事の前後は、今までどおり、年表の並びで決まる。日時を入れたときに年表の並びも合わせる形（データの側で直す）と、並べ替える操作は、既にある値を書き換える移行が要るので、公開の後に、別に起案する（2026-11-22 に、ユーザーへ推奨として伝えた）。
- 日時で比べる変更（P4・P5）は、手書きの出来事にも及ぶ。日時と年表の並びが食い違っている作品では、今と違う出来事が「これまで」に入る。向きは、画面の並びに合う方である。
- AI と MCP が作る出来事は、年表の並びの先頭に置かれる。日時が無ければ、現在地を先頭に寄せる。この案では直らない。別に起案する。
- MCP の一覧は、区別なしで渡る（X2）。
- 道具の位置の印は、道具を呼んだ時点で開いている場面に対するものである。発言の途中で場面を切り替えると、基準が変わる。
- 位置の印は、AI への手がかりである。AI が印を無視して、先の出来事を書くことは、防げない。

## 5. 順番

### 5.1 PR の列

1. **位置の判定、現在地の直し、自動のまとめ**（P1〜P8、M1〜M7、X1）。1 本の PR にする。現在地の直しだけを先に入れると、承認して入れた出来事や、確度が不明の手書きの出来事が、自動のまとめから外れる期間ができる。画面側 `src/features/chronicle/` の新しい module・`resolveSceneAnchor.ts`・`chronicleSnapshot.ts`、文言（日本語・英語）、MCP 側 `chronicle_snapshot.rs` と読む順の作り方、共有の例。道具の作り直しの lane が、年表のまとめの file を共有の場所へ移す前に、merge する。PR を開いたら、その lane の担当に番号を知らせる。
2. **視点の人物**（V1・V2）。ほかと独立である。
3. **道具の返り値と説明**（T1〜T5）。今の道具（`chronicleReadTools.ts` と検索の道具）と、道具の説明の正本に入れる。固定した期待値（返り値 5 本、説明を変えるので定義 4 本）を作り直し、差分を PR の本文に載せる。
4. **「これからの出来事」の欄**（M8）。測定と、ユーザーの決定の後である。

SRA/1 と合わせた全体の列は、SRA/1 の §6 に置く。取り込みの既定を開けるのは、この案の 1 と 3 が master に入った後にする。

AI への指示を変える PR は、品質の検査の手順（`grimodex-author`、`grimodex-impact-gate`）を通す。年表のまとめの file と、新しい module を、検査の対象の一覧に足す。

### 5.2 「これから」の欄の測定

決定 6 による。ADR 013 の J5 は、次の形を置いている。未開示の項目を数個持つ場面で、(i) 項目を除く、(ii) 印つきで渡して「本文では明かさない」と指示する、(iii) 印なしで渡す、の 3 つを比べ、明示の漏れ・伏線としての利用・後の事実との矛盾を数える。生成は、製品の送信をそのまま使う必要が無い限り、補助の AI（subagent）で行う。API を使う場合の総額は、別に伺う。【読んだ（ADR 013 の J5）】

この案の測定は、この形を年表の「これからの出来事」に当てる。題材、場面の数、比べる条件、数え方、費用の見込みは、始める前に、別の文書でユーザーに見せる。凍結済みの評価の題材は使わない。

## 7. 未確認と限界

- この文書の【報告】は、2026-11-22 の read-only の調査と点検の結果である。起案者は、該当の行を読んでいない。実装の前に、基点のコードで読み直す。結果は、repo の外の `design-notes/editor-scene-interpretation-2026-11-21/wf12.json`〜`wf14.json` にある。
- どの挙動も、実行して確かめていない。§1.2 の食い違い（後から過去の出来事を足すと、先の出来事が「これまで」に入る）は、実装のとき、先に試験で再現する。
- 日時で比べる変更（P4・P5）で、今の共有の例 6 本の期待値がどう変わるかは、確かめていない。
- 日時の比べ方の細部（期間のある出来事の終わりの日時、分の単位、確度が「おおよそ」の出来事）は、決めていない。実装のとき、今の「相対時間」の計算と同じ扱いにそろえる。
- 現在地が、手前の場面から借りたものであるとき、借りた先の出来事と「今の場面」の関係の書き方は、文言として詰めていない。
- 件数の配分（M1 の 4 件ずつ）の良し悪しは、測っていない。
- 場面の視点の人物の項目が hidden かどうかを、場面の文脈を組み立てる箇所で引けることは、点検の報告による。
- 作品全体の時制の設定は、日本語の画面でも英語のまま（`Past tense` など）渡っている、と調査が報告した。この案の範囲外だが、別件として直す価値がある。
