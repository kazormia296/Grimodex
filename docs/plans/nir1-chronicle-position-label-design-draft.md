用語：「作中の現在地」は、今書いている場面が、作中のいつに当たるかを表す値である（コードでは anchor）。「年表の並び」は、年表の出来事の順番である（コードでは ordinal）。「読む順」は、原稿の場面の並びである。「道具」は、チャットの AI が自分で呼び出して年表を読む仕組みである（tool）。

## 0. 一枚目

**何を決める案か。** AI に年表の出来事を渡すとき、今書いている場面から見て「これまで」の出来事か、「これから」の出来事かを、区別して渡す。あわせて、今の場面の作中の日時と、視点の人物を、はっきり渡す。

**なぜ要るか。**
- SRA/1 で、承認した出来事を、秘密の印なしで年表に入れることになった。位置で絞ることはしない。絞らない代わりに、前後の区別を渡す。
- 承認して入れた出来事は、作中の日時が無く、年表の末尾に、取り込んだ順で並ぶ。今の作りのままだと、その出来事が結び付いた場面で、「作中の現在地」が年表の末尾に寄る。すると、手書きの先の出来事までが「これまで」として自動で渡り、人物の生死・年齢も「不明」になる。

**形**
1. 作中の日時が無く、確度が不明の出来事は、「作中の現在地」を決める材料にしない。承認して入れた出来事は、必ずこの形である。
2. その種類の出来事の前後は、年表の並びではなく、結び付いた場面の読む順で決める。
3. チャットに自動で入る年表のまとめは、「これまで」と「今の場面」の出来事だけを入れる。見出しを「これまでの出来事」にする。
4. AI が道具で引く出来事の一覧・詳細・人物の年表・検索は、出来事を除かない。1 件ずつ、「これまで／今の場面／これから／不明」の印を付ける。
5. 今の場面の作中の日時が決まらないときは、「未確定」と書く。
6. 場面に設定した視点の人物を、「この場面の視点」として渡す。

**変えないこと**
- 作者が付ける印（Codex の hidden、年表の出来事の秘密の印）の判定は変えない。位置の印は、その判定の後に付ける。
- 自動のまとめに、「これから」の出来事は入れない。入れる場合は、ADR 013 の J4 (b) に当たり、別に確認する。
- 場面ごとの時制の設定は、足さない。現実の今日の日付は、渡さない。

## 1. 確かめた事実

### 1.1 ユーザーの決定（2026-11-22）

1. 承認して年表に入れた出来事に、秘密の印を付けない。位置の絞りは足さない（SRA/1 の決定 11・12）。
2. 「『これまで』と『これから』を区別し、また今の日時、時制、等を渡す必要が有るかもしれません」（発言の原文）。
3. 位置の区別は、「道具の一覧にも公開の前に入れる」。選択肢の説明は、次のとおりだった。自動のまとめを直すことに加えて、道具で引く一覧・詳細・検索にも、1 件ずつ「これまで／これから／不明」の印を付ける。道具を作り直している別の作業と同じ場所を触るので、調整と、固定してある期待値の作り直しが要る。
4. 日時と時制は、「作中の日時をはっきり書く」「場面の視点の人物を渡す」「場面ごとの時制を渡す」を選び、「場面ごとの時制はシーンの作中日時がはっきりすれば渡さなくてもなんとかなるかも？分からないですが」と添えた。「現実の今日の日付を渡す」は選ばなかった。
5. ADR 013 の「送る量を増やす変更は測定の後」は、SRA/1 の変更には当てない（測定を待たない）。

起案者の読み：決定 4 の「場面ごとの時制」は、新しい設定欄を足さずに始め、作中の日時と位置の区別を入れた後に、要るかを見る（V3）。違っていれば、◆1 で指摘いただく。

### 1.2 今、AI に渡しているもの

- 自動のまとめは、年表の並びが「作中の現在地」以前の出来事を、現在地に近い順に入れる。【確認済み（`src/features/chronicle/chronicleSnapshot.ts:186-201`）】場面に結び付かない出来事は、現在地が決まらないとき、前後に関係なく入れる。【確認済み（同 `:226-246`）】件数の上限は 8 件と 3 件である。【報告】
- まとめの導入の文は、「現在のシーンの作中時刻における作品世界の状況」と述べ、「未来の出来事への言及を避ける手がかりにしてください」と指示する。「これまで」「これから」という語は無い。【確認済み（`src/prompts/ja/chatSystem.ts:178-184`）】
- 現在地が決まらない場面では、作中の時刻の行を出さない。【報告】
- 道具の出来事の一覧は、id、題、種類、年表の並び、作中の日時、主な人物を返す。今の場面から見た前後を示す値は無い。今の場面の情報も返さない。【確認済み（`src/features/chat/agent/chronicleReadTools.ts:100-138`）】詳細・人物の年表・検索も同じである。【報告】
- 読む順で前後を決める部品は、既にある。結び付いた場面のうち、読む順で最も手前のものが、今の場面以前かを返す。検索の道具の中で、定数によって止めてある。【確認済み（`src/features/chronicle/chronicleReadingPosition.ts:27-47`）。止めてあることは【報告】】
- 時制と視点は、作品全体の設定（過去形／現在形、一人称／三人称など）を渡している。場面に設定した視点の人物は、「この場面の視点」としては渡していない。場面ごとの時制の設定は、製品に無い。現実の日付は、渡していない。【報告】
- MCP は、場面の位置を持たない。場面を指定して読む道具（`get_chronicle_state`）だけが、自動のまとめと同じ処理をする。【報告】

### 1.3 承認して入れた出来事と、「作中の現在地」

- 「作中の現在地」は、次の順で決まる。場面に作中日付があれば、その日付。無ければ、その場面に結び付いた出来事のうち、年表の並びが最も後ろのもの。それも無ければ、読む順で手前の、最も近い場面の現在地を借りる。【確認済み（`src/features/chronicle/resolveSceneAnchor.ts:123-176`）】
- 承認して入れた出来事は、年表の末尾に追記される。【確認済み（`commit.rs:3129-3139`、`compiler.ts:118-127`）】作中の日時は入らず、確度は「不明」で、根拠の場面に結び付く。【確度は確認済み（同じ箇所の `precision: "unknown"`）。日時と結び付きは報告】
- したがって、作中日付の無い場面に、承認して入れた出来事が結び付くと、その場面の現在地が年表の末尾に寄る。読む順でその後ろにある、作中日付の無い場面も、同じ現在地を借りる。手書きの先の出来事が「これまで」に入る。現在地が日時を持たなくなるので、人物の生死・年齢が「不明」になり、「約 2 年前」のような表示も消える。【報告。場面 5 つ・手書き 4 つ・取り込み 2 件の例を、調査が手で追った】
- これは、秘密の印の有無と関係がない。印があっても、根拠の場面以降では同じである。今は年表への取り込みが閉じているので、起きていない。【報告】
- MCP 側の同じ処理（Rust）でも起きる。【報告】
- 年表の画面に、出来事を並べ替える操作は無い。手書きの出来事も、作った順に末尾へ足される。位置を変える手段は、作中の日時を入れることである。【報告】
- 承認して入れた出来事を、ほかと見分ける列は、保存の形（schema）に無い。「作中の日時が無い・確度が不明・種類が一般」の 3 つで見分けられる。手書きの出来事の確度の既定は「正確」なので、ふつうは当たらない。【報告】

## 2. 規則

### 2.1 位置の判定（P1〜P6）

- **P1**　作中の日時が無く、確度が不明の出来事は、「作中の現在地」を決める材料にしない。場面に結び付いた出来事から選ぶときも、手前の場面から借りるときも、同じである。
- **P2**　出来事 1 件の位置は、4 つのどれかである。「これまで」「今の場面」「これから」「不明」。
- **P3**　P1 に当たらない出来事（手書きの、日時か並びで位置の決まる出来事）は、今までどおり、年表の並びを現在地と比べる。現在地以前なら「これまで」、現在地そのものなら「今の場面」、後なら「これから」である。現在地が決まらない場面では、「不明」である。
- **P4**　P1 に当たる出来事（承認して入れた出来事など）は、結び付いた場面の読む順で決める。結び付いた場面のうち、読む順で最も手前のものが、今の場面より前なら「これまで」、今の場面なら「今の場面」、後なら「これから」である。結び付いた場面が無いか、読む順に無ければ、「不明」である。
- **P5**　今の場面が無いか、読む順に無いときは、どの出来事も「不明」である。
- **P6**　位置には、根拠を添える。「年表の並び」か「読む順」である。2 つを 1 つの語に混ぜない。読む順は、描かれた順であって、作中の順ではない。回想の場面では、食い違うことがある。

判定は、画面側の 1 つの関数に置く。自動のまとめと、道具が、同じ関数を使う。MCP 側（Rust）は、同じ規則を持ち、共有の例（fixture）で、画面側と一致することを示す。

### 2.2 自動のまとめ（M1〜M5）

- **M1**　入れるのは、「これまで」と「今の場面」の出来事だけである。「これから」と「不明」は入れない。
- **M2**　承認して入れた出来事も、P4 で「これまで」か「今の場面」なら入る。件数の上限は変えない。年表の並びで決まる出来事は、今までどおり、現在地に近い順に選ぶ。読む順で決まる出来事は、結び付いた場面が今の場面に近い順に選ぶ。2 種類の配分は、実装のときに決め、共有の例で固定する。
- **M3**　見出し「直近の出来事」を、「これまでの出来事」にする。導入の文に、「ここに無い出来事は、まだ起きていないか、位置が分からないものである」を足す。日本語と英語の両方を直す。
- **M4**　作中の日時が決まらない場面では、「作中時刻: 未確定」と書く。手前の場面から借りたときは、今までどおり、推定であることを書く。
- **M5**　人物の生死・年齢・所在は、P1 の後の現在地から導く。

### 2.3 道具（T1〜T5）

- **T1**　出来事の一覧・詳細・人物の年表・検索は、出来事を除かない（SRA/1 の決定 12）。出来事 1 件ずつに、位置（P2）と根拠（P6）を足す。
- **T2**　一覧・詳細・人物の年表の返り値に、今の場面の情報を足す。場面の題、作中の日時、現在地の出どころ（場面の日付・結び付いた出来事・手前の場面からの推定・未確定）である。検索の返り値は並びのままにし、1 件ずつの位置だけを足す。
- **T3**　位置の読み方（「これから」の出来事は、今の場面ではまだ起きていないものとして扱う、など）を、AI に 1 文で伝える。道具の説明に足すか、年表のまとめの導入の文に足すかは、実装のときに決める。どちらも、AI への指示の変更である。
- **T4**　場面を指定して年表の状況を読む道具（`get_chronicle_state`）は、自動のまとめと同じ規則（M1〜M5）にする。
- **T5**　道具には、道具の作り直しを待たずに、今の道具へ先に入れる。位置の判定の関数は、チャットの IR に依存しない新しい module に置く（§1.4、§5）。

### 2.4 視点・日時・時制（V1〜V4）

- **V1**　チャットの場面の文脈に、場面に設定した視点の人物の名前を、「この場面の視点」として足す。設定が無ければ、何も書かない。
- **V2**　視点の人物の Codex が hidden なら、渡さない（ADR 013 の D2）。
- **V3**　場面ごとの時制の設定は、足さない。作品全体の時制と視点の設定は、今までどおり渡す。作中の日時と位置の区別を入れた後に、場面ごとの時制が要るかを見る。要ると分かれば、公開の後に、別に起案する。
- **V4**　現実の今日の日付は、渡さない。

### 2.5 MCP（X1〜X2）

- **X1**　場面を指定して読む道具（`get_chronicle_state`）は、P1 と M1〜M5 を、画面側と同じにする。
- **X2**　一覧・詳細・人物の年表への位置の印は、この案に含めない。場面を指定する引数が要り、MCP の道具の入出力を変えることになる。公開の後に、別に起案する。それまで、MCP の一覧は、区別なしで渡る。

## 3. 残る制限

- 読む順の根拠は、描かれた順である。回想の場面に結び付いた出来事は、作中では過去でも、「これから」と付くことがある。根拠を添えるのは、そのためである。
- MCP の一覧は、区別なしで渡る（X2）。
- 承認して入れた出来事は、年表の画面では、末尾に並んだままである。位置を直すには、作者が作中の日時を入れる。
- 作者が、日時を入れず、確度を「不明」にした手書きの出来事も、承認して入れた出来事と同じ扱いになる（P1・P4）。
- 道具の位置の印は、画面で開いている場面に対するものである。検索の道具は、発言のときの場面を使う。【報告】
- 自動のまとめに、「これから」の出来事は入らない。AI が先の出来事を知るのは、道具を呼んだときである。
- 位置の印は、AI への手がかりである。AI が印を無視して、先の出来事を書くことは、防げない。返す文章の中のネタバレの抑制は、ADR 013 の J5 の範囲である。

## 5. 変える場所の見込みと、順番

1. **位置の判定の関数と、「作中の現在地」の直し**（P1〜P6）。画面側 `src/features/chronicle/`（`resolveSceneAnchor.ts`、`chronicleReadingPosition.ts`）と、MCP 側 `chronicle_snapshot.rs`。共有の例を足す。道具には、まだつながない。
2. **自動のまとめ**（M1〜M5、T4、X1）。`chronicleSnapshot.ts`、文言（日本語・英語）、MCP 側。品質の検査の対象に、まとめの file を足す。
3. **視点の人物**（V1・V2）。場面の文脈を組み立てる箇所。
4. **道具の返り値**（T1〜T3）。今の道具（`chronicleReadTools.ts` と検索の道具）に入れ、固定した期待値を作り直す。道具の説明を変える場合は、定義を移す PR（#1004）の merge の後にする。

1 と 2 は、年表のまとめの file を、道具の作り直しの lane が共有の場所へ移す前に、merge する。PR を開いたら、その lane の担当に番号を知らせる。

SRA/1 の「年表の出来事の印を付けない」と、この案の 1・2 は、近い時期に入れる。印だけを先に外すと、承認した出来事が、区別なしで渡る期間ができる。取り込みの既定を開けるのは、1・2 の後にする。

PR は 1 本ずつ出す。AI への指示を変える PR は、品質の検査（`grimodex-author`、`grimodex-impact-gate`）を通す。
