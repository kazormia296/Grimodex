## 0. 一枚目：推奨と残る問い

**何を決める案か。** secret の印は 3 つの役を兼ねている。IR に出すかの関門、年表から AI への秘密（MCP を含む）、Graph の本文の開示の拒否である。IR に届けるために印を外すと、ほかの 2 つも外れる。この案は、版の印と年表の印を切り離す。

**推奨**
1. **取り込みの規則**：抽出の提案を年表へ取り込むとき、版の secret の値に関わらず、年表の出来事は secret で作る。reveal と Scene への結び付けは今のまま、版の値から導く。【前提は確認済み】
2. **「まとめて承認」の操作**：提案ごとに、secret を外した子の版を作り、その子の版に承認を記録する。IR 側の開示の判定は変えない。【製品の API で 884 件と 551 件が IR に届いた。確認済み。1 Scene・約 8 件ずつの形】
3. **順序**：1 が先に入るまで、2 は製品で開けない。

**この案で届く範囲**
- 1 Scene ずつ抽出した提案は届く。【確認済み（評価の形）】
- 複数の Scene を 1 回で抽出した提案は、IR の別の条件に当たり、届かないか、その回の最後の Scene より後からしか出ない見込みである。【報告。未確認】この制限は今もあり、この案では変えない。

**残る問い**（§8）：★1 規則の文面、★2 作者が個別に secret を外した版の扱い、★3 実装の時期。

## 1. 確かめた事実

**取り込み**
- 取り込みは、版の secret と reveal をそのまま年表の出来事に書く（`src/features/chronicle/extraction/compiler.ts:124-125`）。【確認済み】
- Native は版から操作を組み立て直し、画面側が出した操作と digest が一致しなければ拒む（`src-tauri/crates/grimodex-db/src/narrative_extraction/commit.rs:2851-2863`、:3103-3124）。【確認済み】
- 年表の出来事の secret は、操作の値で書かれる（`chronicle_operations.rs:343`）。【確認済み】
- 取り込みの対象は、承認済みの現行の版のちょうど全部である（`commit.rs:2724-2733`）。【確認済み】
- 取り込みの Undo は、出来事が取り込みの後に変わっていると止まる（`undo.rs:1007-1018`）。比べる相手は作成直後の DB の値で、Redo は記録した値から作り直す。【前半は確認済み、後半は報告】
- 組み立て直しの照合が効くのは現行の抽出の形式のときだけで、古い形式では版の値をそのまま比べる（`commit.rs:2808-2856`）。【報告】
- 「取り込みは版の値どおり」を前提にする箇所は、上の照合のほかに見当たらなかった。補償、restore、保守は secret の値を読まない。【報告】

**3 つの役**
- IR は secret の版を拒む（`retrieval_admission/disclosure.rs:197`）。【確認済み】
- 非 secret の出来事は、今の Scene より後のものでも AI から隠されない（`src/features/chronicle/chronicleSecrecy.ts:76`）。MCP は secret でない出来事だけを返す（`src-tauri/crates/grimodex-mcp/src/db.rs:1976-1984`）。【確認済み】
- Graph の本文の開示は、secret の出来事が関わる Scene で拒否される（`scene_body_declaration/veto.rs:177-197`）。【確認済み】

**版と操作**
- 提案は `secret: true`、reveal は最初の根拠の文書、で作られる（`src/features/chronicle/extraction/proposalPlanner.ts:179-183`）。【確認済み】
- 子の版の作成者の印は `chronicle-review` に固定で、ほかの値は拒まれる（`human_derivation.rs:43`、:181-184）。作者が個別に外した版と、まとめて外した版は、版のデータでは区別できない。【確認済み】
- 編集した提案は未 review に戻り、今の「まとめて承認」の対象から外れる（`src/features/chronicle/chronicleExtractionStore.ts:630-639`）。【確認済み】
- 子の版の作成と承認を 1 回で行う Native の経路は無く、続けて 2 回の処理になる。【報告】

## 2. 規則（取り込み）

- A1. 抽出の提案（出来事の作成）を取り込むとき、年表の出来事の secret は常に true とする。
- A2. reveal の Scene と、Scene への結び付けは、今と同じく版の値から導く。
- A3. 規則は、画面側の組み立て（`compiler.ts:124`）と Native の組み立て直し（`commit.rs:3123`）の両方に、同時に置く。片方だけ変えると、照合で拒まれる（安全側に倒れる）。
- A4. 古い形式の抽出では、Native は版の値をそのまま操作と比べる（`commit.rs:2808-2856`）。【確認済み】この枝にも A1 を置くか、古い形式の出来事の作成の取り込みを Native で拒む。画面側で対象から外すだけでは、信頼しない側に頼ることになる。古い形式の抽出が今の製品で取り込みまで届くかは確かめていない。【未確認】
- A5. 取り込んだ後に年表で秘密を外すのは、今と同じく作者が年表の画面で行う。

この規則で、取り込み後の年表の状態は、今の既定（secret のまま承認して取り込む）と同じになる。そのため、年表から AI への秘密、MCP、Graph の拒否は、今と同じに効く。取り込みと同じ処理の中で書くので、非 secret の時間は生じない。

## 3. 操作（まとめて承認）

- O1. 対象は、未 review・未取り込みで、抽出の時点の内容が今の「安全」の 7 つの条件（根拠が本文と完全一致、重複なし、ほか）をすべて満たす提案とする。
- O2. 提案ごとに、secret だけを外した子の版を作り、その子の版に承認を記録する。題・根拠・reveal は変えない。
- O3. 子の版だけができて承認が無い提案は、次の回に拾う。拾う条件は「抽出の時点の内容と比べて、変わったのが secret だけ」とする。版に封印された「変わった項目の一覧」は直前の版との差分なので、Native で確かめるには、最初の版まで系譜をたどり、途中の版がすべて secret だけの変更であることを見る。【報告】
- O4. 作者には 1 行で示す。例：「この場面より後の場面で、関連場面に出せるようにします」。
- O5. 承認の記録は、今と同じく作者の操作として 1 件ずつ残す。新しい actor は作らない。

制限
- 取り込みのあった提案の組には、子の版も承認も足せない（`repository.rs:406-435`）。【確認済み】
- 版の数は 2 倍になる。承認のたびに検索 index の作り直しが走る。数百件を続けたときの時間は測っていない。【未確認】
- scope の既定の無い Scene の提案は、承認しても IR に出ない（別の決まり）。

## 4. 作者が個別に secret を外した版（★2）

今は、review 画面の checkbox で secret を外して取り込むと、年表でも秘密でなくなる。A1 を入れると、この場合も年表では secret で入る。

| 案 | 内容 | 代償 |
| -- | ---- | ---- |
| 区別しない（推奨） | checkbox の意味を「関連場面に出す」に改め、文言も変える。年表の秘密は年表の画面で外す | 今の挙動が変わる。年表でも秘密でなくしたい作者は、取り込みの後にもう 1 操作が要る。個別に外した出来事も secret で入るので、その出来事が関わる Scene では、Graph の本文の開示が拒否されるようになる（今は拒否されない） |
| 区別する | 個別に外した版は、今どおり年表でも非 secret で入れる | 区別の印を新しく置く必要がある。承認の記録に置く形は、Native が中身を検査していない。作成者の印を増やす形は、版の作成と系譜の検証の両方を変える |

## 5. 脅威モデル（draft）

- **信頼する actor**：Native の backend、作者の承認の記録。
- **信頼しない actor**：画面側が出す操作の内容、model の出力、古い画面。
- **範囲内の攻撃と誤り**
  - 画面側が、非 secret の出来事を作る操作を出す。
  - 画面側と Native の片方だけが新しい規則になる。
  - 古い形式の抽出を通して、非 secret のまま年表に入る。
  - 取り込みの取り消し・やり直しの後に、非 secret の出来事が残る。
  - 「まとめて承認」が、作者の編集した提案まで対象にする。
- **範囲外**：OS や backend の乗っ取り、作者が年表の画面で自分で秘密を外すこと、外部への送信。
- **必須の防御**
  - Native が版から操作を組み立て直し、一致しなければ拒む（今ある照合を、新しい規則で保つ）。
  - 古い形式の抽出にも、Native で同じ規則を当てるか、取り込みを拒む（A4）。画面側の除外だけに頼らない。
  - 「まとめて承認」の対象を、Native でも、最初の版までの系譜が secret だけの変更であることで確かめる。
- **受入れへの影響**
  - 正例：まとめて承認した提案が、後の Scene から関連場面に出る。取り込むと、年表の出来事は secret で、reveal は根拠の Scene になる。取り消しとやり直しができ、やり直しの後も secret である。
  - 負例：画面側が非 secret の操作を出すと拒まれる。前の Scene を書いているときの AI の文脈、chat の tool、MCP に、後ろの出来事が渡らない。Graph の本文の開示の拒否が今と同じに効く。漏れの許容は 0 とする。

## 6. 波及（この案では決めない）

- **chat の IR**：2026-11-09 の脅威モデルは「secret は拒む」が前提である。secret を外した版が増えるので、その経路を開けるときに、provider へ送る範囲を伺い直す。
- **操作の記録**：取り込みの記録に残る操作の内容は、版と違う secret の値を持つようになる。保存する項目は増えない。【報告】
- **試験**：Rust の `tests/narrative_extraction.rs` の補助関数は、新しい規則に合わせて直す必要がある見込みである。【報告】製品の通し検査と `evals/` は変えない見込みである。【報告】
- **CP-4**：製品のコードが変わるので、評価の候補が変わる。
- **提案の既定**（`secret: true`）：変えない。
