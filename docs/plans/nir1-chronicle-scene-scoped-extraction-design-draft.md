## 0. 一枚目：推奨と残る問い

**何を決める案か。** 今の抽出は、対象がフォルダで、そのフォルダの場面をすべて 1 回の抽出に含める。区切りが 3 つ以上になる抽出の提案は、IR の対象に入らない。そのため、3 場面以上のフォルダから抽出した提案は、関連場面に届かない。この案は、場面 1 つを対象に抽出できるようにする。

**推奨**
1. 抽出の対象の持ち方（フォルダの id と、場面の id の列）は変えない。フォルダの id はその場面の親のまま、場面の列を 1 つにする。【Native と再開の照合は今のまま通る。報告】
2. 変えるのは、画面側の検査 1 種類（2 か所）と、抽出の画面である。【検査の場所は確認済み】
3. review、承認、取り込み、取り消し、再開は、今の流れをそのまま使う。【フォルダに依存しないことは報告】

**この案で届く範囲**
- 6,000 字以下の場面は、区切りが 1 つになり、届く。【区切りの上限は確認済み】
- 12,000 字を超える場面は、区切りが 3 つ以上になり、届かない。その間の長さは、切る位置しだいである。【報告】
- 届くには、確認済みの取り込みの規則と「まとめて承認」も要る（別の文書）。

**残る問い**（§6）：★1 検査の変更、★2 長い場面の扱い、★3 実装の着手。

## 1. 確かめた事実

- 抽出の画面で選べるのはフォルダだけで、1 回の抽出はそのフォルダの子孫の場面をすべて含む（`src/features/chronicle/ChronicleExtractDialog.tsx:112-115`、:319-335）。【確認済み】
- 対象がフォルダでなければ、抽出は始まらない（`src/application/narrative-extraction/projectSnapshotAdapter.ts:220-228`）。【確認済み】
- 本文を封印するとき、画面側はフォルダから場面の列を導き直し、要求の列と数も順も一致しなければ止める（同 :1097-1104）。同じ検査がもう 1 か所ある（同 :1245-1262）。【前者は確認済み、後者は報告】
- Native が持つ対象の形は「フォルダの id と場面の id の列」に固定で、ほかの項目を受け付けない（`src-tauri/crates/grimodex-db/src/narrative_extraction/scope_authority_runtime.rs:30-34`）。Native はフォルダと場面の関係を照合しない。【前半は確認済み、後半は報告】
- 現行の抽出の形式と、封印済みの値に、フォルダの項目は無い。【報告】
- 区切りの上限は 6,000 字（UTF-16）である（`src/features/chronicle/extraction/windowPlanner.ts:8`）。区切りが 1〜2 でない抽出は、材料の再生が未実装で、IR の対象に入らない（`material_roster/replay.rs:109-111`）。【確認済み】
- 第 6 版の評価は、場面ごとにフォルダを作って 1 場面ずつ抽出した。その形で、提案は review から承認まで動き、IR に届いた。【確認済み（評価の記録）】
- 抽出の画面は、開始のときに今の場面の id を読んでいる（保存のため）。場面を引数に取る入口は無い。【報告】

## 2. 変更

- C1. 画面側の検査を、「フォルダの場面の列と完全に一致」から「要求した場面がすべて、今もそのフォルダの子孫で、読める」に改める（`projectSnapshotAdapter.ts:1097-1104`、:1245-1262）。
- C2. 抽出の画面に、対象として「今の場面」を足す。フォルダの選択は残す。
- C3. 再開の候補の表示など、フォルダの名前を出している箇所を、場面が 1 つのときは場面の名前にする。
- C4. 抽出を始める前に、場面の本文の長さを見て、6,000 字を超えるときは知らせる（★2）。

変えないもの：Native の対象の形、抽出の形式、封印済みの値、review・承認・取り込み・取り消し・再開の流れ、本文を封印する経路。新しい保存先と IPC は足さない見込みである。【報告】

## 3. 脅威モデルへの影響（draft）

- C1 は、画面側の検査を 1 つ緩める。今の検査が守っているのは、「作者が選んだフォルダの今の中身」と「抽出に渡した場面の列」が食い違わないことである。
- 改めた後も、要求した場面が実在し、そのフォルダの子孫で、読めることは確かめる。確かめなくなるのは、「フォルダのほかの場面が対象に入っていない」ことだけで、これは意図した変更である。
- 封印する本文は、今と同じ経路で、要求した場面のものだけである。Native の検査と封印済みの値は変わらない。
- 信頼する側としない側、範囲内と範囲外の攻撃は、今の抽出のものから変えない。
- 受入れ：場面 1 つの抽出が、review、まとめて承認、取り込み、取り消し、再開まで通る。その提案が、後の場面から関連場面に出る。抽出の途中で場面を消すか移すと、今と同じく止まる。
