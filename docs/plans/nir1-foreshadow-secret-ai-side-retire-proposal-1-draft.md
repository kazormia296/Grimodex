## 0. 一枚目

**何を決める案か。** 伏線の設定「AI にこの伏線を見せない（ネタバレ防止）」（内部では foreshadows.secret）を、**AI への渡し方についてだけ**やめる。未回収の伏線は、全部 AI に渡す。守る印は Codex の「AI から除外（hidden）」だけにする方向に、伏線も揃える（出どころ：年表では確認 93 の選択肢の文。伏線では、確認 102 の選択肢の文は「伏線の秘匿は、AI への渡し方についてだけやめる」までで、「hidden だけ」とは書かない。この言い回しは、起案者がまとめた表現であり、伏線についてユーザーが選んだ文ではない）。**関連する過去シーンの判定の側は、公開の後に見直す**（確認 102）。新しい伏線は、印なしで作る（確認 105）。もう 1 つ、回収済みの伏線を、AI が求めたときに一覧で取れるようにする（F9。別の contractId）。

**形**
1. 未回収の伏線の一覧から、secret の条件を外す（F1）。
2. 編集のチェックを消す（F2）。
3. 新しい伏線は、印を付けない（OFF。確認 105）。書き口の既定が書かれている所を全部そろえる。AI・MCP の道具からは、印を付けることも外すこともできなくする（確認 118）。人間の書き口（renderer の `createForeshadow`・Native の `foreshadow_create`）は、渡された値を保存する。AI の入口が集まる共有 Rust には関門を足す（F3。R15）。
4. 列と既存の値は、DEFAULT を含めて残す。関連する過去シーンの判定と、本文の宣言の veto だけが、列を読み続ける（F4）。作者向けの警告（Codex の目のアイコン）は、既存の印つきの伏線にだけ出続ける（確認 105・120 (b)。新しい伏線には出ない）。
5. MCP にも全部見せる（F6）。
6. 実装 → 測定 → 公開の順にする（F7）。
7. 回収済みの伏線を、AI が一覧の道具で、求めたときに取りに行けるようにする（F9。別の contractId。今ある一覧の道具に「回収済みも含める」指定を足す。MCP の一覧にも。放棄は含めない。別の PR で、同じ公開版。確認 119）。
8. 約 1000 token の枠を超えて省いたときは、1 行を、AI に渡す内容に足す（F10。上限は変えない。prompt の変更）。**道具を呼べるチャット（Agent モード）：「ほかに n 件あります。一覧の道具で取れます」**（確認 123 の文のとおり）。**道具を呼べないチャット（Agent モードでない設定）：「ほかに n 件あります。」まで**（確認 130。道具の句を付けない）。

### 1.5 書き口と、評価の harness【読んだ】

## 3. 残る制限

1. **AI が、真相を先にほのめかすおそれが増える。** 伏線の「意図」は、真相そのもの（例：犯人は兄で、第 9 章で明かす、という内容）であることが多い。第 1 章を書く場面の自動の文脈にも、これが入る。**応答の点検は、まだ無い**（ADR 013 の D4。別のハーネス）。この案は、「本文では明かさない」という指示を足さない。守りは、AI が指示に従うかどうかと、F7 の測定の結果になる。作者が取れる手段は、題と意図に真相を書かない運用だけである。設定 → AI の文脈の予算（`ai.contextBudget.l1〜l5`・reserve。`settings/types.ts:239-243`）は、文脈を削るだけで、伏線を指定して外せない。プロンプトの追記のスロット（`aiPrompt.custom.foreshadow`）は、指示を足すもので、渡す内容を外せない（読み。実行していない。未回収の伏線を自動の文脈から外す設定は、`settings/types.ts` に見つからない）。
2. **題・意図・メモの文中の、Codex の hidden の名前は、判定できず、そのまま渡る**（指摘 #1。§1.4 の最後の項。確認 120 (a)）。伏線の経路は、結んだ Codex の項目を AI に出さないので、渡るのは作者が書いた文だけである。その文に hidden の判定は掛かっておらず、マスクも無い。これまでは、新しい伏線が既定 ON で一覧から隠れていたので、事実上この漏れが少なかった。F1 で、未回収の全部が、外部の提供者に、最初のチャットから渡る。例：伏線の題「〈hidden にした人物〉の正体」、意図「実は〈その人物〉が犯人」。今は ON なら一覧に出ない（今の場面に紐づけば出る）。変更後は、未回収の一覧と今の場面の文脈のどちらでも、その名前がそのまま外部へ渡る。MCP の `list_open_foreshadows`・`get_writing_context` も同じ。年表では、確認 97 が「出来事の題やメモに、作者が名前を書いている場合は、そのまま渡ります（文章の中身は、判定できないため）。」とユーザーに伝えて選ばせた（CSR/1 の §3・§8 の (7)）。**伏線でも、確認 120 (a) で同じ文を伝え、ユーザーは「このとおりでよい」を選んだ（年表と同じ扱い。「hidden の人物に結んだ伏線は、AI に渡さない」は選ばれなかった）。**
3. **全部渡す、は枠の中でだけ。上限は変えず、省いたことは AI に伝える（確認 123・130）。** 約 1000 token を超えると critical だけに絞る（変えない）。例：未回収が 40 件の作品で、重要度を付けていない伏線が大半なら、critical だけが渡り、ほかは自動の一覧に出ない（`list_open_foreshadows` で取れる）。**確認 123・130 で、省いたときは 1 行が付く（F10）：道具を呼べるチャット（Agent モード）は「ほかに n 件あります。一覧の道具で取れます」、道具を呼べないチャット（Agent モードでない設定）は「ほかに n 件あります。」まで。** これで、critical が 0 件のとき、見出し「### 未回収の伏線」だけが残って、AI には空の一覧に見える（`contextBuilder.ts:1236-1245` の読み。実行していない）問題は、見出しとこの 1 行になり、解ける。**残る制限**：(a) 省かれた伏線の題・意図は、AI が一覧の道具を呼ぶまで、AI に見えない。(b) 道具を呼べないチャット（Agent モードでないとき）では、AI は「ほかにある」と知るが、取りに行けず、取りに行く案内も言わない（確認 130 で選ばれた形。作者が見る違い：Agent モードでない設定のチャットで、AI が省かれた伏線の存在だけを知る）。(c) 1 行の `n` は、絞る前の未回収・未放棄の件数から、渡した件数を引いた数で、回収済みは数えない。F1 の後は、一覧が埋まる作品が増えるので、枠を超える頻度が上がる。1 件の token 数は、未計測【未確認】。
4. **今ほぼ空の一覧が、切り替えの時点から、全部入る**（既存の伏線の ON の割合は、未確認）。**外部の AI の提供者に、題と意図が、知らせずに、最初のチャットから渡る**（確認 102。確認 120 (c)：リリースノートにだけ書く。年表と同じ）。作者は、「見せない」が付いていると思ったまま使い続けうる。
5. **既存の ON の伏線は、B に効き続け、画面から外せず、見えない**（F4）。外れ方は、判定と本文の宣言の veto で違う。判定（A3）：放棄、削除、回収の場面が決まっていれば読む位置がその場面に達したとき、回収の場面が無ければ回収の確定。**回収の場面が決まっていれば、回収を確定しても外れない**。本文の宣言の veto：放棄しても、回収を確定しても外れない。伏線の削除か、その場面との結びを外したときだけ。確認 105 の文「回収まで出ないままなので」は、この実装より単純な言い方だったので、確認 120 (d) で、読む位置で決まる、と伝えた（§1.1）。本文の宣言の veto は、確認 129 で伝え、今までどおり残すと選ばれた（§1.1）。Graph の経路は今は閉じており、作者への影響は、公開の後に出る。
6. **新旧の伏線で、関連する過去シーンの出方が分かれ、目のアイコンも新しい伏線に出ない**（確認 105。選ばれた帰結）。新しい伏線は OFF なので、結んだ Codex の項目は、未回収でも、関連する過去シーンに出る（今は、既定 ON のため、回収まで閉じる）。目のアイコンの警告「このシーン時点で未開示」は、新しい伏線には出ない。既存の ON の伏線には、今のまま出る（確認 120 (b)）ので、**警告は、既存の印つきの伏線が回収・放棄・削除されるにつれて、だんだん消える**。B を公開の後に見直す、という確認 102 の線の内側にある。
7. **本文の宣言の veto は、既存の ON だけに当たる**（`veto.rs:160-175`）。K2/5 の PR-2 の撤去まで。宣言の画面は閉じている。放棄しても外れない（F4）。**放棄しても効き続けることは、11-23 の追記で伝え、確認 129 で、今までどおり残すと選ばれた**（§1.1）。**撤去（PR-2）の時期は、凍結の直前まで待つ予定**（確認 129 の問いで、ユーザーに伝えた点）。**以下の理由は起案者の補足で、問いには出ていない**（`s4-change-list.md` §6「順序（最重要）」：PR-2 は、S4 の枝が `cp4-harness.ts` の import と seam の env を外した後になる。pin 済みの file は単独で merge できない〔C7 #826〕ので、凍結の直前まで待つか、UI・Rust・seam に分けて先に入れる）。**FSR/1 は PR-2 を先取りしない**（許可しない範囲。§8）ので、既存の ON の伏線が、閉じた宣言を拒む期間は、公開の直前まで長くなりうる（宣言の画面は閉じており、作者に見える挙動は今は無い。PR-2 が公開の前に入れば、公開版には残らない見込み。読み。この期間の長さは、確認 129 の問いの文で伝えた〔「残る期間が公開の直前まで長くなりうる」〕上で、ユーザーが「今までどおり残す」を選んだ）。
8. **MCP の向こうの AI が、全部の未回収の伏線を見る。** 更新・放棄・削除も、元から id で書けた。MCP の返り値に、位置の印は無い。アプリには `grimodex-mcp` が同梱される（`electron-builder.yml` の `extraResources`）が、別に配布・設定された古い MCP が使われうるかは未確認で、使われるなら、版がずれる（古い MCP は、ON の伏線を隠したままにする）。
9. **AI が作った伏線を、同じ会話で読み戻せない問題は、なくなる**（今の説明は「pass secret=false if you need to read it back later in this conversation」）。
10. **抽出の作成：製品の作り手は無い。確認 105 とは衝突しない（改稿 4 で閉じた）。** `CreatePayload` の `secret: bool` は必須で既定が無く（`foreshadow_operations.rs:60-68`）、commit の入口（`commit.rs:1520-1522`）は、提案の JSON をそのまま `parse_create` して `payload.secret` を保存する。年表の出来事の作成は「常に secret で作る」と検査する（`commit.rs:2287-2291`）が、伏線には同じ検査が無い。**しかし、`secret` の作り手は、基点の製品のコードに無い**（AI の出力の schema・prompt・TS の組み立てのどこにも `secret` が無い。入口は IPC だけ。F3 (f)）。`true` が入るのは、試験の fixture 2 本（`tests/foreshadow_narrative_commit.rs:268`・`nir1_packing_session_tests.rs:368`）と、手で組んだ IPC の呼び出しだけ。**残る制限**：書き口の層に `true` の拒否が無いので、将来、伏線の提案を op に compile する層を足すと、`true` を入れうる。そのときは、その層で `false` に固定する（F3 (f)）。この案は、規則を足さない（R17）。
11. **AI・MCP は、`secret` を書けなくなる（確認 118）。** (a) MCP の利用者や外部のスクリプトで、`secret: true` を毎回渡すものは、変更後にエラーになる。例：MCP 経由で伏線を作るスキルが `secret: true` を渡し続けると、毎回、廃止を述べる文で失敗する（作者の渡し方が変わる）。(b) update の `secret` は、`false` も拒む。AI は、今までのように、既存の印を外せなくなる（AI の道具の説明は「until the author reveals them」で、外せた）。外せる手段は、作者にも無い（F2）ので、既存の印を外す手段が、どこにも無くなる。(c) create の結果から `secret` が消える（F3 (e)）。
