# NIR-1 standard-build receipt producer lifecycle

Scope: produce only the local, diagnostic standard-build receipt consumed by the NIR-1 setup/retrieval runners. This adds no application, retrieval, or product authority; it does not activate product journeys or infer/send to a model. The only admitted build argv, in order, is `pnpm napi:build` then `pnpm electron:build`.

Review-fix boundaries: the production entrypoint accepts only root, output path, and cancellation signal; it cannot inject commands, runners, or persistence hooks. A separately named fixture entrypoint may inject test dependencies, but always emits `nir1-standard-build-fixture/1` with `standardBuild:false`, which cannot qualify as build evidence. Late-close ownership is captured before any fallible diagnostic write, and the lock remains held through late close/group exit even if that write fails. Source admission and post-build checks reject `assume-unchanged` / `skip-worktree` index flags rather than treating their suppressed status as clean-source proof. The direct retrieval runner must reject a supplied receipt unless its status is `passed`, `standardBuild` is `true`, and schema is `nir1-standard-build/1`, before any model or runtime admission. Its existing optional receipt-free artifact-only precheck remains diagnostic, not standard-build evidence.

It admits command 2 only after command 1 has observed close, exit 0, no signal/timeout/spawn error, and an empty process group. Per-command timeout is finite.                                                                                 | On abort/timeout the supervisor sends TERM, waits its bounded grace, sends KILL if needed, then waits its bounded group grace. A request/error is not close proof.                                                                                                                                                                      | PID and process-group outcome are recorded; no process is retried.                                                                                                                                                                                                              |
| Observed close and group exit         | The supervisor is the only authority for child `close` and process-group existence. Normal command completion requires observed `close`, the expected zero exit/no signal, and observed empty group.                                                                                                 | Only observed close plus empty group can establish quiescence. Logs are finalized/hashed only after this proof.                                                                                                                                                                                                                         | Successful commands include observed status, exit/signal, cleanup, and complete log identities.                                                                                                                                                                                 |
| Unknown cleanup after TERM/KILL       | The optional finite post-KILL close-observation window returns a structured failure with `closeObserved:false`, `cleanup.complete:false`, and `termination:"unknown"`. Supervisor retains the live child/late-close observation; it does not claim kill means termination.                           | No next command. No additional signal is sent from a persisted PID. No final log/artifact proof is emitted. The producer records the failure and keeps the root lock while awaiting late close and group exit; if the OS never reports them, the producer remains quarantined and does not return success or silently orphan the owner. | Late close/error remains observed by the owning supervisor instance. A new process cannot adopt or signal the old PID from disk. If the enclosing process is forcibly killed, its active lock is deliberately stale and blocks automatic reentry pending operator verification. |
| Source manifest and candidate binding | Before admission, the producer requires a clean worktree and records canonical root, local `origin/master` base commit, current HEAD commit/tree, and sorted repo-relative tracked-tree path→SHA-256 manifest.                                                                                       | After both successful commands it recomputes the same path set/hashes, checks clean status and the same base/HEAD/tree, then requires four regular nonempty artifacts and recomputes each SHA-256. Any drift/missing file/output error is failure.                                                                                      | The absolute manifest path/digest and artifact map are written and validated before publishing `standardBuild:true` and `sourceUnchanged:true`. Failure leaves a failure receipt or persistent owner diagnostics; existing receipts are never overwritten.                      |

Known limit: supervision is POSIX process-group based, as is the existing shared supervisor. An uninterruptible OS stall cannot be claimed terminated; it remains an unknown, quarantined owner rather than successful evidence.
