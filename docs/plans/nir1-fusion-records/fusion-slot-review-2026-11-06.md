# 融合の枠の数と Raw 偏重の見直し：判断文書（2026-11-06）

起案のみ（コード・policy・Gold・閾値は変えない）。ユーザーは「枠の数と Raw 偏重を見直してから案の採否を決める」と決めた。結論は「今は決めず、小さな Gold の測定を先に置く」。

## 1. 今の規則と根拠

- 表示は最大 8 件、Raw は全件保持、足せるのは Raw にない Scene を末尾に最大 1 件。融合 ID `raw-stable-one-supplement/1`（`policies/narrative/nir1-related-scenes-ranking.json:7-9`）。
- 実装は「Raw が 8 件未満なら IR の最初の 1 件を足す」（`nir1RelatedScenesFusion.ts:56-59`）。Graph はその枠が空いているときだけ足せる（`nir1GraphFusion.ts:78-90`）。**Raw が 8 件のときは IR も Graph も足せない。** 8 は `RELATED_SCENES_MAX`（`relatedScenesConfig.ts:2`）で、パネル導入時（PR #120）の値の継承。
- 根拠は 2 つだけ。A5 比較 1 で IR の追加は誤りを含んだ（英語の校正 precision 0.769、holdout 0.667）うえ、Raw を超えた事前指定 case は 0。そこで「Raw を動かさず、余地があれば最上位 1 件」にした。**IR と Graph で枠を共有する技術的な必然は記録にない**（初出は #571 の計画文書の 1 文。材料 §2.2）。「1 件」が最適だと示した比較もない。

## 2. 言えること／言えないこと

数値は `pd-ir-slot-2026-11-06/README.md`（第 6 版）と `pd-ir-slot-2026-11-04/README.md`（第 5 版）。

**言えること（日本語、IR が最大に出る条件）**
- Raw が 8 件で枠が閉じていた sample は m-ja-2 258/348 = 74.1％、g-ja-1 279/348 = 80.2％。前の Scene >30 では 219/258 = 84.9％、243/258 = 94.2％（g-ja-1 は時間切れ 33 を含む）。
- そのとき IR に Raw の外の候補があったのは 252/258 = 97.7％、279/279 = 100.0％。
- 枠が開いたときは使われる：主指標 81/90 = 90.0％（第 5 版 78/90 = 86.7％）、g-ja-1 57/69 = 82.6％。
- 全 sample では、IR が実際に足せたのは 81/348 = 23.3％、57/348 = 16.4％（件数から算出）。
- 英語は別の事情：m-en-1 は 6/51 = 11.8％。IR の admitted が 0 件の sample が多く（168/210）、Raw 満杯は 30/210 だけ。枠が開いても足せず、floor 0.66 の論点で枠の数では動かない（第 5 版）。

**言えないこと**
- **2 件目以降の候補の precision は測っていない。** 枠に入った 1 件の正しさも未測定（第 5 版・第 6 版とも）。第 6 版が示したのは「機会が閉じている」側だけ。
- Graph の実原稿での精度は測っていない。CP-4 の s5r6 が判定したのは可用性だけ。Gold G-01〜08 は Graph に有利に設計してあり、差は設計した差（材料 §3.2）。枠の衝突を測った case は G-05 の 1 件。Graph は標準 build で閉じている。「Graph の方が全然精度が高い」は**裏づけも反証もない**。文献では利得はタスク依存で、小説で有意差が出ない報告もある（材料 §3.4）。
- Raw の下位（rank 6〜8）の precision も未測定。「Raw 偏重は妥当か」はこの値がないと答えられない。
- g-ja-1 との差（主指標 −7.4 pt）は記憶以外の交絡を分けられない。1 run、実効 n は約 1/3、作品は各 1 つ。

## 3. 案の比較と推奨

| 案 | 内容 | 第 6 版で変わる評価 |
|---|---|---|
| D | 現状維持＋path の表示強化 | 機会の 74〜80％ は閉じたまま。害は最小 |
| A1 | Graph 専用枠 +1（8 以内） | Raw 満杯なら閉じたまま。Graph の材料は本測定にない |
| A2 | 8 を超えて末尾に足す | Raw 満杯の機会に届く唯一の追加型。UI・件数検査・Gold に波及 |
| B | 共通枠 2〜3 件 | 8 以内なら Raw 満杯の 74〜80％ に効かない |
| C | Raw 下位を押し出す | 届くが、Graph の確信度の契約がなく重い。Raw 非回帰が構造でなくなる |

**推奨：案 B を最小の一歩とする見解に、条件つきで賛成する。** コード上は最小で、末尾追加なので Raw 非回帰を保てる（探索枠 1〜2 件なら害が小さいという抜粋あり。原典未確認）。ただし 2 点を足す。(1) B を「8 以内」と「8 超」に分けて測る。8 以内の B が効くのは Raw が 8 件未満の 20〜26％ だけで、さらに Raw が 7 件なら枠は 1 つしか空かない（Raw の件数の分布は記録にない）。大半の機会に届くのは A2 型で、B はその入口でしかない。(2) 今は採否を決めない。2 件目以降の precision がないまま増やす根拠がなく、A5 の水準なら誤りが 2〜3 倍に出うる。C は Graph の確信度の契約が先。E／F／G と Graph 専用枠は契約に触れ、材料もないので対象外。

## 4. 決める前に要る測定の骨子

**Gold（新設。凍結済みの CP-4 の Gold には当てない）**
- 対象：m-ja-2 と g-ja-1。層は（Raw 満杯／未満）×（前の Scene ≤30／>30）、各層 15 query、計 60 query。種を事前登録して無作為抽出。IR が Raw 外に 2 件以上持つ query の割合も記録する（枠 2〜3 の機会の分母）。反復は 1 と数える。
- 候補：IR の Raw 外の rank 1〜3 と、Raw の rank 6〜8（比較の基準）。由来・順位を隠して混ぜる。
- 注釈：「この Scene を、作者が今の Scene の執筆中に見たいか」を 2 値。**strict**（同じ人物・場所・出来事の連続、伏線と回収など、事前に類型を固定）と **partial**（strict または主題の近さ）の 2 段。2 人が独立に付け、段ごとに κ を出す。
- 報告：rank ごとの precision を Wilson 95％ 区間で。「違反 0」「漏れ 0」は 0/n に片側 95％ 上限（3/n 近似）を併記。
- run：同じ build・harness・model で 2 run。ラベルは（query, 候補）の組に付くので、2 run 目は新しい組だけ追加で付ける。

**arm（評価専用 build）**：枠 1（現行）、2、3（8 以内）、8 超に +1、+2。arm は同じ run の Raw・IR の列から作り、arm 間は対応のある比較にする。指標は、枠の使用数、足した行の precision、1 query あたりの誤った追加行数、Raw の行が不変であること。母集団・種・類型・指標を測る前に contracts へ固定し、閾値は問 4 の後に書く。

**費用・時間（推測）**：抽出は第 6 版の実績で 1 作品 1 run 約 $8〜9、2 時間 10 分〜2 時間 53 分。2 作品×2 run で約 $34、実行は約 10 時間。注釈は 1 query 約 4 分で 1 人 4 時間前後。60 query だと 2 件目の precision の区間幅は約 ±0.12（p=0.7 のとき）で、狭めるなら 80 query。

## 5. ユーザーに決めてもらう問い

1. **測定の lane を起こすか。** (a) 起こす（推奨：枠も Raw 偏重も、この値が無いと決められない）、(b) 案 B を今決める、(c) 現状維持で閉じる。
2. **arm に「8 超」を含めるか。** (a) 含める（推奨：Raw 満杯の機会に届くのは 8 超だけ）、(b) 8 以内の 1／2／3 だけ。含めると UI の件数・検査の変更が候補に入る。
3. **注釈者。** (a) ユーザー＋別の 1 人（推奨：κ に 2 人要る）、(b) ユーザー＋AI（Claude 系は自己選好の恐れ、異系列の model なら可）。ユーザーの時間が約 4 時間要る。
4. **採否の閾値の置き方。** 新しい Gold の閾値は私が決められない。(a) Raw の rank 6〜8 の precision との相対と、strict の下限の併用（推奨。下限の値はユーザーが決める）、(b) 絶対値だけ。測定の前に事前登録へ書く。

## 6. 変えないもの／動くもの

**変えない**：IR の floor（ja 0.813、en 0.66）、Raw の順位付けと行の保持、Raw の非回帰の測り方、既存 Gold の値と期待値、観測後に Gold を変えない規則。

**動くもの（変える場合）**：枠は policy、renderer の融合、Native の compose、IPC の wire、`==1` の検査と hash に固定され、数値だけでは動かない（材料 §4）。融合方針・評価基準・Gold が動き、A2 は件数検査と UI、C は契約も動く。閾値・Gold の変更はユーザーの明示の判断が要る。Graph の評価用の入口は新しい契約になりうるので別途確認する。
