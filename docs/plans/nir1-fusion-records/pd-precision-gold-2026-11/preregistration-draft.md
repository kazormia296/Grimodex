## 4. 注釈

- 設問（2 値）：「**この Scene を、作者が今の Scene の執筆中に見たいか**」。今の Scene と候補の Scene の本文を見せる（製品の IR の解釈文・抜粋は見せない。§10）。

- 注釈者は**ユーザー**と**別系列の AI**で、互いの値を見せず独立に付ける。AI の model・版・prompt は測る前に固定し sha256 を記録する。同じ prompt を 2 回出し、1 回目を注釈、2 回目を安定性（AI 内の一致と κ）に使う。理由の文章は求めない。
- 一致：Cohen の κ と一致率を段ごとに（ユーザー対 AI、AI の 2 回の間）。不一致は消さず、件数を数える（調査文書による と、文学の注釈では絶対の閾値より段別の開示が妥当）。
- **主の注釈はユーザー**（案）。AI は副で、一致と、precision の幅（「両者が 1」「どちらかが 1」）に使う。
- 注意：調査文書による と、LLM が作る・付ける評価は人間より易しい側に寄る報告がある。AI の値がユーザーより高ければその向きで読み、AI だけで結論しない。

## 6. arm（オフライン）

arm は同じ run の Raw の件数 r と IR の候補列だけで決まるので、**評価専用 build は要らず**、集計 script で作る（現行の枠 1 が records の `kind:"ir"` の行を 138 sample で再現することを下書きの時点で確認、不一致 0）。

| arm | 足す行 | 8 件の上限 |
|---|---|---|
| S1（現行） | rank 1 を 1 件 | 超えない |
| S2／S3 | rank 1〜2／1〜3 | 超えない（足せるのは 8−r 件まで） |
| O1／O2（8 超 +1／+2） | rank 1／1〜2 | 超えてよい（r が 8 でも足す） |

- O は「上限を外して k 件足す」と定義する（§12）。S1 と O1 の差は r=8 のときだけ。
- 指標（対応のある比較）：足した行がある query の割合、**足した行の precision**（strict・partial）、**1 query あたりの誤った追加行数**（strict が 0）、Raw の行の不変。
- arm の精度は §3 の注釈から作り、追加の注釈は要らない。rank 4 以降は入れない。8 超は UI の件数・検査に波及するが、この測定は採否も UI の変更の根拠も決めない。

## 7. 判断規則の候補（**ユーザーが決める**）

閾値は私が決められない（問い 4）。測る前にここへ書く。

- **(a) 相対＋strict の下限の併用（推奨）**：IR の rank r（1、2、3 のそれぞれ）が採用候補に残る条件は、両方を満たすこと。(1) 同じ query の Raw rank 6〜8 の strict precision との差が −Δ 以内（Δ は例 0.10）、(2) strict precision の Wilson 下限が L 以上。
  - 理由：相対だけだと Raw の下位が低いときに IR が通ってしまう。絶対だけだと「Raw 偏重」に答えられない。
  - L の目安：下限が 0.4／0.5／0.6 になる点推定は n=60 で約 0.53／0.63／0.73、n=30 で 0.60／0.70／0.80（例：L=0.5 なら n=60 で 38/60）。
- **(b) 絶対値だけ**：strict（または partial）の Wilson 下限が L 以上。簡単だが、Raw 下位との比較（判断文書が未測定とした点）に答えず、L の根拠も無い。
- 参考値（A5 比較 1 の英語の校正 precision 0.769、holdout 0.667）は IR 1 件の過去の値で、L の根拠にしない。
- **判断不能（D0 相当）の案**：次のどれかなら、その rank に結論を出さない。(1) 注釈済みの組が rank あたり 30 未満、(2) ユーザーと AI の strict の κ が 0.4 未満、(3) 候補を取れなかった query が 10％ 超。値は案。
- ここの条件は採否の判断用で、第 5・6 版の D0・D1、IR の floor、既存 Gold の期待値は変えない。
