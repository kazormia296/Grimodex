- 英語は測らないので、英語の対照（g-en-1）の値は無い。英語の IR が空になりやすいのは足切り 0.66 によるもので、この版では扱わない。

この結果に固有の限界：

- **g-ja-1 の抽出の失敗 10 件で、g-ja-1 の IR の入力は設計どおりでない**（第 5 版と同じ注意）。失敗した Scene は提案も承認も 0 なので、後ろの位置の IR はその Scene の revision を持たない。決まりどおり失敗は除かずに数えた。m-ja-2 の第 6 版は失敗 0 で、本測定で初めて「失敗した Scene の revision が欠ける」ことの無い入力になった（IR の build の preflight を通る revision の数は確かめていない）。
- **g-ja-1 の 100％ 地点は IR の時間切れ 33 件で、IR の状態の分布が m-ja-2 と違う。** 主指標と「Raw 満杯で IR 候補あり」には影響していない（上の観測）。「IR が使えなかった割合」（g-ja-1 9.5％、m-ja-2 0）は、作品の差・run の環境の差・build の接続の保持のどれによるかを分けられない。両 run の candidate（head `9930ab64`、clean）・build（receipt `9c1dc011…`）・Electron・model・harness は records で同一で、記録に残る環境の差は無い。窓 D（40 ms）は records に値を記録していない。D は renderer の定数（`RELATED_SCENES_IR_EXTRA_WAIT_MS`、DR-IRW-1）で、両 run は同じ head の作業木から配られるので同じ値（g-ja-1 の時間切れ 33 件の `returnAfterRawMs` 40.1〜40.5 ms は、この D で打ち切られた痕跡）。時間切れの原因は確かめていない。
- **1 回の run の値で、非決定性の分散を含まない。** 抽出の失敗の数・提案の数・IR の admitted・IR の時間切れは run ごとに変わりうる。
- 標本の実効の大きさは sample の数より小さい（同じ query の 3 回の反復を数えている。区間は sample の数で計算しているので実効の n は約 1/3）。作品をまたぐ一般化は主張しない。
- 枠に入った IR の中身の正しさ（その 1 件が関連場面として適切か）は測っていない。枠の使用率は「IR が枠を使う機会」で、関連場面の改善を示す値ではない。
- m-ja-2 は model が学習で知っている可能性が高い公有の古典で、作者の新作に外挿しない。g-ja-1 は学習の締切の後に生成した原稿だが、上のとおり記憶以外の交絡があり、差を記憶の大きさの推定に使うことはできない。
- 公開の文献から足す限界の詳細（実効の標本、FABLES、Speak Memory、RECAP、OWL）は `pd-ir-slot-2026-11-04/README.md` の末尾の節のとおりで、第 6 版にも当たる。
