# ユーザー確認：S2 の時期（Q11′）と S2 で返す IR の形（Q13）（2026-11-18）

## Q11′：S2 の凍結と実行は S1 のどこまでを待つか
- 伺った背景：11-16 の決定は「S1・S2 は S4 の merge 後」で、記録は「S2 は S1 の後」と読んだ。その後 S1 を A（Native）・B（renderer の接続）・C（audit の置き換え）・D（出典の UI）に分けた。A は merge 済み、B は未着手。S2 が測る形は A と B で決まり、C・D は S2 の送信に効かない見込み【推測】。
- **回答：「S1-A・B の merge の後」**（推奨案）。B の merge の後、B の結果の形と説明文に harness を合わせてから第 1 段の凍結を行い、抽出と回答に進む。C・D は待たない。

## Q13：S2 で model に返す IR の項目の形
- 伺った背景：merge 済みの S1-A の item は、要約と引用のほかに `score`・`revisionId`・`review: "human-approved"` を持つ。事前登録の草案は score を見せない形だった。送信先は既存の Anthropic、データは評価用の AI 原稿から作ったもの。
- **回答：「S1-A の形のまま」**（推奨案）。製品と同じ形で閾値を決める。S3 の前の確認で score などが外れたら、S3 の後の A/B で符号を確かめ直し、限界に書く。
- **この回答は S2 の測り方だけを決める。製品でこれらの項目を model へ送ってよいかの同意ではない**（S3 の前に D1・D3 として別に伺う。質問の文面にもそう明記した）。
