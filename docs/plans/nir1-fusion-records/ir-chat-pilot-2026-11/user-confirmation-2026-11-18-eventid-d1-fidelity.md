## ず-1：eventId が item に無いため実装できない 2 つの規則
- 2 つの規則：△7 (4)「IR の規則で除かれた revision の eventId は、年表の結果からも除く」と、「年表と IR に同じ eventId があれば 1 件にまとめる」。
- 伺った背景：merge 済みの S1-A の item には eventId が無い。今の実データでは、承認済みでも未適用の revision が IR に入る。適用済みでなければ年表に event が無いので、重複も (4) も起きない。
- **回答：「規則どおり実装」**（推奨案）。
  - Rust 側（Native と共有 crate）に eventId の欄を別の PR で足す（S1-A2）。
  - (4) と重複の統合の両方を、確認済みの規則どおり実装する。
  - 確認済みの規則は縮めない。

## 除外の渡し方（△7 (4) の実装の形）
- **回答：「候補の eventId を渡す」**（推奨案）。
  - renderer が持つ年表の event の ID（最大 30 件。秘匿と位置の filter の後のもの）を Native に渡し、Native が除くものを返す。
  - **契約 §3.2 の入力が 1 つ増える変更として承認された。** 新しい送信先ではない（Main と Native の中の受け渡し）。
  - 採らなかった案：除外集合を応答で返す形。応答が大きくなる（g-ja-1 で中央 441 件、最大 884 件）。

## D1：model へ送るデータの区分（S3 の前の確認）
- 伺った背景：今の item は、要約と quote のほかに revisionId・sceneId・題・score・review（`"human-approved"`）を含み、このまま model に届く。★1 の回答「§3 のとおり承認」（§3.3 はこれらを出力に挙げる）と、★4 の回答 (B)「要約と quote に限る」の間に食い違いが残っていた。今は定数が false なので、何も送っていない。

## 追加の 3 問（S1-A2 の設計 `fusion-eval-data/design-notes/chat-ir-2026-11-08/s1a2-design-2026-11-18.md` §4.1・§4.4・§6.2 から。同じ日の夜）

### Q1：(4) の「IR の規則で除かれた」の範囲
- **回答：「含めない」**（推奨案、d-i）。
  - 除くのは、問い合わせの時点の開示の判定（出典が今の Scene と同じか後、など）で落ちたものだけ。
  - IR の索引に入っていない revision（stale・版の secret・置き換え済みなど）は対象にしない。
  - 作者の画面の年表は変わらない。

### Q2：除外の結果が得られないとき
- 伺った背景：reveal の Scene が出典の Scene より後である、という構造上の制約は見当たらない（抽出や作者が reveal を自由に決められる）。このため、U-a で残る穴は実在しうる。大きさは未測定で、今の実データでは 0 件。
- **回答：「折衷：model の経路を塞ぐ」**（推奨案）。
  - 事前判定で cap を使い切ったときも、除外を得るためだけに Native を呼ぶ。
  - `turn-limit` と `query-invalid` のときは、secret の event に近似の規則（結ばれた Scene がすべて今の Scene より前）を掛ける。
  - 一時的・構造的な失敗では、今のまま返す（秘匿と位置の filter は掛かる）。

### Q3：脅威モデルの差分
- **回答：「受け入れる」**（推奨案）。
  - T17〜T20 を脅威モデルに入れる。
  - 応答に `eventIds` と `excludedEventIds` を足す。
  - 年表と統合した item に限り、model に `chronicleIr.eventIds` を見せる。
  - 新しい送信先は無い。候補と除外は log・audit・ledger に入れない。

### Q2 の補足（訂正。同じ夜）
- 先の Q2 の選択肢の説明に、代償を 1 つ書き漏らしていた。それを伝えて、改めて伺った。
  - 書き漏らした代償：事前判定で cap を使い切ったときにも、除外のためだけに Native を呼ぶ。その分、応答が最長約 20 秒遅れうる。台帳・同時実行の枠・turn の累積の上限も使う。それでも IR の要約は載らない。
- **回答：「近似の規則で塞ぐ」**（推奨案）。
  - 事前判定の `cap-exceeded` では Native を呼ばない。`turn-limit`・`query-invalid` と同じく、secret の event に近似の規則（結ばれた Scene がすべて今の Scene より前）を掛ける。
  - 一時的・構造的な失敗では、今のまま返す（変更なし）。
  - **Q2 の確定**：model が起こせる 3 つ（事前判定の `cap-exceeded`、`turn-limit`、`query-invalid`）には近似の規則を掛ける。それ以外の失敗には (4) を掛けない。
