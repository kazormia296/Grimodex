# chat の IR pilot の後のユーザー決定（2026-11-08）

凍結済みの事前登録（`preregistration-v3.2.md`）と結果（`results/README.md`）は改訂しない。この文書は、結果を受けた新しい判断の記録。

## 決定

1. **正式な試験は、当面行わない。**
   - 規模の見積り【推測】：10 pt の差を見るには作品 6〜7、5 pt なら 19〜25 作品。
   - これを受けたユーザーの言葉：「うーんまぁそこまでは良いんじゃないでしょうか？このソフト自体投機的実行とも言えるソフトですし。」
2. **chat に、質問を手がかりに IR を引く経路の設計だけを先に起こす。**
   - AskUserQuestion で「設計だけ先に起こす（推奨）」を選んだ。
   - 実装と、閉じた経路を開ける判断は、PUB-G の前提が片付いてから改めて確認する。

## 事前登録との関係（Fable の諮問、2026-11-08）

- 事前登録 1.2 の目的は「次の正式な試験の規模と質問の型の配分を決める材料を得ること」。規模の見積りを受けて「当面は正式な試験を行わず設計に進む」と決めるのは、材料の正当な使い方で、1.2 と矛盾しない。
- **pilot は製品判断の根拠ではなく、設計の着手の優先度の材料。** 経路の開閉は、この結果では決めない。
- pilot の B は、製品に無い「質問で IR を引く」能力を評価側で代替した（限界 16）。製品の経路で測るには、先に経路の設計・実装が要る。この決定は「試験を省く」より、「経路を作ってから小さく測る順序に変える」と位置づける。
- pilot の数値を引くときは、1.5 の文言を守る。「出来事の IR の block を足した効果」と書き、B−A は「chat に質問で IR を引く経路をつないだ場合の見積り」と書く。

## 設計に入れる安全策（Fable の推奨。設計の起案に渡した）

- 既定 off の閉じた実装。開放は別に確認する。
- 検索の hit が無い・弱いときは、IR の block を足さない。根拠 Scene が IR に無い 20 問では、Sonnet +4.2 [−2.5, +11.7]、Haiku −0.6。
- 描画は要約文より quote を先にし、Scene への出典を辿れる形にする。
- 製品の経路で、事後の小さな観測をする（1〜2 作品×20 問の A/B。符号と hit 率だけ）。
- IR 由来の挿入の source metadata と、作者の訂正・却下を local に記録する（送信先・保存範囲は広げない）。
- 設計で先に潰すリスク
  - 今の Scene より後の出来事を引かないこと（ネタバレ防止）
  - `QUERY_SOURCE_CHANGED` が守る query source の契約の変更
  - 送信内容の拡大が既決定で覆えるか
  - 全文を送る場合との費用の比較

## 追記：設計案の問いへの回答（2026-11-08、ユーザーの返答の逐語）

返答：「1,ok 2,ok 3,これは流石に何かしら試験して決めた方が良くないですか？ 4,単純にAgentがtool callを使い分けるんじゃないかなと思ってるんですがどうでしょうか？」

1. **IR の要約と quote を、今の chat と同じ送信先へ送ってよい（承認）。** 新しい送信先は作らない。restricted のプロファイルでは足さない（設計案のとおり）。
2. **使った IR の ID と、作者の訂正・却下を local に保存してよい（承認）。** 外部へ送らない。
3. **弱い hit を落とす閾値は、試験で決める。** pilot の 79 問から決めることはしない。事前登録 1.2 の例外は作らない。
4. **IR を足すかどうかは、agent が tool call で使い分ける形を主に検討する。** 製品の chat の agent モードには、既に `search_events` などの tool がある。

1・2 は、この機能を実装するときの送信先と保存範囲の承認。実装と、閉じた経路を開ける判断は、引き続き PUB-G の前提の後に確認する。
