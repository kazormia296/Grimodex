## 4. 本測定の手順（B のみ）

1. ユーザーへ、件数・費用・宛先を示した最終の確認を 1 問出す（B1 の前に。B2 の前にも、B1 の結果を示して別に出す）。承認の範囲だけを送る。
2. 他の lane と窓を調整する（cargo・Electron を避ける。3 分前に連絡）。出所の記録を HEAD で取り直し、乾いた実行（送信なし）を回して、4 作品とも ok を確かめる。
3. `launch-measure-b.mjs`（本物の session の shell で。`--mode b1`、承認の後に `--mode b2`。`--confirm-send yes-send-to-anthropic`、`--egress-allow`・`--egress-resolver` は 3.5）。
4. `aggregate.mjs`。records は repo の外（`/home/grimodex/identity-review-load-2026-11`）に置き、repo には件数だけを書く。混入走査 0 件。
5. 試走から本測定まで枝を動かさない（D5）：B1・B2 が終わるまで、master を取り込まない。結果は、この記録の commit と、各 script の sha256（上）を添えて報告する。作者への報告は「値を並べるだけ」。

## 5. 規則（§14 の 5・6）

- 凍結後の変更は**逸脱**として、件数と理由を記録する。**名簿は測定の後に直さない。**途中で止めた範囲の結果は採点しない。
- 閾値・上限・停止線・判断不能の条件は、結果を見た後に緩めない。
- **結果として採用するのは、その段の cell がすべて ok のときだけ**（B1＝16 cell、B2＝4 cell）。1 つでも rejected・failed・未実行・停止があれば、その段は**未完了**として件数・理由・費用を記録し、結果として報告しない。
- 失敗した cell（rejected・failed）は結果として採点せず、**費用を含めて**記録し、原因が**環境**か**道具**かで分ける。
  - **環境起因**（他の process との重なり、Playwright の一過性の失敗など。道具の file は変えない）：同じ commit・同じ入力・同じ定義で、その cell だけ回し直してよい（再送で費用が掛かる。予備 $2 から出し、回数・理由・費用を記録する。作者の承認した送信の範囲と上限の内）。
  - **道具の欠陥**（道具の file〔3.7〕を変えないと直らない）：直した版は凍結済みの道具ではない。結果を見る前に、直した道具の sha256 を載せた新しい凍結の記録（第 2 稿）を commit し、その段の cell を全部回し直す（作者へ再確認）。旧い run の値は採用しない。
- 停止線に当たった・台帳が STOP を立てた場合は、**実測を示して作者に伺う**（続けるか、基準を取り直すか）。伺う前に STOP を解除しない。
