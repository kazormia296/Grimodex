## 4. 本測定の手順（A のみ）

1. 他の lane と窓を調整する（cargo・Electron を避ける。3 分前に連絡）。
2. build を取り直し（`pnpm napi:build`・`node electron/scripts/build.mjs`）、`record-build-provenance.mjs`（clean な HEAD）。
3. `run-inventory.mjs --mode inventory`（4 作品）→ 候補の file を 3.2 と照合（違えば逸脱）。
4. `run-measure-a.mjs`（4 作品。35 cell。`--persist try`）。
5. `aggregate.mjs`。records は repo の外（`/home/grimodex/identity-review-load-2026-11`）に置き、repo には件数だけを書く。混入走査 0 件。
6. 結果は、この記録の commit と、各 script の sha256（上）を添えて報告する。

## 5. 規則（§14 の 5・6）

- 凍結後の変更は**逸脱**として、件数と理由を記録する。**途中で止めた範囲の結果は採点しない。**
- 閾値・上限・判断不能の条件は、結果を見た後に緩めない。
- 失敗した cell（rejected・failed）は、結果として採点せず、件数と理由を記録して原因を直し、同じ入力と定義で回し直す（回し直しの回数も記録する）。
