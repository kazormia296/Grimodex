## 5. 規則（§14 の 5・6）

- 凍結後の変更は**逸脱**として、件数と理由を記録する。**途中で止めた範囲の結果は採点しない。**
- 閾値・上限・判断不能の条件は、結果を見た後に緩めない。
- **結果として採用するのは、35 cell がすべて ok のときだけ**。1 つでも rejected・failed・未実行があれば、その集計は**未完了**として件数と理由を記録し、結果として報告しない（途中の表を「結果」として並べない。参考として出すなら、「未完了」と印を付けて別に書く）。
- 失敗した cell（rejected・failed）は、結果として採点せず、件数と理由を記録して、次のように扱う（原因が**環境**か**道具**かで分ける）。
  - **環境起因**（他の process との重なり、window の不足、一時的な起動失敗など。道具の file は変えない）：同じ commit・同じ入力・同じ定義で、その cell だけ回し直してよい。回し直しの回数と理由を記録する。
  - **道具の欠陥**（道具の file〔§3.5 の sha256 の対象〕を変えないと直らない）：道具を直した版は**凍結済みの道具ではない**。直した版の結果を、この凍結の結果として採用しない。**結果を見る前に**、直した道具の sha256 を載せた**新しい凍結の記録**（第 1 版・A の第 2 稿）を commit し、**35 cell を全部回し直す**。旧い run の値は採用せず、件数と理由だけを逸脱として残す。
