## 0. 何を決める案か

/1 の C5 は、確度が「不明」の出来事を、生死の導出の対象から外す。そのため、誕生が分かる人物の死亡の出来事の確度が「不明」だと、死亡が無いのと同じになり、どの場面でも AI に「存命」と渡る。これを、その死亡の仮の日以後の場面（日時が無い死亡なら、誕生の後のどの場面でも）では「不明」にする。

## 1. 確かめた事実

- 生死の導出は 2 か所にある。アプリ内の AI 向けの `deriveCharacterStateAt`（`electron/shared/readDomain/features/chronicle/chronicleSnapshot.ts`）と、MCP の `derive_character_state_at`（`src-tauri/crates/grimodex-mcp/src/chronicle_snapshot.rs`）。どちらも、確度が「不明」の誕生・死亡の出来事を飛ばし、誕生が現在地以前で、使える死亡が現在地以前に無ければ「存命」にする。【読んだ】
- 生死の値「不明」は、今もある（誕生が分からないとき）。自動のまとめには「名前: 不明」と出て、年齢は出ない。道具と MCP の返り値にも同じ値が入る。【読んだ】
- 確度が「不明」として扱う死亡の出来事は、次のものである。作者が確度を「不明」にしたもの。移行（版 49）が日時を入れた、日時の無かったもの。抽出の取り込みで Native が日時を入れたもの（/1 の G6。取り込みは今は閉じている）。取り消しや復元で戻った、日時の無いもの（/1 の B1）。日はあるのに粒度が空の行（2026-07-29 より前の版の AI・MCP の作成で起きうる。移行が粒度を直す。移行の後に、移行前の状態を復元すると残る）。【読んだ】

## 2. 規則

用語：「確かな死亡」は、その人物が主な人物の、種類が「死亡」の出来事で、日時があり、確度が「確定」か「おおよそ」のもの。「不明の死亡」は、同じく種類が「死亡」で、確かな死亡でないもの。「日時がある」は /1 のとおり（開始の日があり、粒度が「なし」でない）。

- **L1**　「故人」の判定と、年齢の計算に、不明の死亡は使わない。出生の出来事の扱いは /1 の C5 のまま（確度が「不明」の出生は使わない）。
- **L2**　誕生が分かり、現在地が誕生以後の人物は、次の順で決める。
  1. 確かな死亡が 1 件でもあれば、確かな死亡だけで、今と同じに決める（最も早い確かな死亡の日が現在地以前なら「故人」、後なら「存命」）。不明の死亡は見ない。
  2. 確かな死亡が無く、次のどちらかの不明の死亡が 1 件でもあれば、「不明」にする。(a) 日時の無いもの。(b) 日時があり、その仮の開始の日が現在地以前のもの。
  3. それ以外は「存命」にする（不明の死亡が無い人物と、不明の死亡の仮の日が全部現在地より後の人物）。
- **L3**　L2 の 2 で「不明」にした人物の年齢は、「存命」のときと同じく、現在地の年齢を渡す。
- **L4**　不明の死亡には、日時の無い死亡と、日はあるのに粒度が空の死亡も数える。どちらも /1 の定義で「日時が無い」ので、L2 の 2 の (a) に当たる。
- 変えないもの：誕生が分からない人物は「不明」（年齢なし）。現在地が誕生より前の人物は「未誕生」。現在地が決まらないときは「不明」。「故人」の人物の年齢。整合の検査（因果、二か所に同時に居る、年齢、季節）、出来事の前後、「作中の現在地」、画面の表示。アプリ内の道具の説明文。

## 3. 残る制限（/1 の §3 の該当の項を置き換える）

- 今（切り替えの前）との差：作者が確度を「不明」にした日付つきの死亡しか無い人物は、その日以後の場面で、今は「故人」で年齢は死亡の時点で止まる。この案の後は「不明」で、年齢は場面ごとに増える。仮の日より前の場面は、今もこの案の後も「存命」である。
- 日時のある不明の死亡しか無い人物は、仮の日より前の場面では「存命」と渡る。仮の日は当てにならないので、実際の死より後の場面で「存命」と渡ることや、死より前の場面で「不明」になることがある。作者が、死亡の出来事の確度を「確定」か「おおよそ」に直すと、日で「故人」か「存命」を決める。
- 版を上げる前から日時が無かった死亡の出来事には、移行が、その時点で日時のある出来事と、保管していない場面の作中日付の、最も後の日の翌日以降の仮の日を入れる。そのため、移行の時点にある日付の場面では、今と同じ「存命」のままである。現在地が仮の日以後になる場面（移行の後に後の日付を足した場面など）だけが「不明」になる。
- 「不明」でも年齢を渡すので、AI が存命と受け取る手がかりになりうる。
- 「不明」の理由を示す欄は無い。死亡が不確かな「不明」には年齢が付き、誕生や現在地が分からない「不明」には付かないので、AI が年齢の有無から区別できることがある。
- 取り消しや復元で日時の無い死亡が戻った人物は、確かな死亡が無ければ、次にその出来事を変えて日時を補うまで、誕生の後のどの場面でも「不明」になる。
- 確度が「不明」の出生の出来事だけを持つ人物は、今までどおり（/1 のまま）「不明」である。
- 英語の自動のまとめは、`alive` が `unknown` になる分、少し長くなり、長さの上限で行を縮める境目が動くことがある（日本語の文字数は同じ）。

## 4. 脅威モデル

変えない。actor、受け手、保存先、送信先、権限を足さない。渡る生死の値は、今ある 4 つ（存命、故人、未誕生、不明）のどれかで、欄を足さない。

## 5. 受入れ

- アプリ内の AI 向けと MCP が、同じ共有の例（`src/features/chronicle/fixtures/chronicle-snapshot/`）で、同じ値を返す。
- 次の例を固定する：日時のある不明の死亡が現在地以前（「不明」、年齢あり）と、後（「存命」）。確かな死亡と不明の死亡の両方（確かな死亡で決まる）。日時の無い死亡と、粒度が空の死亡（「不明」、年齢あり）。不明の死亡が無い人物（今と同じ値と年齢）。誕生より前の場面（「未誕生」）。
- 起動時の JS が上限を超えるときは、CI の実測に 256 byte を足した値まで、独立した commit で上げる（確認 164。この直しに限る）。
