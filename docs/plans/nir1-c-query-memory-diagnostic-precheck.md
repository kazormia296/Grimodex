Threat boundary: a disposable local preseed DB and explicit seed/query IDs only; SQLite and Rust allocation are measured, not rejected under a newly invented authority. Stored corrupt JSON and large inputs may consume resources: bound CLI input, use existing Graph admission/deadline/cancel, child process timeout and disposable DB. No external egress, background daemon, provider invocation, product IPC or migration. The original DB is not mutated; manuscript, credentials and Source bodies never enter reports. No `PASS` label for unmeasured SQLite heap, other process allocation, concurrent product requests, RSS, or any input outside the fixture set.

| Entry / finite owner | Admission, cancel, termination evidence, restart state |
| --- | --- |
| Explicit CLI start | One invocation, no automatic retry, reentrancy or scheduler. Require explicit fixture DB copy, project, query Scene and seed, reject invalid/unknown input before query. Preparation/registration is reported separately, never counted as query-only memory. |
| Dedicated Graph reader | Existing Native-internal owner and workspace participant hold the read-only connection and registration; fail closed if no sealed generation. | CLI and process termination | A caller-owned finite process timeout covers setup/query/cleanup; timeout kills the process and is a failed/incomplete diagnostic, not evidence of successful cleanup. Normal success requires closed reader, bounded structured report, and exit code 0. Crash, cancellation, incomplete registration or allocation-measurement failure yield no success receipt. Only the explicitly requested report remains on disk; no persisted grant or auto-resume. |

Accept only a positive real registered query, N/N+1 admission and malformed/oversize/cancel cases as **observations** with fixture/base/model/toolchain IDs, query status, wall/cleanup time and two memory domains. Never sum two observed peaks as a universal hard proof. To assert the confirmed 2 MiB product bound requires a separately approved enforcement/coverage design and additional evidence; that approval is not implied by this diagnostic.
