# C2-ZC Canonical Freshness Cutover Impact Matrix

This matrix records the implemented but **unaccepted** C2-ZC foundation.  The
feature remains a main/N-API/shared-Rust maintenance seam; renderer and
preload do not gain a cutover or scheduler-maintenance surface.  An ordinary
Freshness wake runs a bounded cycle and may mint liveness evidence, but it
does **not** write the C2-ZC marker or switch canonical authority.  The
explicit activation boundary remains blocked in the roadmap until its separate
acceptance evidence exists.

## Authority decision

The durable authority marker is owned by the schema migration module, while a
future explicit C2-ZC decision is owned by shared Rust.  The live scheduler
proof is not a free-form timestamp: the N-API call obtains the current
main-process authority binding and shared Rust mints/registers the receipt
only from a cycle capability for that exact SQLite authority.  A future
cutover may accept that receipt only while its exact authority/generation,
connection epoch, scope, and monotonic age remain current; the consumed cycle
capability itself must also still be within that liveness bound.  This keeps the
marker durable without making it a second Freshness authority and keeps
restart/swap recovery fail closed; it does not authorize ordinary wakes to
perform the irreversible switch.
