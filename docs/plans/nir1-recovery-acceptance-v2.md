# NIR-1 応答性とバックグラウンド再構築の受入れ

版: `nir1-recovery-acceptance/2`。状態: **2026-09-09 ユーザー明示承認済み**。

ユーザーは、旧結果の失効と新しいIRの再生成を分け、400回・p95 2秒を必須gateとする基準を見直した。
本書は[統合実装計画](narrative-ir-nir1-implementation-plan.md)と[A5候補2](nir1-a5-candidate-2.md)の
incremental recoveryの受入れ条件だけを更新する。初回の固定manifestと過去の測定記録は履歴として保持する。
現在の機械可読契約は `evals/nir1-retrieval/acceptance-policy-v2.json` とする。

| 対象                           | 必須条件                                                                                                                 | 時間の扱い                                                          |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------- |
| 開く・編集する・検索結果を返す | IR再構築を利用開始の前提にせず、応答性を維持する                                                                         | 利用者が操作できるまでを優先して測る。検索の既存B/D予算は維持する   |
| 古い根拠・撤回済み結果         | 変更に応じて直ちに無効化し、表示・再利用・Evidence移動で旧資格を使わない                                                 | 新Indexの完成を待たずに失効させる                                   |
| 新しいIR検索結果               | バックグラウンドで再構築し、その間もRaw検索を利用できる。再公開時はcurrent・承認・Freshness・Scope・Evidenceを再確認する | 再生成2秒は改善目標。p95 2秒未達だけで受入れを止めない              |
| バックアップ復元               | 正確な復元、進捗表示、失敗時の回復、公開前の旧資格失効を重視する                                                         | 2秒を適用しない。復元時間と開いて書き始められるまでを分けて記録する |

各変更種別の正しさ、旧資格の失効、Rawの利用継続、再公開の資格確認は、既存の契約テストと
対象を絞った実製品journeyで検証する。100 current revisionのfixtureは負荷診断用として維持するが、
各種100回・合計400回の反復やそのp95算出を必須条件にしない。任意の性能診断では試行数・並列数・
負荷条件・失敗・timeoutをすべて記録し、未測定と不合格を成功へ読み替えない。

固定corpus・Gold・モデル・順位規則・B/D/T、検索時の開示境界は変更しない。
`nir1-product-tm/1` の信頼主体、禁止情報、必須防御も変更しない。過去の400回campaignや失敗receiptを
新基準で合格へ書き換えず、この承認差分と現在の機能証拠を別に記録する。
