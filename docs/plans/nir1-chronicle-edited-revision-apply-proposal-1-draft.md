## 0. 一枚目：推奨と残る問い

**何を決める案か。** 今の製品では、作者が review で編集した年表の提案は、年表に取り込めない。編集して承認した提案が 1 件でもあると、その組の取り込みは全体が失敗する。この案は、編集した版を取り込めるようにする。

**推奨**
1. 取り込みは、作者が編集した版を受け付ける。条件は、その版から AI が出した最初の版まで、1 段ずつ系譜を確かめられることである（E2）。
2. 系譜の確かめ方は、関連場面の資格がすでに使っている検証を使う。AI の出力の裏付け（受領書と文脈）は、最初の AI の版に対して、今の取り込みと同じ検査で確かめる（E3、E5）。材料が今も同じかは、取り込む版で確かめる（E4）。新しい種類の検査は作らない。
3. 受け付ける編集は今と同じ 4 項目（題、メモ、secret、reveal の場面）で、広げない。
4. 年表の出来事は secret で作る（CAS/1）。

**この案で通るようになるもの**
- 題やメモを直して承認した提案を含む組の取り込み。
- secret を外した提案を含む組の取り込み。「まとめて承認」で関連場面に出した提案が、年表にも入る。

**作者に見える制限が 1 つ残る**（§3）：secret のまま reveal を別の場面に変えた提案は、その後に場面を足したり並べ替えたりすると、取り込めなくなる。

**残る問い**（§7）：★1 規則と脅威モデル、★2 残る制限の扱い、★3 実機の検査の追加。

## 1. 確かめた事実

**今の制限**
- 取り込みは、版の Envelope（版 2）の `revisionBasis.kind` が `interpretation`（AI が出したままの版）でなければ `NEX_V2_APPLY_BASIS_UNSUPPORTED` で拒む（`src-tauri/crates/grimodex-db/src/narrative_extraction/v2_apply_sources.rs:17-24`）。準備でも実行でも掛かる（`commit.rs:575`、`:1677`、`:874`）。【確認済み】
- 作者の編集の保存は、現行の抽出の形式（Envelope の版 2）では、必ず編集した版（`human-derived`）を作る（`src/features/chronicle/chronicleExtractionApi.ts:1883-1889`）。【確認済み】古い形式では Envelope の無い版になり、別の検査で取り込めない。【報告】古い形式はこの案の対象外である。
- 取り込みの対象は、承認済みの現行の版のちょうど全部である（`commit.rs:2724-2733`）。【確認済み】
- 拒否の検査を外すだけでは通らない。AI の版にしか無い項目を必須にする検査が 3 箇所ある：受領書の照合（`stage_provenance.rs:1570-1575`）、文脈の一覧（`v2_apply_sources.rs:186`）、部品の契約の digest（同 `:229-233`）。【確認済み】
- この制限は #566（2026-09-07）で入った。理由は PR にも文書にも書かれていない。当時の計画は「人の編集は、取り込みの時の照合を迂回しない」と書いていて、人の編集した版も取り込みを通る前提だった（`docs/plans/narrative-ir-nir0-implementation-plan.md:1079`）。【報告】
- 年表以外（人物、伏線、プロット）の取り込みは別の経路で、この制限に当たらない。【報告】

**編集した版の形**
- 受け付けられる編集は、題、メモ（表示だけの変更）と、secret、reveal の場面（開示に関わる変更）の 4 項目だけである。ほかの項目の変更は、版の作成で拒まれる（`src-tauri/crates/grimodex-core/src/narrative_ir.rs` の `classify_chronicle_scene_event_changes`）。【確認済み】根拠、起こり方、重要度は編集できない。
- 編集した版の Envelope は、親の版の id、最初の AI の版の id、親の Envelope の digest を持つ。文脈の一覧は親のものを写し、どの版から受け継いだかを付ける。開示に関わる変更では、scope の解決の文脈を 1 件足す（`human_derivation.rs:497-534`）。【確認済み】
- 開示の項目を 2 回以上編集すると、scope の解決の文脈が同じ id で一覧に 2 件以上並ぶ。材料の側は、古い scope の材料を落として新しいものに置き換える（`human_materialization.rs:525`、`:579`）。【確認済み】
- 今の取り込みの文脈の検査は、同じ id の文脈が 2 件あると拒む（`v2_apply_sources.rs:192-195`）。【確認済み】このため、編集した版の文脈の一覧を今の検査にそのまま掛ける形は取らない（E5）。
- 開示に関わる変更をした版は、材料が 1 件多い（scope の投影）。この材料の token は、版が secret のとき reveal の場面の並びの順位を含み、非 secret のとき含まない（`grimodex-core/src/narrative_scope_dependency_projection.rs:112-144`）。【確認済み】

**すでにある検証**
- 関連場面の資格は、選んだ版から最初の AI の版までさかのぼり、1 段ごとに「親から作り直した期待の Envelope」と子の Envelope が一致することを確かめる。循環、提案・組・抽出の一致、版の順、最初の版の id も見る（`material_membership/lineage.rs:167-262`）。【確認済み】この検証は読み取りだけで、今の場面の並びには依存しない。取り込みの処理の中から呼べる。【報告】今は関連場面の資格の側からだけ呼べる（可視性）。【確認済み】
- 受領書の照合は、渡した Envelope の項目で行う。最初の AI の版の id と Envelope を渡せば、今の AI の版の取り込みと同じ検査になる。【報告】

## 2. 規則

- E1. 取り込みは、`revisionBasis.kind` が `interpretation` の版に加えて、`human-derived` の版を受け付ける。`changeIntent.changeKind` は `add` だけのままとする。
- E2. `human-derived` の版を受け付ける条件は、系譜の検証（§1）が、その版から最初の AI の版まで通ることである。通らなければ、取り込み全体を拒む。
- E3. 受領書の照合は、最初の AI の版に対して行う（今の AI の版の取り込みと同じ検査）。
- E4. 材料の今の値との照合は、取り込む版自身の材料で行う。根拠の場面の本文や、その版の scope の投影が変わっていれば、今と同じく拒む。
- E5. 文脈と依存の対応の検査（今の取り込みの検査）は、最初の AI の版の Envelope と、その版自身の材料に対して行う（取り込む版の材料を渡さない）。編集した版の文脈と依存の形は、系譜の検証（親から作り直した形との一致）で確かめる。編集した版の文脈の一覧に、取り込みで別の検査を足さない。
- E6. 取り込む操作は、取り込む版から Native が組み立て直して照合する（今と同じ）。題、メモ、reveal の場面は編集後の値、出来事は secret で作る（CAS/1）。
- E7. 受け付ける編集の項目は広げない。版の種類がどちらでもないものは拒む。
- E8. この規則が入ったら、表示の暫定の案内（PR #857 の「編集した提案があるため、この組は年表に取り込めません」）を外す。E4 で拒まれたときの案内に置き換える（§3）。

## 3. 変わるもの、変わらないもの、残る制限

| 経路 | 変わるか |
| ---- | -------- |
| AI が出したままの版の取り込み | 変わらない |
| 編集した版を含む組の取り込み | 変わる。通るようになる。編集の回数は問わない |
| 取り込みの取り消し、やり直し | 出来事は記録した値から戻す作りで、版の種類に依存しない【報告】。取り込みの記録が持つ依存の片付けは未確認（§8） |
| 取り込みの記録の鮮度 | 開示に関わる変更をした版から取り込むと、取り込みの記録の依存に scope の投影が 1 件加わる。記録が古くなる条件が、その分だけ増える。古くなったときの製品の挙動は未確認（§8） |
| 関連場面の資格と索引 | 変えない。取り込みは資格を変えない（PR #858 の試験） |
| 年表から AI への秘密、Graph の本文の開示の拒否 | 判定は変えない。編集した版から取り込んだ出来事は secret で入る。secret を外した提案の出来事が関わる場面では、Graph の本文の開示が拒否される（CAS/1 の ★2 で確認済みの代償。この規則で初めて生じる） |
| 評価の harness（CP-4、IR の評価） | 変わらない。取り込みを呼ばない |
| 人物、伏線、プロットの取り込み | 変わらない |

**残る制限。** 開示の項目（secret か reveal）を変えた版は、scope の投影を材料に持つ。この材料が変わると E4 で拒まれ、その版を含む組は取り込めなくなる。変わるのは次のときである。

- secret のまま reveal を別の場面に変えた版：その後に場面を足したり並べ替えたりして、reveal の場面の順位が変わったとき（secret の版の投影は、reveal の場面の並びの順位を含む）。
- 開示の項目を変えた版のすべて（secret を外した版を含む）：reveal の場面か根拠の場面を消したとき。scope の語彙の契約の版が変わったとき（製品の更新のときだけで、作者の操作では変わらない。`scene_scope.rs:102` の定数）。【確認済み】

直すには、その提案の開示の項目を別の値に編集し直す。同じ値のまま保存し直しても直らない（差分の無い保存は、古い材料を受け継ぐ）。同じ状態に戻したいときは、2 回の編集（変えて、戻す）になる。secret を外した版と、AI が出したままの版は、場面の並びでは古くならない。根拠の場面の本文が変わった場合は、どの版でも抽出のやり直しが要る（今と同じ）。

外部への送信、subprocess、背景の処理、非同期の lifecycle、保存先、IPC は変えない。

## 4. 脅威モデル（draft）

- **信頼する actor**：Native の backend、作者の承認の記録、Native が封印した AI の版と受領書。
- **信頼しない actor**：画面側が出す操作の内容と版の指定、model の出力、古い画面。
- **範囲内の攻撃と誤り**
  - Native の版の作成を通らない版、4 項目の外を変えた版、親の digest が合わない版、親や最初の版を差し替えた版を取り込ませる。
  - 受領書の無い版を、最初の版として系譜に置く。
  - 根拠の場面の本文が変わった後の版、scope が変わった後の版を取り込む。
  - 承認されていない版、現行でない版を取り込む。
  - 非 secret の出来事を作る操作を出す。AI の版の secret を画面側で外して保存し、同じ値の操作を出す場合を含む（AI の版の secret が true であることは、Native は保証していない。CAS/1 の検査が、操作の側で塞ぐ）。
- **範囲外**
  - 画面側が、4 項目の範囲で版を作り、承認まで進めること。版の作成と承認は画面側が呼ぶ入口で、Native は人が操作したことを証明できない。今の AI の版の承認と同じく、承認の記録を信頼する。
  - OS や backend の乗っ取り、作者が自分で行う編集と承認、年表の画面での手動の編集、外部への送信。
- **必須の防御**
  - 系譜の検証を、最初の AI の版まで 1 段ずつ行う（E2）。新しい緩い検証を作らず、関連場面の資格と同じ検証を使う。
  - 受領書の照合と、文脈と依存の対応の検査を、最初の AI の版に対して行う（E3、E5）。
  - 材料の今の値との照合を、取り込む版で行う（E4）。
  - 受け付ける編集を 4 項目に限る検査（版の作成の検査と、系譜の検証の中の再分類）を保つ（E7）。
  - 承認の束縛と操作の組み立て直しの照合（今ある検査）を、編集した版にも同じに掛ける（E6）。
  - 出来事は secret で作る（CAS/1 の検査）。
- **受入れへの影響**
  - 正例：題を直して承認した提案、secret を外して承認した提案、開示の項目を 2 回編集した提案を含む組が取り込める。出来事の題と reveal は編集後の値で、secret である。取り消しとやり直しができる。取り込みの後も、関連場面の資格は変わらない。
  - 負例：系譜のどこかを崩した版、親の digest が合わない版、受領書の無い最初の版、根拠の本文が変わった版、並び替えの後の secret のまま reveal を変えた版、承認の無い版は、取り込み全体が拒まれ、年表に出来事は作られない。漏れの許容は 0 とする。

## 5. 実装の見立て（確認なしで決める技術判断を含む）

- `ensure_supported_intent` を、版の種類が 2 つのどちらかで、変更の種類が add であることの検査に改める。
- 取り込みの材料の読み込み（`load_v2_apply_sources_with_control`）を、版の種類で分ける。編集した版では、系譜の検証 → 最初の AI の版での受領書の照合と文脈の検査（最初の版の Envelope と、その版自身の材料で） → 取り込む版の材料の照合、の順に行う。
- 系譜の検証を、取り込みから呼べる入口にする（可視性の変更か、薄い入口の追加）。最初の版の材料の再生は呼ばない。再生は、区切り（window）が 1〜2 でない抽出では未実装で（`material_roster/replay.rs:109-111`）、取り込みの可否を再生に結び付けないためである。関連場面の資格は再生も要求するので、この点で資格の検証と同じ強さではない。今の AI の版の取り込みと同じ強さである。
- 系譜の検証のエラーには `NEX_` のコードが無い。取り込みのエラーコードへの写し方を決める。
- 今の制限を固定している試験（PR #858 の `current_limit_human_derived_revision_is_refused_by_chronicle_prepare`、`v2_apply_sources.rs` の単体の試験）を、「通る」に書き換える。関連場面の資格の試験を、本物の取り込みに置き換える。開示の項目を 2 回編集した版の試験を足す。
- 高リスクの変更（Native の取り込みの検証）なので、実装と独立の受入れレビューを分ける。
