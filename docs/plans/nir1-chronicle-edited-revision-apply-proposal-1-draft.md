## 0. 一枚目：推奨と残る問い

**何を決める案か。** 今の製品では、作者が review で編集した年表の提案は、年表に取り込めない。編集して承認した提案が 1 件でもあると、その組の取り込みは全体が失敗する。この案は、編集した版を取り込めるようにする。

**推奨**
1. 取り込みは、作者が編集した版を受け付ける。条件は、その版から AI が出した最初の版まで、1 段ずつ系譜を確かめられることである（§2 E2）。
2. 確かめ方は、関連場面の資格がすでに使っている系譜の検証を使う。新しい検証の規則は作らない。
3. 受け付ける編集は今と同じ 4 項目（題、メモ、secret、reveal の場面）で、広げない。
4. 年表の出来事は secret で作る（CAS/1）。

**この案で通るようになるもの**
- 題やメモを直して承認した提案を含む組の取り込み。
- 「まとめて承認」で secret を外した提案を含む組の取り込み。関連場面に出した提案が、年表にも入る。

**残る問い**（§7）：★1 規則と脅威モデル、★2 実機の検査（journey）の追加。

## 1. 確かめた事実

**今の制限**
- 取り込みは、版の Envelope の `revisionBasis.kind` が `interpretation`（AI が出したままの版）でなければ `NEX_V2_APPLY_BASIS_UNSUPPORTED` で拒む（`src-tauri/crates/grimodex-db/src/narrative_extraction/v2_apply_sources.rs:17-24`）。準備と実行の両方で、取り込む全件に掛かる（`commit.rs:300`、`:1033`、`:874`）。【確認済み】
- 作者の編集の保存は、必ず編集した版（`human-derived`）を作る（`src/features/chronicle/chronicleExtractionApi.ts:1883-1889`）。【確認済み】
- 取り込みの対象は、承認済みの現行の版のちょうど全部である（`commit.rs:2724-2733`）。【確認済み】
- 拒否の検査を外すだけでは通らない。AI の版にしか無い項目を必須にする検査が 3 箇所ある：封印の受領書の照合（`stage_provenance.rs:1570-1575`）、文脈の一覧（`v2_apply_sources.rs:186`）、部品の契約の digest（同 `:229-233`）。【確認済み】
- この制限は #566（2026-09-07）で入った。理由と、後で編集した版を扱う予定は、PR にも文書にも書かれていない。ADR 011 は、年表の試行を「追加（add）だけ」に絞ると書く（`docs/adr/011-narrative-ir-revision-semantics-contract.md:94-99`）。【前半は報告、後半は確認済み】
- 年表以外（人物、伏線、プロット）の取り込みは別の経路で、この制限に当たらない。【報告】

**編集した版の形**
- 受け付けられる編集は、題、メモ（表示だけの変更）と、secret、reveal の場面（開示に関わる変更）の 4 項目だけである。ほかの項目の変更は、版の作成で拒まれる（`src-tauri/crates/grimodex-core/src/narrative_ir.rs` の `classify_chronicle_scene_event_changes`）。【確認済み】根拠、起こり方、重要度は編集できない。
- 編集した版の Envelope は、親の版の id、最初の AI の版の id、親の Envelope の digest を持つ。文脈の一覧は親のものを写し、どの版から受け継いだかを付ける。【確認済み（評価 DB）】
- 編集した版が参照する文脈は、その版の文脈の一覧にすべてある（評価 DB の 884 件のすべて）。【確認済み】
- secret か reveal を変えた版だけ、材料が 1 件多い（scope の投影）。取り込みの材料の解決器は、この種類を扱える（`source_revision.rs:200`）。【確認済み】

**すでにある系譜の検証**
- 関連場面の資格は、選んだ版から最初の AI の版までさかのぼり、1 段ごとに「親から作り直した期待の Envelope」と子の Envelope が一致することを確かめる。循環、提案・組・抽出の一致、版の順、最初の版の id も見る（`material_membership/lineage.rs:167-262`）。【確認済み】
- この検証は、今は関連場面の資格の側からだけ呼べる（可視性）。【確認済み】

**取り込みのほかの段**
- 承認の束縛、操作の組み立て直し、取り込みの記録、依存の辺、取り消しは、版の種類に依存しない。【報告】

## 2. 規則

- E1. 取り込みは、`revisionBasis.kind` が `interpretation` の版に加えて、`human-derived` の版を受け付ける。`changeIntent.changeKind` は `add` だけのままとする。
- E2. `human-derived` の版を受け付ける条件は、§1 の系譜の検証が、その版から最初の AI の版まで通ることである。通らなければ、取り込み全体を拒む。
- E3. 封印の受領書の照合は、最初の AI の版に対して行う（今の AI の版の取り込みと同じ検査）。
- E4. 材料の今の値との照合は、取り込む版自身の材料で行う。根拠の場面の本文や scope が変わっていれば、今と同じく拒む。
- E5. 文脈と部品の契約の検査は、編集した版の文脈の一覧と、最初の AI の版の契約の digest で行う。
- E6. 取り込む操作は、取り込む版から Native が組み立て直して照合する（今と同じ）。題、メモ、reveal の場面は編集後の値、出来事は secret で作る（CAS/1）。
- E7. 受け付ける編集の項目は広げない。版の種類がどちらでもないものは拒む。
- E8. この規則が入ったら、表示の暫定の案内（PR #857 の「編集した提案があるため、この組は年表に取り込めません」）を外す。

## 3. 変わるもの、変わらないもの

| 経路 | 変わるか |
| ---- | -------- |
| AI が出したままの版の取り込み | 変わらない |
| 編集した版を含む組の取り込み | 変わる。通るようになる |
| 取り込みの取り消し、やり直し | 変えない。編集した版から取り込んだ出来事にも同じに効く【取り消しは報告のまま】 |
| 関連場面の資格と索引 | 変えない。取り込みは資格を変えない（PR #858 の試験） |
| 年表から AI への秘密、Graph の本文の開示の拒否 | 判定は変えない。編集した版から取り込んだ出来事は secret で入る。secret を外した提案の出来事が関わる場面では、Graph の本文の開示が拒否される（CAS/1 の ★2 で確認済みの代償。この規則で初めて生じる） |
| 評価の harness（CP-4、IR の評価） | 変わらない。取り込みを呼ばない |
| 人物、伏線、プロットの取り込み | 変わらない |

外部への送信、subprocess、背景の処理、非同期の lifecycle、保存先、IPC は変えない。

## 4. 脅威モデル（draft）

- **信頼する actor**：Native の backend、作者の承認の記録、Native が封印した AI の版と受領書。
- **信頼しない actor**：画面側が出す操作の内容と版の指定、model の出力、古い画面。
- **範囲内の攻撃と誤り**
  - 画面側が、作者の編集を経ていない内容を、編集した版として取り込ませる（系譜の偽造、親の差し替え）。
  - 封印の受領書が無い版を、最初の版として系譜に置く。
  - 編集で、根拠や起こり方を差し替える。
  - 根拠の場面の本文が変わった後の版を取り込む。
  - 承認されていない版、現行でない版を取り込む。
  - 非 secret の出来事を作る操作を出す。
- **範囲外**：OS や backend の乗っ取り、作者が自分で行う編集と承認、年表の画面での手動の編集、外部への送信。
- **必須の防御**
  - 系譜の検証を、最初の AI の版まで 1 段ずつ行う（E2）。新しい緩い検証を作らず、関連場面の資格と同じ検証を使う。
  - 封印の受領書の照合を、最初の AI の版に対して行う（E3）。
  - 材料の今の値との照合を、取り込む版で行う（E4）。
  - 受け付ける編集を 4 項目に限る検査（今ある版の作成の検査と、系譜の検証の中の再分類）を保つ（E7）。
  - 承認の束縛と操作の組み立て直しの照合（今ある検査）を、編集した版にも同じに掛ける（E6）。
  - 出来事は secret で作る（CAS/1 の検査）。
- **受入れへの影響**
  - 正例：題を直して承認した提案、secret を外して承認した提案を含む組が取り込める。出来事の題と reveal は編集後の値で、secret である。取り消しとやり直しができる。取り込みの後も、関連場面の資格は変わらない。
  - 負例：系譜のどこかを崩した版、親の digest が合わない版、受領書の無い最初の版、根拠の本文が変わった版、承認の無い版は、取り込み全体が拒まれ、年表に出来事は作られない。漏れの許容は 0 とする。

## 5. 実装の見立て（確認なしで決める技術判断を含む）

- `ensure_supported_intent` を、版の種類が 2 つのどちらかで、変更の種類が add であることの検査に改める。
- 取り込みの材料の読み込み（`load_v2_apply_sources_with_control`）を、版の種類で分ける。編集した版では、系譜の検証 → 最初の AI の版での受領書の照合 → 取り込む版の材料の照合 → 文脈と契約の検査、の順に行う。
- 系譜の検証を、取り込みから呼べる入口にする（可視性の変更か、薄い入口の追加）。最初の版の材料の再生は呼ばない。場面が 3 つ以上の抽出では再生が未実装のため（`material_roster/replay.rs:109-111`）で、取り込みの可否を再生に結び付けない。【再生を呼ばずに系譜だけを検証できることは確認済み（`lineage.rs:167`）】
- 今の制限を固定している試験（PR #858 の `current_limit_human_derived_revision_is_refused_by_chronicle_prepare`、`v2_apply_sources.rs` の単体の試験）を、「通る」に書き換える。関連場面の資格の試験を、本物の取り込みに置き換える。
- 高リスクの変更（Native の取り込みの検証）なので、実装と独立の受入れレビューを分ける。
