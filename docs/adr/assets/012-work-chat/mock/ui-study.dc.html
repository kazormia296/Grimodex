TURN 8 · DISPOSITION / BLOCKED / BATCH

処分後の姿 / Blockedの全身像 / 一括承認

8a: Snooze/Hold/Dismiss後 — 処分済みは件数から除外するがレコードは削除しない（durable human state）。Trayの割り込み帯の下に折り畳みで住み、Snoozeは期限で自動再浮上、LEGACYは推測再割当しない。8b: BLOCKEDはATTNでなくSYSの事象 — 「壊れず、古くなるだけ」を明示し、再実行/INSPECT/Detach(不可逆・確認あり)を提供。8c: 安全なProposalの一括承認 — SAFE判定は決定的で条件を明文化、要個別判断は選択不可のまま残し、承認は1つのHuman Decisionとして記録。

8b Blocked — SYSドアの全身像 契約エラーの説明 + 再実行 / INSPECT / Detach。執筆は妨げない

TURN 7 · RESOLUTION MOMENT · EMPTY STATES

解消の瞬間 — 判断の結果として解ける

7a: Binding確定直後の1.5秒。ATTNは2→1の逆ビート（✓ −1ゴースト）、本文の注釈・外周フレーム・リーダー線は消え、アンカーは通常のCodexハイライトへ復帰。Lensシートは「何が確定し・何が記録され・何が再評価中か」の因果を示してから次へ誘導 — チェックを外す操作は存在せず、根拠が再び失われれば同じidentityで再浮上する。7b: Attention 0のTray — ATTENTION帯は「0件」と表示せず帯ごと消える（TasksがシステムFindingの人質でない証明）。FOCUS未設定は「—」、ATTN 0は薄いグレー。全消化時に祝祭は無い — 静けさが報酬。

7a Binding確定直後（ATTN 2→1） 注釈は消え、Lensは因果の受領証になる。SYS ◐=Freshness再評価中
7b Empty states — Attention 0 / Focus未設定 ATTENTION帯は帯ごと消滅。残るのはFocusの静かなリストだけ
TURN 6 · INTERRUPTION POLICY · 新規ATTENTIONの到着

TURN 5 · INCREMENTAL RE-INTERPRETATION · CHANGE REVIEW

変更レビュー — Proposal差分の視覚文法

Projectionの変種として設計（Work Graphで2件目のAttentionを選択した状態）。差分は無彩色のまま: 取り消し線=旧値、3px変更バー=新値、REMOVEDタグ=削除、「変更なし」は薄く残す（隠すと差分の範囲が疑わしくなる）。Evidence行は新旧を並記し、旧はMISSING・新はAnchor位置を付す。下部にREVIEW ACCEPTED·V1 / FRESHNESS SOURCE-MISSING / PROJECTION APPLIED·V1 — 「承認済み・根拠消失・適用済みが同時に成立する」三状態並記をレビューの前提として常設。操作はApply / 編集して適用 / Reject / 保留 + このMaterial Basisだけ無視 / Correction rule作成。右レールは「変更を引き起こした本文」と「適用した場合の影響」（Apply/Rejectそれぞれの帰結を明文化）。
