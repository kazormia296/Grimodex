## Context

### 1. 今の配置

今の場面に追随する情報は、本文をはさんで 2 か所に分かれている。

| 場所 | 中身 | 性質 |
| ---- | ---- | ---- |
| エディタのサイドペイン「シーン詳細」（本文の右） | 視点・場所・作中日付、適用範囲（Scope）、あらすじ・狙い、ビート | 作者が書く。AI の「生成」ボタンがある |
| Scene Context パネル（左の領域の下段） | 今の場面に出る Codex、関連する過去シーン | 読み取りと検索の結果 |

- サイドペインは既定で開いている。幅はエディタの 20%（15〜50%）である。閉じると、タブバーの下にチップ行（視点・場所・作中日付・あらすじ・ビート）が出る。【報告】
- Scene Context は、伏線・校閲と同じ枠に重なっていて、同時には見えない。【報告】
- 関連する過去シーンの案内「Scope を設定」は左下に出るが、Scope の欄はエディタの右のペインにある。押してもペインが開くだけで、既に開いていれば見た目は変わらない。【報告】
- 既定の配置（Write）では、左右の領域が先に幅を取る。計算では、エディタは 1280〜1920px のどの窓でも 412〜652px、サイドペインは 82〜130px である。【報告（計算値）】
- Scene Context を独立パネルにした理由と、左下に置いた理由は、設計書にも履歴にも残っていない。【報告】

### 2. ユーザーの決定（2026-11-21、原文）

- 「私は現行サイドペインと統合する方が良いと思っています。」
- 「SceneContext が左下に有る理由は特に無く、単純に最も初期の UI モックでそのシーンの Codex 一覧が配置されていたからに過ぎません。」
- 「今の SceneContext の幅は特に考慮する必要はありません。…全体のレイアウト比率自体も大体こんなもんだろうというもので、再考の余地が有ります。」
- 「SceneContext だけを見たい場面が存在しない」
- 「サイドペインへの統合と言うは Editor への統合と捉えてください。表現方法はサイドペインでなく、案 2 のようにエディタに下の領域を追加するのでも構いませんし、オーバーレイのみで表現するのでも構いません。今の状態に縛られることなく自由に考えてください。」
- 「A の承認ボタンは欲しい気がします。」

### 3. 統合する情報

1. 視点・場所・作中日付
2. あらすじ・狙い
3. ビート（未配置と配置済み）
4. 適用範囲（Scope）
5. この場面の解釈（新規。原稿から読み取った出来事の提案と、その根拠の引用）
6. 今の場面の Codex
7. 関連する過去シーン

## Decision

### 確認済み（D1〜D6）

**D1　場面の情報は、エディタの中に置く。** 対象は上の 7 種である。Scene Context を、独立のパネルとして残さない。

**D2　次のものを、設計の前提にしない。** Scene Context が左下にあること。今の Scene Context の幅。全体のレイアウトの比率。Scene Context だけを見る使い方。

**D3　チップ行を、常に出す。**
- 常に出すのは、視点・場所・作中日付・Scope の 4 つである。押すと、その場にピッカーが開く（今のチップと同じ）。
- あらすじ・ビートのチップは、統合ペインを閉じているときだけ出す。
- 統合ペインを閉じているときは、解釈・Codex・関連のチップも出す。件数を添え、押すと統合ペインがその中身で開く。

**D4　統合ペインは、今のサイドペインと Scene Context を合わせたものである。**
- 入れるもの：あらすじ・狙い、ビート、この場面の解釈、今の場面の Codex、関連する過去シーン。
- 入れないもの：視点・場所・作中日付と Scope。チップ行に移す。この 2 つだけで、ペインの高さを約 400px 使うためである（計算値）。

**D5　統合ペインを開いている間、1440px の窓では、シーン一覧を畳む。** 本文 480px と統合ペイン 400px を守ると、1440px の窓で左右の領域に残せる合計は 409px である（計算値）。シーン一覧・統合ペイン・チャットのうち、同時に開けるのは 2 つまでになる。

**D6　Work Layer との分担。**
- 統合ペインは、今の場面の分を、その場で 1 件ずつ判断する。承認・拒否・保留のボタンを置く。
- Work Layer（Work Pulse、Task Tray、Resolve）は、作品全体の件数と入口、まとめて処理、変更レビューを持つ。
- 承認の操作と、件数の数え方は、共通にする。
- 「解釈の状況」の画面（可視化の D 案）は、新しい画面にせず、Work Layer に吸収する。
- Resolve の一時パネルは、場面をまたぐ判断と、候補から選ぶ判断に使う。

### 提示した案のまま、異議が無かったもの（D7〜D9）

実装の前に、絵と実寸で確かめる。

**D7　統合ペインの中は、「計画」と「文脈」の 2 つのタブで切り替える。** 「計画」は、あらすじ・狙いとビート。「文脈」は、この場面の解釈、今の場面の Codex、関連する過去シーン。既定は「計画」である。「文脈」は、開くまで読み込まない。

**D8　統合ペインの幅は、400px 前後を px で持つ。** エディタが約 880px より狭いときは、同じ中身を本文の上に浮かせて出す。Esc か外側を押すと閉じる。

**D9　本文の上の印は、2 つだけにする。** 余白に、その段落に未確認の提案がある印。カードを選んでいる間だけ、根拠の文に地色と両端の棒。下線は使わない。本文の装飾は、波線＝直すべき問題、点線＝コメント、破線＝伏線、と割り当て済みである。

### 段取り（D10）

**D10　公開（PUB-G）の前に入れるのは、今のサイドペインに節「この場面の解釈」を足すところまでである（SRA/1）。** チップ行を常に出すこと、Scope をチップに移すこと、Scene Context パネルの撤去、左右の領域の既定の幅の見直しは、公開の後に行う。節は、既定で閉じていて、開くまで読み込まない。評価の測定がサイドペインごと mount するためである。

## 守ること

1. 作者が書いたもの（計画）と、読み取り・検索の結果（文脈）を、同じ見た目にしない。未確認の提案と、承認済みの解釈も区別する。色だけに頼らない。
2. 確認の状態、参照元の状態、年表への取り込みの状態は、別々の印にする。
3. 帰属の 3 色（人が書いた・AI・不明）を、確認の状態に使わない。
4. 「NIR」「IR」「Revision」という語を、画面に出さない。
5. 提案が届いても、ペインを自動で開かない。通知を出さない。フォーカスを動かさない。変わるのは件数だけである。
6. 縦書きでも成り立つこと。統合ペインは本文の横に置く。縦書きでは列の数が減るだけで、1 行の字数は減らない。
7. 関連する過去シーンの検索は、「文脈」が見えているときだけ走らせる。
8. 常に出ている領域を増やさない（ADR 012）。

## 比べて採らなかった方向

| 方向 | 形 | 採らなかった理由 |
| ---- | -- | ---------------- |
| 余白に沿う | ビートや解釈を、段落の横に並べる。場面全体の情報は、場面の頭に置く | エディタが約 856px より狭いと、カードを段落の横に置けない。余白の印だけを D9 に採った |
| 下の作業台 | 本文の下に、引き出せる横長の帯を足す | 縦書きで、1 行の字数が減る（約 41 字から 29 字。計算値）。2026-07 に不採用にした「下部ドロワー」に近い |
| 呼び出す | ふだんは本文とチップ行だけ。要るものを、その場に浮かせる | 狭い窓では、浮いた面が本文の半分以上を覆う。出したまま残す形は、ADR 012 の記録（本文を覆う重ね表示は採らない）と逆向きである。狭いときの出方として D8 に採った |
| 領域のパネルに集める | サイドペインをエディタから外し、Scene Context と合わせて領域に置く | ビートは、本文へのドラッグと結び付いている。2026-07 の決定（エディタの中の分割を維持）とも逆向きである |

## 未決（実装の前に決める）

- 左右の領域の既定の幅。今の既定（475px と 645px）では、どの窓でも統合ペインを横に置けない。
- Scene Context パネルの id（`codex-quick`）と、ショートカット（Mod+Alt+Q）の行き先。コマンド名 `focusCodexQuick` は、AI 向けの tool の定義に入っている。【報告】
- 分割したときの見え方。各エディタが半分の幅になるので、統合ペインはほぼ常に浮く形になる。出すのは、操作中の側の場面である。
- リニア編集モードでは、カーソルのある場面に追随し、見出しに場面名を出す。phone では、今と同じ全画面のシートに出す。phone に「文脈」が出るのは、新しい機能になる。
- 浮かせた形での、ビートのドラッグと、根拠の文の見え方。470px のエディタに 400px を浮かせると、本文は約 70px しか残らない。
- Scope をチップに移すと、「Scope を設定」の案内の飛び先について、記録済みの決定を改めることになる。保存のボタンと、解釈が失効する確認も、チップから開く面に入る。
- 縦書きのとき、統合ペインの中の引用は横組みになる。ルビと縦中横の扱い。
- 幅と高さの実測。本 ADR の数値は計算値である。

## Consequences

- `docs/Grimodex_Editorパネル設計書.md` と `docs/Grimodex_SceneContextパネル設計書.md` を、実装のときに改める。
- サイドペインの幅の設定（今は「エディタの何 %」）を、px で持つ形に変える。保存済みの値の読み替えが要る。
- Scene Context パネルを撤去すると、保存済みのレイアウトから、そのパネルが消える。プリセット 5 つ、ショートカット、ヘルプ、試験に及ぶ。
- 関連する過去シーンの検索の起動条件を、パネルが前面であること、から、「文脈」が見えていること、へ写す。
- Work Layer を実データにつなぐとき、件数の数え方と、場面へ飛ぶ入口を、統合ペインと共通にする。
